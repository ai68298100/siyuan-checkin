# 迁入源扩展评估（T-1367，2026-09-21）

> 目标：在 Loop（T-1218 已交付）与 Obsidian Habit Tracker 21（H21 导入，已交付）之外，评估主流习惯应用公开导出格式的迁入路径。
> 边界：只读取**官方公开导出格式**；不逆向私有格式、不使用未公开 API（全版本「明确不做」延续）。
> 调研方式：官方帮助文档/更新日志 + 社区佐证（见文末来源）；未获取真实导出样本的字段一律标注「待样本核对」，不臆造。

## 结论

| 候选 | 官方导出 | 结论 | 依据 |
| --- | --- | --- | --- |
| **Habitify** | CSV 日志导出（29.0 起，Settings → Import/Export）+ 全量备份 .sqlite | **做（P1）**：CSV 逐日志行可映射到事件模型；CSV 为官方公开通道 | 官方帮助中心与 29.0 更新日志确认导出存在；精确表头待真实样本核对 |
| **Streaks (iOS)** | CSV 导出/导入（逐完成行：任务名 + 完成时间戳，近版已含本地时间列） | **做（P2）**：官方导入器存在（Loop→Streaks 转换脚本佐证格式形态），逐完成行可直接映射 | App Store 更新日志 + 社区转换脚本；精确表头待样本核对 |
| **TickTick** | 官方 CSV 备份**不含习惯打卡数据**（仅任务） | **不做**：补齐习惯数据只能走未公开 API/网页抓取，违反「不逆向」边界 | 官方备份说明 + 多方数据可携性调研佐证 |

## 映射可行性（两候选共用口径）

- **行语义**：两者均为「一次完成一行」（习惯名 + 时间戳 ± 数值），直接映射为 `CheckinEvent`：
  - `localDate` ← 时间戳取本地日期（Streaks 已有本地时间列；Habitify 需核对时区口径，UTC 样本按宿主时区折算并在导入摘要中声明）；
  - binary 类习惯 → `value: 1`；带数值/时长的完成行 → 对应 count/duration/quantity，量纲（分钟 vs 小时）以习惯名旁的元信息推断，不可判定时按原值导入并标注 `note`；
  - `source: "import"`、`externalRef` 使用新登记前缀 `habitify:<exportHash>:<rowIdentity>` / `streaks:<exportHash>:<rowIdentity>`（幂等可重放，沿用 Loop 迁入模式，T-1218 先例）。
- **不可恢复项（导入摘要必须明说）**：
  1. **排期不可恢复**——导出只有完成历史，无频率规则；导入后项目按「历史完成重建」+ 默认 daily 排期生成，由用户在编辑器确认实际频率（或改弹性配额）；
  2. 跳过语义两平台均无对应概念，不留存；
  3. 负向习惯（at-most）在导出中与普通完成无差别，按普通完成导入，方向由用户导入后调整。
- **安全性**：导入前自动恢复点（沿用 T-1218 恢复点先行）；文件大小上限与行数上限（对齐备份导入的 512 KiB/结构化上限纪律，CSV 放宽至 5 MB + 5 万行，超出拒绝）；非法行计入降级说明，不静默丢弃。

## 工作量与验收口径（每源一批次）

1. 解析器（表头探测 + 容错）+ 映射器（含降级说明）+ `source`/`externalRef` 前缀登记（`docs/identity-and-merge.md` 与契约清单同步）；
2. 导入摘要（成功/降级/跳过行数）+ 恢复点先行；
3. 门禁：解析器运行时测试（真实样本表头夹具）+ `tests/export-identity-docs` 式文档交叉核对；
4. 预估各 1 个批次（3~5 任务）。
