# 小驴打卡 UI 重构大项目

当前界面已经具备清晰的信息结构，但整体仍偏向“简单卡片堆叠”，在桌面端缺少层次、质感和重点引导，在窄窗口和移动端又容易出现内容拥挤、操作密度不均和入口分散。UI 重构作为独立大项目推进，覆盖今日、历史、总结、复盘、日期事项、设置、新建和弹窗/页签/侧栏全部表面。

## 设计目标

- 现代、舒适、有质感，同时保留打卡场景需要的清晰和快速反馈。
- 用层级、留白、色彩和动效建立重点，不依赖大面积空白制造“极简感”。
- 桌面端支持宽屏信息编排，窄窗口保持内容可读和操作可达。
- 手机端优先触控、滚动和安全区域，避免把桌面布局简单压缩。
- 侧栏、弹窗、页签共享数据语义和组件语言，入口不同但行为一致。
- 没有 AI、网络或外部插件时，核心界面仍完整可用。

## 视觉系统

- 建立颜色角色：背景、表面、浮层、边框、主色、成功、提醒、危险、禁用。
- 建立字号、字重、行高和数字显示规范，标题、统计数字和辅助信息分层。
- 建立 4/8/12/16/24/32 的间距尺度，减少各页面自行设定间距。
- 统一圆角、阴影、描边和焦点环，区分卡片、浮层、输入控件和强调区域。
- 支持思源主题变量，避免固定白色背景和固定文字颜色。
- 增加低动效和高对比度兼容规则。

## 页面重构范围

### 今日页

- 重新设计顶部日期、完成进度和主要操作区。
- 将重要打卡、普通打卡、日期事项和已完成项目形成明确层级。
- 卡片根据内容类型呈现不同的信息密度，避免所有项目使用同一种卡片。
- 宽屏采用自适应多列，窄屏回落单列并保证名称、进度和操作完整。
- 最近记录使用紧凑时间线或横向摘要，不占据主要内容高度。

### 历史页

- 缩小日历占用高度，增加每日完成/记录摘要。
- 日期选择、筛选、记录列表和操作形成连续流程。
- 备注、复盘、撤销等动作使用统一的行内操作和反馈。
- 宽屏使用日历加详情双栏，窄屏使用上下分层。

### 总结与复盘

- 总结页从简单数字列表升级为仪表盘：概览、趋势、分组、异常和行动建议。
- 复盘页突出单个项目的连续记录、目标达成、波动和历史事件。
- 图表拥有空状态、加载状态、无数据说明和可读标签。
- AI 建议作为辅助层，不影响本地统计和复盘流程。

### 日期事项

- 表单采用分组步骤和即时反馈，减少大块空白。
- 生日、纪念日、缴费事项使用不同视觉标识。
- 列表展示下次提醒、提醒提前量、完成状态和重复规则。
- 添加、编辑、删除、完成和延期都提供明确反馈。

### 新建与设置

- 模板选择、名称、图标、类型、目标、频率、分组和重要性分成清晰区块。
- 高级字段默认折叠，常用选项优先展示。
- 预览卡片实时反映最终的今日页效果。
- 设置页按数据、显示、快捷入口、AI 和生态分类。

## 响应式策略

- 以组件容器宽度而不是屏幕宽度作为主要断点依据。
- 侧栏默认保证图标、名称和主要操作可读；极窄状态只隐藏次要信息。
- 弹窗支持紧凑、标准和全屏三种密度。
- 页签允许宽屏双栏，移动端切换为单栏和底部操作。
- 所有按钮至少满足触控尺寸，输入控件在键盘弹出时保持可见。

## 实施顺序

1. 建立视觉 token、层级、间距、控件和状态规范。
2. 重构今日页和通用打卡卡片。
3. 重构历史页、总结页和复盘页。
4. 重构日期事项、新建和设置页面。
5. 统一侧栏、弹窗、页签和移动端容器行为。
6. 补齐动效、可访问性、主题适配和性能优化。
7. 统一截图/浏览器验证清单，最后再进行真实环境验收。

## 验收原则

- 每个阶段至少有生产代码、结构测试和构建验证。
- 真实思源桌面端与移动端截图属于最终验收证据，不能由结构测试替代。
- UI 重构期间优先保护数据读写、打卡记录、日期事项和历史操作，不改变核心数据语义。
- 如果出现主流程回归，暂停视觉扩展，先修复并补回归测试。
