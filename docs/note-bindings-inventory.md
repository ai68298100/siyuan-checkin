# 笔记联动绑定盘点（T-1470 · R-A18+，2026-09-26）

本文回答三个问题：插件有哪些笔记联动绑定、各自读写什么、失效时表现如何。同时记录跨插件绑定 UX 调研的可吸收项与本次落地（「笔记联动总览」面板）。权威行为口径以代码与 DECISIONS 为准，本文是索引与说明。

## 一、绑定清单（7 处）

| # | 联动功能 | 目标类型 | 存储位置 | 方向 | 生效条件 | 设置入口 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 日记报告（周期报告写入） | 文档 | view-preferences `diaryReport.docId` | 写（Markdown 报告追加） | enabled + 合法 docId | 设置 → 外部联动 → 日记 |
| 2 | 摘要驻留（每日单行汇总） | 文档 | view-preferences `summaryResident.docId` | 写（单行 + 标记幂等） | enabled + 合法 docId | 设置 → 外部联动 → 摘要 |
| 3 | 健康收件箱（快捷指令中转） | 文档 | view-preferences `healthInbox.docId` | 读（`health:指标:日期 数值` 行） | enabled + 合法 docId | 设置 → 外部联动 → 健康 |
| 4 | 问卷日记写入目标（T-1465） | 文档或笔记本 | journal.json `integration`（mode/notebookId/docId） | 写（问卷条目，标记幂等） | 项目绑定问卷模板 | 设置 → 外部联动 → 问卷日记；弹窗内可改 |
| 5 | 叶归 LifeLog 来源 | 笔记本 | view-preferences `yeguifIntegration.notebookId` | 读（当日行首时间 Marker 段落） | enabled + itemId + notebookId | 设置 → 外部联动 → 叶归 |
| 6 | 笔记锚点回写（按项目） | 块（文档 ID 亦可） | store 项目 `noteAnchor.blockId`（+appendNotes） | 写（块属性状态 + 可选备注追加） | 项目配置锚点（opt-in） | 项目编辑器 → 笔记锚点 |
| 7 | 微信读书目标项目（按项目） | 无文档目标 | store/preferences 项目绑定 | 无文档读写（仅数据映射） | 项目 + Key | 设置 → 外部联动 → 微信读书 |

另有两类「新建文档」流：日记报告目标的新建日记文档（笔记本下拉+标题）、问卷日记的当日日记缺失时自动补建（createDocWithMd 同路径幂等）。

## 二、失效模式与现有防护

| 失效场景 | 表现 | 现有防护 |
| --- | --- | --- |
| 目标文档/块被删除 | 写入失败（锚点通道有界重试 → 挂起/审计）；轮询读取静默跳过 | 锚点挂起告警（T-1233）；诊断审计留痕 |
| 目标文档被移动/改名 | 文档 ID 不变 → ID 型绑定（1/2/3/6）不受影响；问卷日记 daily 模式经 sprig+hpath 定位受影响 | T-1470 补：custom-dailynote 属性兜底定位 |
| 同日重复写入 | — | 标记/锚点幂等（摘要驻留、问卷日记） |
| 多窗口同时写 | 合并层按身份收敛 | store 事件身份 + 审计 |
| 绑定填错 ID | 保存时块 ID 校验拒绝 | validateAnchorBlockId / 启用门槛 |

| Notion relation/linked view | 关系枢纽一屏总览 | 本次总览面板的信息架构参照 |

## 四、「笔记联动总览」面板（本次交付）

- 位置：设置 → 外部联动 → 笔记联动总览（置顶）。
- 每行：功能名 / 目标类型与 ID / 启用状态 / 健康状态（未检测·正常·目标丢失）/ 操作（打开、去配置）。
- 「检测全部联动」：文档与块目标一次 SQL IN 批量校验，笔记本目标经 lsNotebooks 成员校验；健康状态为会话内结果（不持久化），可重复点击刷新。
- 「打开」：块 ID 先解析所属文档根 ID 再 openTab；「去配置」：滚动定位并展开对应的源设置面板与输入框。
- 数据归集与归并为纯函数（features/note-bindings.ts，零依赖无时钟），宿主只做 IO。
