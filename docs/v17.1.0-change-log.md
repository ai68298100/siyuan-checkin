# 17.1.0 变更记录

17.1.0 是宿主契合度版本：对照思源 master（v3.8.4）源码与官方 `siyuan-testing` 测试体系，逐条核对插件的卸载收尾、跨窗口合并、智能体接入与移动端交互，修掉四类用户可见问题并补上真实例端到端验证。**存储结构不变（仍为 v3），可直接升级，无需迁移。**

## 卸载收尾与拆除预算（D-220/T-1242）

- 新增 `src/teardown.ts`：`createTeardownDeadline` / `waitWithinDeadline`（区分 `done`/`failed`/`timeout`）/ `createTeardownWriteGate`。
- 思源把同一插件实例的 `onload`、`onLayoutReady`、`onDataChanged`、`onunload`、`uninstall` 放进同一份 5 秒拆除预算，超时强制销毁，且不代插件清理 `setInterval`/`setTimeout`/`window` 监听。`onunload` 因此改为自带 3.6 秒排空 + 900 毫秒补写的有界收尾。
- 拆除期写门禁：队列内的变更照常读盘合并，但跳过各自的整文件写入，收尾一次性落主存储（单次 `persist` 是「读备份-写备份-写主档-回读校验」四次 IO）。补写不生成快照历史，锁被其它窗口占用时以 `navigator.locks` 的 `ifAvailable` 降级，不再无限排队。
- 专注计时：秒级心跳与 6 秒庆祝延时纳入卸载回收；卸载时若专注进行中，先按正常路径入账已投入的分钟数再关闭操作入口，避免整段专注丢失。
- 排不进去时用 `msg.teardownTruncated` 明确提示，不再静默截断。

## 跨窗口合并写放大（D-221/T-1246）

- `persistSuggestionWorkflow` 增加与已落盘文本的等值判断，基线在 `onLayoutReady` 与 `onDataChanged` 两条读取路径建立（非字符串存储清空基线，保证真正需要写时仍会写）。
- 审计写入改为 `scheduleAuditPersist()` 的 1.5 秒合并窗口，并在 `onunload` 收尾落盘；锚点旁路的三处失败诊断同样合并。
- 实测：双窗口场景下接收方的辅助存储写入由 2 次降为 0 次（主存储本就不回写，合并语义正确）。

## 智能体接入状态自证（D-223/T-1253）

- 设置页原本用一个布尔值显示「未检测到可用的思源智能体入口」，而注册调用被放在存储读取成功的分支里——数据读取失败会被伪装成「宿主不支持」。
- 改为四态状态机（`pending`/`registered`/`unsupported`/`failed`），回收宿主返回的能力 id 并在设置页显示「已注册 N 项能力」与核对位置；注册移出 try/catch 无条件执行（读能力自带「数据尚未准备好」返回，写能力由 `canRecord()` 守卫）。
- 真实宿主核对：`addAgentCapability` 自思源 3.8.0 起提供，注册后能力登记在插件实例的 `agentCapabilities`，id 形如 `plugin/frontend/siyuan-checkin/<能力名>`，默认策略允许，可在 设置 - 人工智能 - 能力 中逐个拒绝。

## 移动端回顾页（D-224/T-1254）

- 工具栏四个控件（复制报告 / 导出报告 / 报告设置 / 更多）顶部对齐：`.lc-checkin__text-button` 的全局 `margin-top:15px` 在工具条按钮与菜单项内归零；工具组去掉独立胶囊（边框、底色、内边距）消除双层容器撑高；`summary` 与按钮统一为方角无边框透明底；移动端 `justify-content` 由 `space-between` 改 `flex-start`，消除「更多」被推到最右的空洞。
- 下拉被裁剪修复：移动端 `.lc-checkin__header-actions` 的 `overflow:hidden` 改 `visible`（横向滚动由范围页签自己的 `overflow-x:auto` 承担）；`.lc-checkin__editor-header` 由 `position:static` 改 `relative; z-index:8`（此前 sticky 时代的 `z-index:4` 因 static 失效，头部失去层叠上下文，菜单被统计卡片压住）。「报告设置」「更多」「自定义范围」三处浮层恢复完整可见。

## 原生容器导出通道（D-224/T-1255）

- 修复「手机端点导出报告导致思源重启」：原先 7 处导出全部使用 `URL.createObjectURL(blob)` + `<a download>`，而思源 Android/iOS/鸿蒙客户端的 WebView 没有下载处理，blob 导航会打到宿主自身。
- 新增 `src/download.ts` 的 `saveGeneratedFile`：检测到容器原生保存桥时，先用 `/api/file/putFile` 写入工作区 `assets/`，再把绝对 URL 交给宿主 `saveExportFile`；宿主按前端能力拒绝（`status:"error"`）时退回容器桥，成功时不重复触发；原生路径任何分支都不再产生 `blob:` 导航，失败只报错。桌面与普通浏览器保持原行为。
- 行为变化：手机端导出会在工作区 `assets/` 留下文件（与思源自身导出一致），README 与 `docs/export-formats.md` 已说明。
- Loop 双文件导出改为顺序保存，避免两个系统保存面板互相吞掉。

## 兼容性与文档
