# 微信读书接入指南（T-1402，official-pull 渠道）

小驴打卡可以通过**微信读书官方 Agent API**自动记录三类打卡事实。本文说明申请、设置与口径；全部数据经官方通道获取，无 Cookie、无逆向、无私有存储读取。

## 一、能力总览

| 链路 | 语义 | 写入口径 |
| --- | --- | --- |
| 阅读时长 | 当日阅读分钟达阈值 → 该日记 1 次打卡 | `weread:<项目>:<日期>`，每日一次 |
| 完读事件 | 书架每读完一本（progress=100）→ 记 1 次打卡 | `weread:<项目>:finish:<书ID>:<日期>`，每本书一次 |
| 笔记计数 | 前一日新增划线+想法/点评条数 → 数值打卡 | `weread:<项目>:notes:<日期>`，每日一条 |

三条链路相互独立，绑定项目可以不同；不绑定的链路不启用。

## 二、准备：申请 API Key

1. 打开 `weread.qq.com/r/weread-skills`，按官方指引登录并生成 API Key（`wrk-` 前缀）；
2. Key 与你的微信读书账号绑定，**只保存在小驴打卡的本地偏好中**——不进入导出文件、不写入思源文档、不出现在日志与通知里（设置页只显示「已保存」状态，不回显 Key 本体）；
3. 建议**定期轮换 Key**；在设置页保存新 Key 后旧 Key 立即失效。

## 三、设置步骤

1. 打开 小驴打卡 → 设置 → 外部来源 → **微信读书集成**；
2. **目标项目**：选择一个单位为「分钟」的项目（时长链路的写入目标）；
3. **完读书目项目**（可选）：选择一个勾选型项目（读完一本书记一次）；
4. **划线计数项目**（可选）：选择一个数值型项目，单位设为「条」（每日新增笔记数）；
5. **API Key**：粘贴 `wrk-` 开头的 Key（已保存后再打开此行显示占位符，不会回显旧 Key）；
6. **每日达标阈值**：当日阅读达到该分钟数才记时长打卡（默认 30，1~1440）；
7. 打开顶部开关 → 点 **「立即拉取」** 验证。状态行会显示结果：
   - 成功：`上次拉取：N 天记录，新写入 M 条`；
   - 失败：`上次拉取失败：<原因>`（含 errcode 或 HTTP 状态码，照原样反馈给插件作者即可定位）。

设置完成后插件每 **30 分钟**自动拉取一次，断网/失败静默跳过，不影响本地使用。

## 四、口径说明（宁少记不多记）

- **时长**：取官方「本月按日分桶」明细，单位秒向下取整为分钟；单日超过 24 小时的桶视为异常丢弃；只有当月数据，更早历史不回补。
- **完读**：以官方 `progress=100` 且带读完时间为准（1~99% 都算「在读」）；有声书专辑的「完结」是系列状态、不是个人读完，不计；每本书只记一次，删除打卡记录后也**不会**重写（可撤销）。
- **笔记计数**：只结算**昨天**这个完整日（今天划的线次日才入账，避免把进行中的计数写死）；划线与想法/点评合并计数，书签不含（官方接口本就过滤）。
- **与思阅的分工（载体归属）**：微信读书的时长只写入你在本面板绑定的项目；思源内文档的阅读时长走思阅联动。绑定不同项目即天然不重复记账。

## 五、隐私与边界

- 插件只**读**微信读书的统计与书目元数据，不写任何内容回微信读书；
- 书名只进入完读事件的本地备注（导出前会按敏感字段机制向你披露），外部身份只含匿名 bookId；
- 出站请求经思源内核公开转发接口 `POST /api/network/forwardProxy` 发往官方域名 `i.weread.qq.com`，无其他外联；
- 全程零遥测；关闭开关即停止采集，已落盘事件与幂等身份全部保留（重开不重复记账）。

## 六、常见问题

| 现象 | 说明 |
| --- | --- |
| 拉取成功但 0 条 | 当日分钟未达阈值 / 没有新完读书 / 昨日无新增笔记（笔记计数只结算昨日） |
| `errcode -2010/-2012` | Key 无效或过期——重新生成并保存 |
| 回包带升级提示 | 官方 skill 版本升级，状态行/消息会原样转达；等待插件更新版本常量即可 |
| 长期未打开思源 | 时长只覆盖当前月；完读与笔记计数按书架/笔记现状补记，上限每轮 10 本 |
