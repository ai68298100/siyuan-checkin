# 健康数据收件箱——iOS 快捷指令官方配方（T-1501 / T-1403）

> 状态：**插件侧可用；iOS 快捷指令需在目标设备实测（host-pending）**。
> 本文把「健康样本 → 思源收件箱文档 → 小驴打卡」整理成可照着搭建的官方配方。插件不新增公开 API，也不会直接访问手机健康数据。

## 先看结论

- 当前收件箱解析器只接受两种指标：`steps`（步数）和 `weight`（体重）。
- 每条数据必须是一行严格文本：`health:<指标>:<YYYY-MM-DD> <非负数值>`。
- 快捷指令只负责调用思源内核公开的 `appendBlock`；小驴打卡每 5 分钟轮询一次，保存设置后会立即补拉。
- 同一项目、指标和日期只记一次；重复运行快捷指令不会重复累计，删除后的外部身份也不会被重放复活。
- 「自定义自动化场景」可以复用下面的步数/体重配方（例如到家、睡前或手动补录触发）；任意新的健康指标名称目前不会被插件接受，不能把 `health:睡眠`、`health:心率` 等行当成已支持能力。

## 一、准备工作

1. 手机与运行思源内核的电脑处在同一局域网，或已配置可访问的内网穿透。
2. 准备内核地址，例如 `http://192.168.1.10:6806`，以及思源「设置 → 关于」里的 API token。
3. 在思源中新建一个普通文档作为收件箱（建议放到独立笔记本，命名如「健康收件箱」），复制文档 ID（块 ID，形如 `20260101120000-xxxxxxxx`）。
4. 打开小驴打卡「设置 → 外部联动 → 健康数据收件箱」：
   - 填写收件箱文档 ID并保存；
   - 将「步数」绑定到单位为「步」或「步数」的项目；
   - 将「体重」绑定到单位为「公斤」「千克」或 `kg` 的项目；
   - 确认目标和映射无误后再打开启用开关。
5. token 只放在自己设备的快捷指令中，不要把含 token 的快捷指令或截图发给别人。

## 二、通用的「写入收件箱」动作

步数和体重配方最后都使用同一组网络动作。先把这组动作搭好，再替换前面的取数动作：

1. 添加「文本」动作，内容为一行变量，例如：

   ```text
   health:steps:<格式化日期> <统计结果>
   ```

   体重配方把 `steps` 换成 `weight`，把数值变量换成公斤数。
2. 添加「获取 URL 内容」动作：
   - URL：`<内核地址>/api/block/appendBlock`
   - 方法：`POST`
   - Headers：
     - `Authorization`：`Token <你的 API token>`
     - `Content-Type`：`application/json`
   - 请求体类型选择 JSON，字段为：

     ```json
     {
       "dataType": "markdown",
       "data": "<上一步的文本>",
       "parentID": "<收件箱文档 ID>"
     }
     ```

3. 第一次搭建时先手动运行一次，确认收件箱文档出现完整的一行，再到小驴打卡设置里观察是否在本轮或 5 分钟内入账。

> 快捷指令的魔法变量可能显示为彩色胶囊，不要把尖括号原文连同尖括号发送出去。请求体中的 `data` 必须是单行文本；不要额外加 Markdown 列表符、引号或单位。

## 三、官方配方 A：每日步数

适合「每天固定时间自动同步」或「到家后自动同步」两种触发方式。

### 取数动作

1. 新建个人自动化，触发器选择「特定时间」（例如每天 21:00），关闭「运行前询问」。也可以改用「到家」等系统触发器，后面的动作不变。
2. 添加「查找健康样本」（Find Health Samples）：
   - 类型：步数；
   - 时间范围：今天；
   - 如界面提供来源筛选，可保留系统默认来源。
3. 添加「计算统计数据」（Calculate Statistics），对上一步结果选择「求和」。
4. 添加「当前日期」并用「格式化日期」转为 `yyyy-MM-dd`。不要使用 `yyyyMMdd` 或本地化日期文本。
5. 用「文本」动作拼成：

   ```text
   health:steps:<yyyy-MM-dd> <步数求和>
   ```

6. 接上「通用的写入收件箱动作」。

### 验收

- 收件箱中能看到例如 `health:steps:2026-09-27 8432`；
- 绑定了步数项目后，今日或历史日志出现一条「接口写入」记录；
- 同一快捷指令当天再次运行，事件数不增加；
- 项目单位不符合步数校验时，插件保持不入账并在设置页提示单位不匹配。

## 四、官方配方 B：每日体重

体重可做成早晨自动化，也可以保留为手动快捷指令。

1. 新建自动化，触发器选择「特定时间」（例如每天 07:30），或直接创建普通快捷指令供手动运行。
2. 添加「查找健康样本」（Find Health Samples）：类型选择体重，时间范围选择今天。
3. 添加「获取列表中的项目」（或等效的「获取最新项目」）并取最新一条样本；不要把一天内多次称重求和。
4. 添加「当前日期」→「格式化日期」，格式固定为 `yyyy-MM-dd`。
5. 用「文本」动作拼成：

   ```text
   health:weight:<yyyy-MM-dd> <最新公斤数>
   ```

6. 接上「通用的写入收件箱动作」，请求体和步数配方完全相同。

### 验收

- 收件箱中能看到例如 `health:weight:2026-09-27 72.5`；
- 绑定了体重项目后，日志出现一条对应日期的「接口写入」记录；
- 同日重复运行不会覆盖首条外部事件；如需修正，先按历史记录的撤销规则处理，再保留收件箱原文作为审计依据。

## 五、自定义自动化场景（复用配方，不伪造新指标）

下面场景只改变「什么时候运行」或「数值从哪里来」，仍然写 `steps` / `weight` 两种受支持的行：

| 场景 | 触发器 | 取数/输入 | 适用指标 |
| --- | --- | --- | --- |
| 睡前汇总 | 特定时间 | 当天步数求和 | `steps` |
| 到家同步 | 到家 | 当天步数求和 | `steps` |
| 运动后手动补录 | 快捷指令手动运行 | 「询问输入」填写当天步数 | `steps` |
| 早晨称重 | 特定时间 | 最新体重样本 | `weight` |
| 出差补录 | 快捷指令手动运行 | 选择日期 + 输入公斤数 | `weight` |
| 一个快捷指令分支 | 从菜单中选择步数/体重 | 两个分支分别生成严格行 | `steps` / `weight` |

当前不能用任意名称扩展指标。比如 `health:sleep:2026-09-27 420` 会被严格解析器忽略；这不是一个可用的自定义指标配方，也不会创建隐藏事件。若要记录睡眠、心率或活动分钟，请使用插件现有的手动/精确记录路径，或另立支持该指标的任务后再更新本文。

## 六、摄取、幂等与修改规则

- 插件每 5 分钟轮询一次绑定文档；文档不可见时跳过本轮，回到前台后再补拉。
- 单轮 SQL 按块 ID 升序最多读取 500 行，窗口外的旧行应定期归档或裁剪。
- 未来日期不会写入；非法日期、负数、空数值和多余文本会被忽略。
- 同一「项目 + 指标 + 日期」只入账一次；同日重复 push、多窗口轮询都会收敛。
- 记录删除会留下外部身份墓碑；相同外部身份之后再次 push 不会复活已删除记录。
- 收件箱文档由用户管理，插件只读不改写原行；原文可以作为外部自动化的审计依据。
- 同一指标可以显式挂载多个项目，每个项目各自拥有独立的 `externalRef`：
  `health:<项目 ID>:<指标>:<日期>`。

## 七、失败排查

### 收件箱没有新行

先单独运行「获取 URL 内容」，检查 URL、端口、手机与电脑网络，以及 `Authorization` 是否写成 `Token ` 加一个空格再接 token。思源内核未启动、局域网权限未授权或 token 过期都会让快捷指令失败。

### 收件箱有行，但插件没有入账

逐项检查：文档 ID 是否保存且仍存在、健康收件箱是否已启用、对应指标是否至少挂载一个项目、项目是否归档、单位是否满足步数/体重校验。保存设置后会立即尝试一次，也可以回到插件前台等待下一个 5 分钟轮询周期。

### 文本看起来正确但仍被忽略

只接受以下形式（日期必须是真实日历日）：

```text
health:steps:2026-09-27 8432
health:weight:2026-09-27 72.5
```

常见错误包括使用斜杠日期、把单位写进数值、在行首添加 `- `、使用本地化日期、写负数，或把自定义指标名放进 `health:<指标>`。

### 同日修改数值没有覆盖旧记录

这是预期的不可变事件语义：同一外部身份不会覆盖首条记录。请按插件历史记录处理撤销/更正，并保留收件箱原行，不要靠重复 push 试图覆盖。

### 文档越来越长或旧数据重复进入窗口

单轮最多读取 500 行。定期把已摄取行归档到其他文档；换绑项目之前先停用并整理窗口内旧行，避免旧行以新项目身份重新入账。

## 八、真机验收清单（host-pending）

- [ ] iPhone 与思源内核同网，步数配方自动运行成功；
- [ ] 体重配方写入小数并成功入账；
- [ ] 同日重复运行只生成一条事件；
- [ ] 断网、内核关闭、token 错误时能按本文排查并恢复；
- [ ] 收件箱文档保留原始行，插件不改写用户内容；
- [ ] 换绑多个项目后，各项目身份和撤销行为符合预期。

## 九、数据边界

- 收件箱是用户工作区内的普通思源文档，内容由用户和快捷指令写入。
- 插件只读取绑定文档中严格匹配的行，不读取其他健康数据，不联网访问第三方健康服务。
- 解析后的事件走既有 `recordExternalEvent` 通道，来源为 `api`，受统一的幂等、撤销、墓碑和审计规则管理。
- token 只存在于本地快捷指令和本地设置流程中；不要把 token 写进收件箱行、备注、导出文件或公开截图。
