# 笔记推导打卡接入指南（T-1500）

笔记推导是一个可选的本地自动化来源：用户明确绑定一个思源文档或笔记本、一个打卡项目和一个固定标记模板后，插件定期读取命中的笔记块并生成完成事件。它只读笔记，不改写笔记内容，也不接受任意 SQL。

当前实现把事件写入既有 `source: "api"` 通道，用 `notequery:<itemId>:<blockId>:<localDate>` 作为稳定的 `externalRef` 身份。`notequery` 是身份前缀，不是新增的公共 `CheckinEvent.source` 枚举。

## 1. 开启前提

设置保存时必须同时满足以下条件，缺一项就保持关闭：

| 条件 | 说明 |
| --- | --- |
| 显式开启 | `enabled: true`；默认关闭，安装或升级不会自动启用 |
| 目标 | 绑定一个文档块 ID；`document` 查询使用该文档，`notebook` 查询使用该文档所在笔记本 |
| 项目 | 绑定一个现有、未归档的打卡项目 ID |
| 模板 | 选择 `frontmatter` 或 `tag`；字段、值和标签只接受受限 token |

目标文档和项目在保存时由宿主核验。目标被删除、项目不存在或配置无法归一化时，下一轮查询直接降级为空结果并保留原配置，等待用户重新选择；不会猜测相邻文档或项目。

## 2. 两个固定模板

### A. 日记字段（frontmatter）

在日记正文中写入一行完整字段，例如：

```text
checkin: done
```

配置默认是 `field: "checkin"`、`value: "done"`。字段和值可以改成短 token，例如 `habit: yes`，但不能包含 SQL 标点、换行或超过 40 个字符。匹配要求字段和值位于行首、行尾或分隔符之间；`checkin: todo`、`mycheckin: done` 和自然语言中间出现的相似片段不会命中。

### B. 标签（tag）

在笔记正文中写入完整标签，例如：

```text
今天完成 #checkin
```

配置默认是 `tag: "checkin"`。标签按完整 token 匹配，`#checking`、`#checkin-more` 和普通文本中的相似片段不会命中。标签不负责解析数值，命中即产生值为 `1` 的二值完成事件。

## 3. 固定只读 SQL

插件只从下面这一类查询生成 SQL。用户配置只会进入已校验的目标 ID、字段 token、值 token 或标签 token，并在拼接前转义单引号；用户不能输入 `SELECT`、表名、排序、连接条件或额外语句。

```sql
SELECT child.id, child.root_id, child.content,
       root.ial AS root_ial, root.hpath AS root_hpath
FROM blocks AS child
JOIN blocks AS root ON root.id = child.root_id
WHERE child.type IN ('p', 'h', 'l')
  AND root.type = 'd'
  AND <document: root.id = boundTargetId | notebook: root.box = boundTargetId>
  AND child.content LIKE '%<field: field: | tag: #tag>%'
ORDER BY child.id ASC
LIMIT 200;
```

查询只取正文、标题和列表块，按块 ID 稳定排序，单轮最多读取 200 行。它不会查询全库，不会读取附件内容，不会写回 `blocks`，也不会创建日记文档。

日期只从根文档的 `custom-dailynote-YYYYMMDD` 属性或路径中的真实 `YYYY-MM-DD` 日期投影。缺少日期、日期不合法或无法定位根文档时，该行被丢弃；不会用当前时间补日期。

## 4. 身份、幂等与手动互斥

每个合法命中按以下规则生成身份：

```text
notequery:<itemId>:<blockId>:<localDate>
```

其中 `itemId` 来自显式绑定，`blockId` 来自 SQL 行，`localDate` 来自根日记日期。三者任一不符合安全格式时，整行跳过。相同笔记块在同一天重复轮询会得到同一个 `externalRef`，因此只会产生一条事件；已撤销事件的墓碑也会阻止其复活。

手动事实优先：同一项目同一 `localDate` 已存在任意 `source: "manual"` 事件时，本轮笔记命中会跳过，并在来源状态中提示手动记录覆盖推导结果。这个判定按天和项目进行，不删除已有事件，也不回写笔记。没有手动事件时，命中既有 `source: "api"` 且 `externalRef` 相同的事件视为重复，不会双重累计。

推导事件的备注只保留模板类型和块 ID（例如 `note:frontmatter:<blockId>`），不把整段笔记正文复制到打卡事件中。撤销仍沿用既有事件撤销和墓碑通道，之后同一身份不会自动复活。

## 5. 轮询与失败降级

- 默认轮询间隔为 5 分钟；一次只处理最多 200 行，超出部分留待下一轮，不扩大单轮工作量。
- 宿主 SQL 接口缺失、超时、返回非数组或查询失败时，本轮记为不可用并保留现有事件；不会清空历史、生成随机身份或把失败当作完成。
- 配置关闭、目标失效、项目归档、模板 token 非法时，安全回落为空结果。用户修复配置并重新保存后，下一轮按原始稳定身份重试。
- 写入失败时保留 `externalRef` 供后续重试；不得为了绕过失败生成新的引用。
- 来源状态只展示可诊断的失败和重试提示，不展示原始 SQL、令牌或笔记正文。

## 6. 支持边界

以下内容当前不属于本集成的能力：

- 任意 SQL、用户自定义表连接、聚合表达式、脚本或自然语言判断；
- 没有显式绑定的全库扫描、跨笔记本推断或按标题猜测目标；
- 用 `health:` 等其他来源前缀伪装笔记事件；
- 把 `health:sleep`、`health:heart-rate` 等新指标写成已支持的健康收件箱能力；
- 把一条笔记中的数字自动解释为时长、次数或数量；当前模板只产生二值值 `1`；
- 自动创建日记、自动改写笔记、自动覆盖同日手动记录。

需要更多字段语法、数值指标或跨文档规则时，应先另立运行时任务，补齐来源身份、单位校验、迁移/撤销语义、性能上限和守门测试，再扩展模板。只修改文档不能把未实现的查询能力变成契约能力。

## 7. 验收清单

接入完成后可用下面的最小闭环验收：

1. 关闭开关保存，确认没有 SQL 请求和新事件。
2. 绑定一个日记文档和项目，写入 `checkin: done` 或 `#checkin`，等待一轮刷新。
3. 确认事件值为 `1`、来源显示为接口写入/笔记推导、`externalRef` 以 `notequery:` 开头。
4. 再次刷新，确认事件数量不增加；撤销后再次刷新，确认墓碑阻止复活。
5. 同日手动记录一次，再刷新，确认手动事实保留且笔记命中显示互斥提示。
6. 删除目标或改成非法 token，确认状态降级、历史事件保留，修复并重新保存后可按原身份恢复。

所有数据留在本机；笔记正文、目标路径和查询配置不进入公开 API 的事件备注或来源前缀登记。真实宿主 SQL 行为仍需在目标思源版本上做设备验收，自动化守门只证明固定模板和归一化边界。
