## 近期计划：v17.3.x，发布后 1～2 周

目标是把 v17.2.1 的自动化成果闭环到真实使用场景，并处理高影响的小问题，不新增大型数据模型。

### 1. 完成真实宿主验收

按 [集成冒烟清单](integration-smoke-checklist.md) 记录设备、思源版本、前端类型、窗口尺寸、截图和结果，优先关闭：

- `T-023`、`T-033`：桌面、页签、dock 和移动端残留 UI/重载问题；
- `T-129`、`T-1173`：记录、撤销、筛选、完成态切换后的焦点和滚动；
- `T-1256`：Android WebView 导出、系统保存面板、键盘和回顾浮层；
- `B-007`：Dock Tomato 双插件开始、暂停、继续、完成、放弃、重载、双窗口和移动端联调。

验收证据进入 `PROGRESS.md`；Dock Tomato 现场还必须确认没有数据损坏、重复记账或跨窗口会话误暂停。没有真实宿主证据的场景继续标记为开放，不用浏览器结果替代。

### 2. 保持兼容口径一致

`3.8.4` 继续作为完整验证下限。`TODO.md` 中仍写着旧的 `3.4.2` 的 `T-1247` 记录需要同步为已按 D-238 收口，避免误以为插件仍承诺 3.4.2。若未来要降低下限，必须先完成 3.4.2～3.8.3 的真实回归矩阵。

### 3. 做小范围可观察性和体验修补

- 设置页继续完善番茄钟、Task Horizon 和智能体的状态、错误原因、重试与恢复提示；
- 让事件来源（手动、内置专注、Dock Tomato、API、事项）在回顾和日志中更容易识别；
- 修复真实设备反馈中的布局、触控、键盘和浮层问题；
- 每次改动保持 30 项容量、双主题、无障碍、窄屏和长文本门禁。

近期版本不做云同步、社交排行榜、系统级后台通知或新的万能智能体写入口。

## 中期计划：v18.x，1～3 个月

目标是让插件成为可靠的本地数据工作台，并让至少一个真实外部消费者稳定使用公开契约。

### 1. Task Horizon 公开契约联调

完成 `T-1165`、`T-1228`～`T-1230`，只使用双方已记录的公开 API：

- 日历「打卡」图层读取有界摘要或范围事件；
- 原生任务复选框真实完成后写入 `recordEvent`；
- 使用 `taskhorizon:<blockId>:<localDate>` 幂等身份，重复回放不重复记账；
- 双方互置契约测试和刷新事件测试。

对方没有排期时，本插件继续维护契约夹具、诊断和降级路径，不把外部等待变成版本阻塞。

### 2. API v5 稳定化

把已实现的范围读取、统一项目查询、批量写入和指标门面整理为稳定文档：类型定义、最小示例、错误码、限制、兼容矩阵和契约测试包。v4 能力保持兼容，新增能力继续采用能力发现和有界输入。

### 3. 回顾与导出增强

在现有趋势、周期对比和日志基础上，完善可配置周报/月报、来源筛选、目标偏差解释和安全导出。所有指标必须能够回溯到原始事件、项目修订和统计截止时间，并覆盖空数据、小数据、大数据、跨时区和夏令时边界。

### 4. UI 进入维护阶段

重点从“增加页面”转为降低维护成本：清理重复 token 和历史样式、复用反馈/空态/错误/保存状态组件、减少布局跳动，并持续关注生产 CSS 体积。每轮仍运行完整质量链，不能以体积优化换取触控、可读性或数据流程回归。

同时明确两套版本语义：内部 `CheckinStore` 已为 v3，公开 API descriptor 的 `storeVersion: 2` 是公共契约版本。后续若调整任一数字，必须先补决策记录、迁移说明和契约测试，避免第三方误把私有存储版本当成公开 API 版本。

### 5. 恢复与并发演练

补齐真实升级/降级、损坏数据隔离、双窗口并发、断网后重试和恢复点演练，形成用户可读的诊断与恢复指南。

## 长期计划：v19.x～v20+，6～12 个月

长期方向是开放成熟能力，同时维持本地优先、可解释和可撤销的产品边界。

### 1. 开放生态

- 稳定 API v5 的类型、版本协商、错误码和弃用周期；
- 发布适配器准入清单和契约测试包，要求身份、幂等、卸载清理、权限和失败隔离全部通过；
- 至少有两个真实消费方后，再扩大新的写入能力；
- 形成可重复的预发布、回滚、资产摘要和升级/降级流程。

### 2. 笔记原生差异化

继续深化笔记锚点、日记回写和声明式渲染块：支持可配置数据集、热图/汇总表达式和日期跳转。所有回写默认关闭、用户主动开启，保留审计、失败隔离和撤销能力，插件私有存储继续作为事实来源。

### 3. 受控智能体

维持“只读 → 建议 → 用户确认执行”三层边界。执行前显示差异和影响范围，写入经过审计、冲突检查、错误码、重试和撤销；未配置模型时，手动打卡、统计、导出和恢复完整可用，不提供万能写入口。

### 4. 习惯内核二期

SKIP、强度、弹性周期、at-most 和成熟度模型已经落地，后续根据真实反馈优化周期目标、里程碑、反内疚文案和统计口径。暂不引入 RPG、社交压力或自建同步，除非用户需求和隐私模型都明确支持。

### 5. 性能与隐私

维护 10k/100k 事件、低端设备、跨窗口和多插件组合基线；评估端到端加密或外部同步时，先完成隐私、冲突、撤销和数据所有权设计，再决定是否立项。

## 版本节奏与决策门

| 阶段 | 版本节奏 | 进入条件 | 发布门槛 |
| --- | --- | --- | --- |
| 近期 | v17.3.x | 真实宿主反馈或高影响兼容问题 | 现场清单、完整质量链、升级/回滚说明 |
| 中期 | v18.x | Task Horizon 至少一个真实联调方，API v5 文档稳定 | 契约测试、性能基线、数据恢复演练 |
| 长期 | v19.x～v20+ | 至少两个真实消费方或明确的笔记生态价值 | 兼容矩阵、隐私评估、迁移/弃用周期、可撤销写入证据 |

每个版本都保留以下固定门槛：

- `pnpm run check`、`pnpm run build`、`pnpm run test:quality`、`pnpm run check:release`；
- 浅色/深色、桌面/页签/dock/移动端、30 项容量、长名称和长单位；
- 键盘焦点、ARIA、触控尺寸、软键盘、安全区和导出路径；
- 真实宿主证据与自动化证据分开记录；
- 版本、提交、构建产物和 SHA-256 保持一致。

## 当前风险

1. 真实宿主和双插件证据不足，可能遗漏 WebView、系统键盘、安全区和事件时序问题。
2. Task Horizon、Dock Tomato 等外部排期不可控，必须保持本地降级路径和独立版本节奏。
3. 提高 `minAppVersion` 会让旧思源自动禁用插件，任何下限变更都要在发布说明中明确影响。
4. 笔记回写、渲染块和智能体扩大写入面，必须坚持 opt-in、公开 API、审计、失败隔离和可撤销。
5. 旧路线文件较多，后续新任务统一登记到本文、TODO、PROGRESS、BLOCKERS、DECISIONS，避免出现多个“当前路线”。
