# 小驴打卡 UI 原型设计规范 v3

> 版本：v3 · 2026-10-07
>
> 配套原型：[checkin-ui-v3.html](./prototypes/checkin-ui-v3.html)。
>
> v3 的任务是把“低压力个人行动台”落成页面、状态、动作和视觉的共同语言。它是设计与实现验收基线，不替代生产代码中的状态契约、数据模型和宿主验证。

## 1. 设计目标

### 1.1 一屏只回答一个问题

| 页面 | 首屏问题 | 唯一主动作 |
| --- | --- | --- |
| 今天 | 我现在先做什么？ | 记录 / 开始专注 |
| 回顾 | 这段时间发生了什么？ | 查看证据 / 进入下一步 |
| 事项 | 哪个日期事项需要处理？ | 完成 / 推迟 |
| 设置 | 我要改变什么？ | 进入目标分组并保存 |
| 快速记录 | 这条事实怎么写入？ | 确认记录 |
| 编辑器 | 未来会怎样出现？ | 保存项目 |
| 洞察 | 这个项目的长期形态是什么？ | 调整规则草稿 |
| 归档 | 如何找回或清理？ | 恢复 / 查看影响 |

### 1.2 视觉层级

页面只使用四种信息层：

1. **行动层**：记录、开始、保存、完成，颜色最强，数量最少。
2. **事实层**：日期、数值、来源、写入状态，使用中性色和可读标签。
3. **解释层**：趋势、完成率、建议，必须有口径、依据和回源入口。
4. **治理层**：冲突、失败、隐私、导入、恢复，使用明确文字和恢复动作。

卡片不是装饰容器。每张卡只承载一个问题、一个数据范围和一个主要动作。

## 2. Design tokens

### 2.1 颜色语义

实现优先复用插件独立主题变量；原型提供下列参考值。任何状态都必须同时使用文字、图形/图标和位置，颜色只是第三通道。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#F7F7FC` | `#141419` | 页面背景 |
| `surface` | `#FFFFFF` | `#1D1E24` | 卡片、表单 |
| `surface-raised` | `#FFFFFF` | `#23242C` | 弹窗、抽屉、浮层 |
| `surface-muted` | `#EFF0FA` | `#26272F` | 分组、图表底板 |
| `border` | `#E4E6F4` | `#2C2D38` | 1px 半透明边界 |
| `text` | `#2A2B35` | `#EFEFF6` | 主文本 |
| `muted` | `#63657A` | `#9FA0AC` | 辅助文本 |
| `accent` | `#5B65E8` | `#8B93F8` | 当前页、主动作、焦点 |
| `success` | `#3BA55D` | `#4CBB7F` | 已保存、已完成 |
| `warning` | `#E89A2B` | `#F0B45C` | 待确认、即将到期 |
| `danger` | `#E5484D` | `#F07C7C` | 失败、删除、冲突 |
| `warm` | `#F6A94B` | `#F6B04E` | 事项和轻量庆祝 |

禁止纯黑硬阴影、纯红表示普通未完成、只用绿色表示“写入成功”、用金色表示错误。

### 2.2 字体、间距、圆角

```text
字体：Inter, PingFang SC, Microsoft YaHei, ui-sans-serif
display 28/36 720 · page 24/32 720 · section 18/26 680
body 14/22 450 · label 13/20 600 · help 12/18 450 · metric 30/36 720
间距：4 / 8 / 12 / 16 / 24 / 32px
控件：36px 默认 · 44px 触控 · 52px 主动作
圆角：8px 小控件 · 12px 行 · 16px 卡片 · 22px 弹窗
内容宽度：min(1200px, calc(100vw - 48px))；正文行长 ≤72ch
```

嵌套容器外大内小：卡片 16px、输入 10px、弹窗 22px。间距只能来自 4px 栅格，除非是宿主安全区或文字基线校正。

### 2.3 阴影与层级

```text
shadow-1：0 1px 2px rgba(55, 58, 120, .06), 0 6px 18px rgba(55, 58, 120, .05)
shadow-2：0 4px 10px rgba(55, 58, 120, .08), 0 16px 34px rgba(55, 58, 120, .08)
shadow-3：0 12px 24px rgba(25, 27, 56, .14), 0 28px 60px rgba(25, 27, 56, .12)
```

卡片使用 1px 半透明描边；只有浮层、弹窗、拖拽中的卡片使用 shadow-2/3。背景分层靠明度差，不用厚实色块。

### 2.4 动效

```text
fast 120ms · normal 180ms · page 240ms · easing cubic-bezier(.2,.8,.2,1)
```

只动 `opacity` 和小幅 `transform`。按钮按压最多下移 1px；列表切页不自动滚动；`prefers-reduced-motion` 下删除位移和连续数字动画。焦点环 2px，外间距 2px。

## 3. 信息架构与承载形态

### 3.1 一级导航

```text
今天 · 回顾 · 事项 · 设置
```

洞察、编辑、归档、专注、建议工作台、数据中心由上下文进入；桌面命令面板和移动“更多”保留深链。一级导航的变化不删除功能，只改变默认发现路径。

### 3.2 Surface matrix

| Surface | 适合做什么 | 必须保留 | 延后内容 |
| --- | --- | --- | --- |
| Tab | 完整行动、回顾、设置 | 上下文、主动作、返回栈 | 复杂诊断可进抽屉 |
| Dock | 当前项目、记录、撤销、计时 | 来源、状态、最小操作 | 图表、批量编辑 |
| Dialog/Sheet | 快速记录、命令、推迟 | 日期、项目、保存状态 | 高级规则 |
| Block | 就地查看和最小记录 | 日期、项目、事实状态、回源 | 全局设置 |
| Mobile | 单列完成核心任务 | 标题、主动作、底栏、撤销 | 侧栏、长表格、诊断 |

所有表面共享 `SurfaceContext`：`page`、`returnTo`、`itemId`、`localDate`、`range`、`source`、`query`、`filters`、`scrollAnchor`、`draftId`、`focusId`。关闭、刷新、宿主重载和系统返回优先恢复上下文。

### 3.3 原型 Surface 与生产入口的对应关系

v3 为了完整表达用户旅程，展示了几个独立的表面原型。它们不代表生产代码必须新增一级 `PageId`：

| v3 Surface | 生产承载 | 原型边界 |
| --- | --- | --- |
| Focus | Today/Review 项目行上的计时条、Focus panel 或 Dock | 结束后确认入账；不新增独立一级导航 |
| 建议工作台 | Review/Insights 的建议草稿、审计和确认抽屉 | 只能生成草稿；没有模型时手动路径完整 |
| 数据中心 | Settings → 数据与恢复详情 | 导入/导出/快照/诊断复用现有设置与审计路径 |
| Archive | 现有 Archived 页面和项目菜单 | 当前稳定能力是归档、批量恢复/删除；暂停/待删除/草稿工作台属于后续扩展概念 |

评审原型时，应检查入口可达、返回上下文和状态诚实，不把这些 Surface 误读为新增稳定功能。

## 4. 全局壳

### 桌面

左侧只放四个一级入口和一个“更多”入口；顶部显示页面名、日期/范围、来源和保存状态；右侧是搜索/命令、主题和帮助。底部操作栏只保留撤销状态和当前主动作，避免与左侧快速记录入口重复。

### 中等宽度

导航收为图标轨；文字通过悬浮说明和页面标题补足。主内容不低于 680px；证据侧栏可收起，不能把主动作挤到不可见区域。

### 移动端

顶部显示标题与日期，底部为“今天 / 回顾 / 事项 / 记录 / 更多”。“更多”打开命令 Sheet，设置和二级页面从这里进入；进入二级页后“更多”保持选中，避免用户失去位置感。记录按钮固定在拇指可达区域；弹窗变成底部 Sheet，输入法出现时操作栏跟随键盘上方。所有动作目标至少 44px。

## 5. 页面规范

### 5.1 Today：行动台

**默认布局**

1. 上下文条：日期、时区、本地保存/待同步状态。
2. 下一步卡：只出现一个建议项目，主按钮是“记录”或“开始专注”。
3. 待处理队列：名称、规则、状态、来源、行内主动作。
4. 今日摘要：只显示“待处理 N · 已记录 M”，不抢主动作；移动端排在待处理队列之后。
5. 已完成区：默认折叠，可展开时间线。
6. 证据轨：提醒、事项、未来负荷、往年同日，默认收起。

**状态矩阵**

| 状态 | 行文案 | 主动作 |
| --- | --- | --- |
| 未记录 | 今天尚未记录 · 每天 30 分钟 | 记录 |
| 已完成 | 已记录 · 30 分钟 · 手动 | 撤销 |
| 跳过 | 已跳过 · 不计入完成率 | 恢复/查看原因 |
| 部分完成 | 已记录 12/30 分钟 | 继续记录 |
| 上限破戒 | 已超过上限 · 4 次 | 查看事件 |
| 自动来源 | 已由思阅记录 · 20 分钟 | 查看来源 |
| 失败 | 事实未写入 · 输入已保留 | 重试/改为手动 |

**空态**：空库引导模板、空白项目或跳过；筛选无结果显示筛选条件和清除；无排期显示“今天没有安排”，不显示伪造的 0%。

**现有能力映射**：搜索支持项目/备注/自然语言快速解析；“更多”进入分组、排序、批量完成/跳过/归档/删除、拖动排序、失败恢复和 at-most/配额规则说明。原型只展示默认路径，生产迁移不能删掉这些二级动作。

### 5.2 Quick record：快速记录 Sheet

顶部固定项目、日期和来源。第一层动作提供“完成一次 / Add / Set / 时长 / 自定义”；备注、附件、原文锚点和来源详情全部折叠。

提交流程：按钮进入 saving → 本地已保存 → 显示事实、来源、影响和撤销。失败保留所有输入，给“重试”和“改为手动”两条路径。自然语言解析只生成草稿，解析的日期、项目、单位和数值必须逐项可编辑。

### 5.3 Review：证据工作台

页签固定为“概览 / 记录 / 分析”。

- **概览**：事实条数、项目/来源数量、完成节奏、项目证据；每个数字带范围、分母、更新时间。
- **记录**：按日期/项目/来源搜索，点击事件打开详情或回到源文档；批量补记和导出在动作菜单。
- **分析**：趋势、热力图、比较、成就和报告；建议放在事实之后，样本不足时明确提示。

所有图表支持键盘焦点、日期标题、空值说明和“查看当日事件”。热力图中“无数据、跳过、未安排、完成、破戒、冲突”使用不同图形/文字，不靠色阶单独区分。

**更多工具折叠**：每个工作区保留批量补记预览、日/周/月/年范围、来源/计量/排序筛选、热力图、项目比较、成就、提醒中心、周复盘草稿、报告/分享卡、保存视图和建议审计入口。它们是 Review 的二级工具，不与事实首屏竞争。

### 5.4 Insights：单项目洞察

从 Review 项目卡或 Today 证据进入。顶部显示项目、单位、目标、有效安排和数据范围；中部是状态日历和事实趋势；底部是原始事件。建议卡必须分为“依据”“可能解释”“可选调整”，调整进入 Editor 草稿，不直接写入规则。

### 5.5 Occasions：日期事项收件箱

列表优先，按“今天 / 即将 / 逾期 / 已完成”筛选；每行显示日期、重复、提醒、来源和动作。编辑是可关闭抽屉；移动端是全屏 Sheet。逾期不自动变成惩罚状态，动作是完成、推迟、静默或打开来源。

编辑抽屉的高级区需覆盖农历、里程碑/长周期、错过后的补标记、提醒仅一次/静默和往年同日；默认路径仍只要求名称、日期和下一步。

### 5.6 Editor：项目向导

四段流程：

1. **定义**：名称、类型、单位、目标、模板。
2. **安排**：频率、有效日期、跳过、提醒、优先级。
3. **连接**：记录来源、笔记锚点、专注工具、外部项目。
4. **确认**：未来 7 天预览、历史统计影响、绑定影响、保存/草稿状态。

高级组织字段和危险操作放在页尾。类型×排期×方向的显隐只有一个事实源；改变规则前显示“影响未来 / 历史保持”的说明。保存失败保留草稿，关闭时区分未保存、待同步和冲突。

定义步骤提供最近、推荐、场景组合包、我的模板和空白入口；图标搜索/自定义、模板应用标记、同名规则冲突和部分应用进入预览，而不是静默创建重复项目。连接步骤保留问卷、番茄、笔记锚点和外部来源的可选状态。

### 5.7 Archive：恢复中心

筛选为暂停、归档、待删除、草稿。每行显示原因、最后事实、绑定、可恢复期限和影响预览。永久删除前提供导出/备份，完成后保留短审计；批量恢复遇到规则冲突时逐项展示，不静默覆盖。

当前生产页面已实现的是归档项目、详情、批量恢复和批量删除；“暂停/待删除/草稿”作为未来恢复中心工作台概念，原型必须使用候选标签，不能当成当前稳定能力。

### 5.8 Settings：健康总览 → 目标详情

首页先显示四张只读状态卡：本地数据、提醒与专注、笔记输出、外部来源。每张卡只显示健康状态、最近结果、缺失项和“去配置”。

详情分为：

- 外观与操作；
- 今日与提醒；
- 规则与统计；
- 联动与目标；
- 数据与恢复；
- 关于与诊断。

外部来源采用“总览状态列表 → 单来源详情抽屉”；详情固定四行：产生什么、写入哪里、最近结果、下一步。失效、断开、待授权、无数据和写入失败各自有文案与恢复动作。

### 5.9 Focus：附着于项目的模式

状态为 idle、running、paused、completed、abandoned、save-failed。结束后必须确认是否把实际时长入账；锁屏、休眠、切换窗口和系统时间变化显示实际计时并可修正。Dock 只保留计时、暂停、结束和返回来源。

### 5.10 Suggestion workspace：建议草稿

流程固定为“解释 → 生成草稿 → 用户编辑 → 确认写入”。建议卡显示输入范围、来源、置信度/不确定性、预计影响、隐私范围；拒绝后不重复展示相同建议。没有模型时显示手动路径。

### 5.11 数据中心与嵌入块

导入、导出、备份、恢复、诊断和 API 状态统一在 Settings 的数据与恢复分区。批量操作先给预计数量、去重依据、部分失败行为、取消和回滚说明。

嵌入块只显示日期、项目、事实状态、最小记录按钮和来源；点击统计或日期打开带 `returnTo` 的完整页面。

## 6. 统一状态字典

```text
draft 草稿
saving 保存中
saved 本地已保存
pending-sync 待同步
confirmed 已确认
skipped 已跳过
partial 部分完成
at-most-breach 上限破戒
offline 离线
conflict 冲突
failed 失败
undone 已撤销
archived 已归档
```

“已完成”只描述项目规则，不替代“事实已写入”；“同步完成”只描述外部结果。状态必须有可读文案、图形、位置和可选详情。

## 7. 组件契约

| 组件 | 必须显示 | 必须支持 |
| --- | --- | --- |
| PageShell | 标题、目标说明、上下文、状态槽 | 返回保留筛选/滚动/焦点 |
| PrimaryAction | 动词 + 对象 | saving 禁重入、成功可撤销 |
| TaskRow | 名称、规则、事实状态、来源 | 整行可聚焦，主动作位置稳定 |
| ContextBar | 日期/范围、项目、来源、保存状态 | 展开详情、复制上下文 |
| MetricCard | 数值、单位、分母、范围、来源 | 点击回源，空值不伪造 0 |
| StatusChip | 文案 + 图形 | 键盘可读，颜色非唯一编码 |
| EmptyState | 原因、下一步、可跳过 | 空库/筛选/未配置/离线分型 |
| ErrorState | 发生了什么、保护了什么、现在做什么 | 保留输入，重试幂等 |
| UndoBar | 影响对象、期限、结果 | 撤销后显示前后差异 |
| Drawer/Sheet | 标题、关闭、上下文、保存态 | Esc/系统返回/点击外部语义一致 |
| SuggestionCard | 依据、影响、不确定性、隐私 | 编辑、拒绝、确认、撤销 |

## 8. 可访问性与响应式

- 文字与背景至少 4.5:1；大字和非正文至少 3:1；焦点环与邻近背景至少 3:1。
- 触控目标 ≥44px；鼠标密集 Dock 可保留 32px，但不能复用到移动端。
- 320、360、390、600、760、1024、1280、2000px 均保持单一滚动容器，主动作不被底栏/输入法遮挡。
- 200% 字体和中文长名称不能依靠省略号传达事实；可隐藏的是辅助说明，不是项目名、数值、状态和主动作。
- 图表提供表格/列表等价文本；热力图日期格使用原生 button、`aria-current="date"` 和明确状态。
- `prefers-reduced-motion`、高对比和灰度下仍能区分状态；不使用闪烁和持续庆祝。
- 键盘顺序为上下文 → 主动作 → 队列 → 证据 → 辅助动作；弹窗打开时焦点进入标题/首控件，关闭后回到触发按钮。

## 9. 原型与生产迁移边界

v3 原型只确认信息架构、视觉层级和交互契约；示例数字不是业务事实。生产迁移必须继续复用已有的 `recordEvent`、`recordExternalEvent`、保存/回滚、审计、来源框架、SurfaceContext 和公开 API 契约，不在渲染层另造数据判断。

现有生产能力没有因为原型重排而删除：Insights、Archive、Editor、Focus、AI、导入导出、渲染块、外部来源和 API 仍有入口。尚未实现或条件性的项目在页面上使用“候选/待验证/外部依赖”标签，不伪装成可用功能。

原型中没有 `data-page`、`data-open` 或 `data-command` 的按钮只用于展示静态状态（例如候选标签、占位筛选和示例操作），不能据此宣称生产已有完整交互。迁移时必须为它绑定真实动作、明确标成“预览”，或从交付页面移除；所有示例数字和来源状态同样按预览数据处理。

原型自身已接线的交互范围也要明确：页面导航、命令过滤、无匹配空状态、`G` 后接 `T/R/O/S`、`N` 新建、`C` 快速记录、主题/密度切换、Review 标签和设置开关只模拟可见状态；快速记录弹窗按触发项目显示名称、目标、单位和默认值，每次打开先回到“完成一次”，用户在当前会话内再切换 `Add 数值 / Set 自定义`；确认只显示“未写入数据”的预览提示。顶部状态槽与底部操作栏也必须使用“仅预览 · 未写入”语义，不能把示例状态写成已保存或可撤销。未接线按钮显示“该操作尚未接入交互”。弹窗打开后焦点进入首个控件，Tab 在弹窗内循环，Escape/关闭后焦点回到触发控件。

## 10. 视觉验收清单

- [ ] Today 首屏能在 3 秒内找到唯一主动作。
- [ ] 记录成功、失败、撤销、跳过、部分完成、上限破戒、自动来源均可读且可恢复。
- [ ] Review 每个数字都有范围、分母、更新时间和原始事件入口。

- [ ] Occasions 的逾期不使用羞辱文案，推迟后给出明确结果。
- [ ] Editor 先给未来预览，再保存；规则改变不改写历史。
- [ ] 移动端输入法、底栏、安全区、系统返回和焦点恢复可完成核心任务。
- [ ] 深色、低刺激、200% 字体、键盘、读屏和 reduced-motion 路径保持等价。
