## 设计提炼

| 需要解决的问题 | 本轮采用的原则 | 对插件的具体影响 |
| --- | --- | --- |
| 每个习惯都像独立大卡，数量增加后视觉割裂 | 同一组习惯作为一份清单阅读 | 紧凑布局使用连续白底、轻分隔和一致列宽；宽屏继续利用多列。 |
| 每行都出现多个显眼按钮，注意力分散 | 让习惯名称和当前数值优先被看见 | 快捷记录采用较柔和的强调色；次要入口维持可辨认但降低视觉重量。 |
| 为放下更多项目而缩小点击区 | 分开处理图形尺寸、命中尺寸和行距 | 主要触控目标 44px；复选框图形 18px，外围选择标签保持可点范围。 |
| 统计、说明和工具栏都有独立外框 | 用位置和排版表达层级 | 统计合成一条；工具条去重复外壳；设置目录不再套白卡。 |
| 短数字好看，长名称却失真 | 用真实长内容决定布局 | 保留换行、完整名称与单位；不通过裁掉用户内容换取整齐。 |
| 借进度底色时容易混淆戒除目标 | 视觉必须服从原有目标语义 | 柔和目标进度仅用于适合的累积目标；不把戒除类数值增长画成正向成就。 |

没有新增每日鸡汤、装饰性数据或大插画。原有七日概览仍按用户设置显示；借鉴 Productive 的信息层次，不等于强制增加一个常驻日期组件。

## 各页实际修改

### 今日清单与概览

- 紧凑模式及窄端将同组打卡项放在一张连续表面中，行间用细线区分，减少大量独立卡片边缘和空隙。
- 数量/时长等累积目标使用真实进度驱动的低对比底色，同时保留数值、单位和细进度条。完成、跳过、多选的状态继续独立表达。
- 快捷记录与打卡按钮由重复的实心强调块改为柔和底色，名称和当前进度更容易先被扫到。
- 时长项目及非二值的番茄来源项目，在非戒除方向下提供右侧显式主操作“开始专注”/窄屏“专注”。左侧保留项目图标，启动计时无需猜测隐藏入口。
- 用户同时明确手动打卡是普通使用路径：时长项的专注旁直接显示文字“记录”，普通数值项的快捷按钮旁显示“填写”，未完成的完成型项目显示“备注”。点击后展开手动数值、备注、照片与提交控件；手动记录无需启动或安装番茄钟。
- 内置计时重复进入同一项目保留原会话；已有其他项目正在计时时提示并保留原会话，避免误触重置时间。
- 多选模式继续只提供选择操作，不恢复单项打卡、编辑或专注动作。
- 概览降低高度；连续记录将标签、天数和项目名拆分，使长名称不与说明挤在同一行。继续保留暖色连续区与紫色今日进度区。
- 已完成区与待完成清单靠近，减少区块间无信息的空白。

### 桌面顶栏与移动底栏

- 桌面通过间距区分品牌、日常页面和设置，标签使用较克制的圆角矩形，选中页以底色与字重体现。
- 移动底栏未选中项回归次级颜色，避免多个页面名称同时像当前页；当前页保留图标底色和文字强调。
- 中央新建按钮减弱悬浮投影，继续保留明确加号和稳定入口位置。
- 修正共享搜索图标的路径，统一为可辨认的放大镜。

### 回顾

- 三个独立指标卡合并为一条统计带，用轻分隔保持数字之间的关系。
- 时间范围切换使用统一选项底座；导出等工具取消重复外框，避免工具与内容争夺注意力。
- 页内分类采用轻分隔与较低视觉权重；月份切换保留明确左右按钮及触控范围。
- 总结标题、说明和间距重新配比；上一轮已经完成的“较上期按需展开”继续保留，数据不因视觉简化被删除。

### 新建与编辑

- 桌面从基础表单旁边挂一个细窄预览，调整为连续表单、预览条和高级设置的纵向顺序；预览不再与主要输入争夺同一行高度。
- 宽屏名称与图标选择并排，其他字段按自然顺序占满内容列；高级设置展开后仍可按组织信息、计划信息分列。
- 五种类型选择改为统一分段底座和清楚的选中项，减少独立大卡的割裂感。
- 模板入口、输入框、图标入口和预览动作统一圆角比例。模板仍按需展开，键盘焦点仍清晰可见。
- 卡片预览与实际操作保持一致：时长和合适的番茄来源展示专注/记录，普通数值展示快捷量/填写，完成型展示打卡/备注；切换类型、来源、方向时即时更新。长步长在正文完整展示，预览仍为非交互说明。
- 保存/取消保持可达，桌面保存栏留在插件自己的滚动区域内；本轮并未改动保存业务或番茄钟协议。
- 短横屏移动宿主中，阻止编辑内容被flex压成视口高度，恢复真实底部滚动余量；预览与自定义值可以滚到保存栏上方完整阅读，不再被底栏覆盖。

### 习惯复盘与归档

- 复盘指标合成一条统计带，数字和说明保持同一阅读轴；建议以左侧细线区分层次，减少多个彩色框叠加。
- 长标题、建议正文及证据说明保持换行。
- 归档选择区保留 44px 操作范围，复选框本身恢复为 18px，避免被通用输入框规则撑大。
- 选中归档项有行底色与边界反馈；恢复与删除继续分开，危险操作使用危险色。

### 设置

- 分类目录移除多余白色卡壳；普通悬停与当前分类区分。桌面当前分类使用侧边标记，窄端使用底部标记。
- 开关行按文字列加 44px 控件列分配，说明不再被一个空的宽控件列挤窄。
- 手机下拉选项的说明放到控件下方整行，避免说明在左侧连续折成多行。
- 统一字段、次级按钮圆角和高度，明确主文字、说明、章节标题的层次。
- 清理叠加的卡片外间距，避免不同宿主中章节间距忽大忽小。

### 日期事项

- 日期与倒计时独立一行，日期用语义化 `time` 节点；类型、重复规则和提前提醒作为次级信息。
- 不再为每个正常启用项重复放“启用”标签；今天与停用等有辨识意义的状态仍显示。
- 长名称与备注仍可完整阅读；长备注按需展开，列表不会被每条长文撑满。
- 搜索增加放大镜；筛选入口去掉重复外框，展开后再展示字段。
- 转为打卡、编辑、启停、删除统一矢量图标和 44px 命中范围；删除与常用操作留间隔。
- 表单字段、标签、备注和保存区重新对齐，按钮不再使用明显悬浮胶囊效果。

## 打卡形式与自定义变化矩阵

本节来自对 [types.ts](../src/types.ts)、[model.ts](../src/model.ts)、[rules.ts](../src/rules.ts)、[shared.ts](../src/shared.ts)、[record-step.ts](../src/record-step.ts) 和 [fragments.ts](../src/render/fragments.ts) 的只读梳理。类型、排期、方向、来源是可以组合的维度；不能只检查三个默认演示项目，就认为所有打卡形式适配完成。

| 形式/变化 | 当前数据含义 | UI 必须保留的语义与验收要求 |
| --- | --- | --- |
| `binary` 完成型 | 默认目标为 1，普通排期为完成/未完成 | 主动作应明确打卡或撤销；若为戒除方向则改为记破戒/撤销破戒，图标辅助名称也必须一致。 |
| `count` 计数 | 数值、单位和独立的快捷步长 | 如喝水目标 8 杯，快捷一次可能 1 杯或其他用户配置；不可从目标推断本次增量。 |
| `duration` 时长 | 累计时长与目标；常见单位为分钟、小时 | 右侧显示“开始专注”/“专注”，旁边直接显示“记录”；手动填写时长是正常路径，展开后可附备注与照片，无需番茄钟。 |
| `quantity` 数量 | 克、毫升、公里等任意数量单位 | 不把大数值误当时间；目标和已记录量使用相同单位，不能把“记录 250 毫升”缩成无法辨认的增量。 |
| `custom` 自定义 | 用户定义的数值、单位和步长 | 保留自定义单位与必要类型/分组辨识；不能仅因没有间隔/配额排期就把所有描述一并隐藏。 |
| 百分数目标 | 通常为 `custom` 且单位为 `%`，没有独立百分比类型 | 数值仍是业务量。例如 65/80% 的目标完成进度为约 81%，不是 65%；不能擅自把所有目标限制在 100，或把原始值替换成完成比例。 |
| 周/月配额 `value` | `quota.amount` 是周期目标，进度累计该周期同单位事件值 | 明确周期与单位；显示目标采用周期配额，不与单日 `target` 混淆。 |
| 周/月配额 `dates` | 进度是周期内有真实记录的不同日期数 | 数值显示单位为“天”；同日多次记录只贡献一天，不能将一个快捷按钮标成保证增加一天。记录输入仍采用原项目单位。 |
| `binary + quota` | 二值项目进入周期计数视图，而非普通每日开关 | 展示周期进度及记录动作；不能沿用“一个勾号代表整周完成”的排法。 |
| `atMost` 数值型 | 仅每日排期，未超过上限即达成；增长代表上限用量 | 显示“上限”及已用量，不显示鼓励补足的“还差”；使用中性的用量条，超过上限时明确状态，不画正向庆祝进度。 |
| `atMost + binary` | 当日无真实记录为成功，任意真实记录为破戒 | 不提供会自动入账的专注入口；“今日已避开”与破戒操作不混用普通完成文案。 |
| 弹性配额 `AUTO` | 周期达成后推导的日期状态，非独立类型、非新增事件 | 不把推导日期描述成当天真实手动记录；跳过、真实记录、配额达成的既有计算优先级不因外观改变。 |
| 番茄来源 `minutes` | 完成时按实际分钟入账，小时单位按既有换算 | 非二值项目可配置来源；计时目标与实际完成量分开，不能把计划时长直接记成已完成时长。 |
| 番茄来源 `sessions` | 一次合格完成记 1，与会话实际分钟数不同 | 显示“番茄钟·次数”；不能因新增专注按钮落入内置分钟写值路径，将 25 分钟记成 25 次。 |
| 自定义步长 | 正有限值，最多 1,000,000,000，最多两位小数；默认值按种类和单位决定 | 检查 `+0.01`、`+250`、`+1000000000` 等；固定 44px 动作不能只把溢出的关键数字裁成省略号。 |
| 自定义图标 | 支持 emoji、最多 24 字符文本、HTTPS 图片和本地 data URL | Today、预览、专注面板采用相同图标渲染语义；图片地址不能在面板中变成一长串可见文字。 |
| 长名称、单位和大值 | 编辑器名称上限 40 字；导入/API 可能更长；存储单位最多 16 字符，目标可为较大有限值 | 名称、单位、目标、已记录值都要在窄端实际阅读；不仅检查元素边界，还检查文本是否被裁切。不能通过展示假缩写改变计量。 |
| 历史修订 | 类型、目标、单位、步长和排期按日期修订解析 | 当前卡片、补记、番茄完成不能混用不同日期的单位或步长；UI 重排不改变修订选择规则。 |

### 番茄来源与启动入口的契约边界

`completionSource` 与类型独立，保存表单没有仅允许时长型的限制。现有 Dock Tomato 适配器支持非 `binary`、非 `atMost` 项目；[联动文档](docktomato-integration-plan.md) 明确次数、数量、自定义及按次计入的项目不传目标时长，使用提供方的默认时长。因此非时长、按次计入的番茄项目需要可发现的外部专注入口，不能简单按 `kind === duration` 划分全部能力。

`completionSource=tomato` 的既有文案是“兼容的番茄钟插件”，并非专属于一个提供方。本轮显式启动入口按当前合作场景选择 Dock Tomato；普通时长项目仍使用用户设置的计时提供方。番茄来源项目在提供方不可用时给出诊断，不无声切换到内置计时器，不改变用户保存的来源、次数/分钟模式。手动记录入口始终保留。`binary` 的泛 API 来源标签也不能被当作 Dock Tomato 自动入账已受支持的证明。

### 代码审计发现与实现状态

以下修正已在代码中实现；具体自动验收结果和真实宿主边界见文末。

1. **自定义辨识已恢复**：紧凑样式保留自定义类型的 metadata，避免普通排期下类型与分组一起消失；没有把所有项目恢复为多行重复说明。
2. **大步长展示已调整**：步长数字或单位超过 4 个字符时，快捷按钮使用“记录”，正文显示完整的 `+步长` 与单位；辅助名称及悬停说明保留实际记录量，避免显示“+10…”造成误判。按天配额同样在正文交代真实记录增量，区分“周期天数”与“本次记录量”。
3. **小数输入粒度已修正**：精确记录支持最小 0.01 的既有步长，计数的整步仍为 1，不再把合法默认增量放进与其不匹配的 0.1 输入步进中。
4. **上限方向已独立表达**：数值型戒除项目显示“上限”，去掉正向“还差”提示，进度条表示中性用量，超过上限时使用超限状态。二值戒除项图标辅助名称与记破戒/撤销破戒动作一致。
