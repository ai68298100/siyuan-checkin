# 小驴打卡 UI 原型系统 v2（2026-10-03）

> 状态：设计基线 / 待实现。本文是页面、组件、交互和视觉验收的统一来源。
> 配套原型：[checkin-ui-v2.html](./prototypes/checkin-ui-v2.html)。
> 适用范围：完整插件页面、快速记录、Dock、移动端、嵌入块、提醒、AI、导入导出和恢复中心。

## 1. 这次重构要解决什么

小驴打卡的核心定位是“把想持续做的事，变成今天可以安全完成的一步，并且让结果可回看、可解释、可撤销”。UI 不负责施压，也不替用户判断人生价值。它需要同时服务四个时刻：

1. **现在要做**：用户打开插件后能立即知道今天最小的一步是什么。
2. **刚刚做完**：用户能确认事实已经写入、知道来源，并且能撤销或修正。
3. **想理解**：用户能从原始事件走到统计、趋势和复盘，再返回原位置。
4. **想调整**：用户能修改规则、提醒和绑定，并在保存前看到影响范围。

本版本把“精品”定义成可验证的体验质量：主动作稳定、结果可信、解释足够、错误可恢复、视觉安静、跨 Surface 连续。任何新增功能都必须说明它减少了哪种负担、增加了哪种选择权，以及如何证明它没有把维护成本转移给用户。

## 2. 现有原型审视结论

本次审视覆盖 `docs/images/today-light.png`、`review-light.png`、`review-dark.png`、`settings-light.png`、`editor-light.png`、`occasions-light.png`，并对照现有 `tokens.scss`、`page-shell.ts`、UI 审计和页面路线文档。

| 现状证据 | 体验风险 | v2 决定 |
|---|---|---|
| Today 用大面积完成卡、连续卡、提醒条、搜索和任务卡并列展示 | 视觉上有层级，行动上却要先读多块内容才能找到“现在做什么” | 首屏固定为上下文条、唯一主动作、下一步卡、任务队列；统计降为辅助证据 |
| Review 已有“概览/记录/分析”页签和日程图 | 指标、图表和项目卡缺少统一的事实来源与钻取返回契约 | 所有派生数字都带来源、分母、计算口径；图表点击进入事件并保留原筛选和滚动 |
| 设置是长表单，左侧目录与右侧字段稳定 | 按内部实现分组，用户要在“外观/今日视图/连接能力”等词之间猜自己该去哪 | 改为“我想改变什么”导向的任务卡，字段按目标渐进展开，高级项可搜索 |
| 编辑器推荐网格内容丰富，底部保存条醒目 | 选择模板、改字段、设规则和预览同时出现，首次创建决策数过多 | 三步向导：定义、安排、确认；每步只保留一个主选择，右侧实时预览“今天会怎样出现” |
| 日期事项使用左右分栏，空列表与表单同时占据大量空间 | 空态时编辑区显得像主任务，移动端也难以保持双栏 | 桌面 list-first + 可关闭详情抽屉；移动端单列，编辑作为全屏/底部 Sheet |
| 深色截图基本复用浅色层级 | 色彩变化后边界、状态、强调色的语义容易被误读 | 深色是独立对比板；状态同时使用文字、图形、位置和色彩，禁止只靠颜色 |
| 现有 token 已具备独立浅色/深色、圆角、间距和 z-index | 组件样式历史叠加较多，设计原则尚未沉淀成页面级契约 | v2 先固化语义 token 和组件状态，再逐页迁移；不在迁移期间改变数据语义 |

## 3. 产品模型与信息架构

### 3.1 六层信息模型

页面任何内容只能属于以下一层，并使用固定视觉通道：

| 层 | 含义 | 默认表现 | 可执行动作 |
|---|---|---|---|
| 事实 Fact | 已写入的记录、来源、日期、单位、状态 | 普通文本、来源胶囊、时间线 | 查看、修正、撤销 |
| 规则 Rule | 目标、频率、分母、跳过、提醒配置 | 说明行、规则标签、预览 | 编辑、暂停、复制 |
| 派生 Derived | 完成率、趋势、周期、连续天数 | 图表或指标卡，必须带口径 | 钻取、比较、隐藏解释 |
| 建议 Suggestion | 模板推荐、AI 草稿、下一步 | 低对比卡、建议标识、依据入口 | 采用、修改、忽略 |
| 动作 Action | 记录、补记、保存、导出、恢复 | 唯一主按钮或动作栏 | 执行、撤销、取消 |
| 治理 Governance | 权限、隐私、备份、冲突、诊断 | 状态条、恢复中心、设置卡 | 授权、重试、导出、清理 |

### 3.2 一级导航和辅助 Surface

```text
Today  记录今天的事
Review 回看已经发生的事
Insights 理解一个项目的长期形态
Occasions 管理日期事项和提醒
Archive 找回暂停、归档或删除前的内容
Settings 调整体验、规则、数据和连接

全局辅助：Quick record / Focus / Command palette / Reminder inbox / AI workspace
承载形态：Tab（完整工作台）· Dock（轻量连续）· Dialog（快速完成）· Block（就地查看）· Mobile（单列）
```

所有页面都从同一 `SurfaceContext` 进入和返回：

```text
page · returnTo · itemId · localDate · timezone · range · workspace
query · filters · source · draftId · focusId · scrollAnchor · pendingTaskId
```

上下文条必须能读出当前日期、范围、项目、来源和保存状态。回退、刷新、宿主切换、弹窗关闭和移动系统返回使用同一个返回栈；不把用户送回默认首页，不清空刚完成的记录。

### 3.3 全局壳原型

```text
┌───────────────┬──────────────────────────────────────────────────────────────┐
│  小驴         │  [当前页面] [日期/范围] [来源] [已保存 / 待同步]  [⌘K] [主题] │
│  Today        ├──────────────────────────────────────────────────────────────┤
│  Review       │  页面标题 + 目标说明                       [辅助动作]        │
│  Insights     ├──────────────────────────────────────────────────────────────┤
│  Occasions    │  可选的工作区页签 / 筛选条 / 搜索                           │
│  Archive      ├─────────────────────────────────────┬────────────────────────┤
│  Settings     │  主内容：事实、列表、图表或表单       │  证据/建议/状态侧栏      │
│               │                                      │  可收起，不抢主动作      │
│  ＋ 快速记录  ├─────────────────────────────────────┴────────────────────────┤
│  ◷ 专注       │  动作栏：撤销 · 稍后处理 · 保存/记录（主按钮固定）            │
└───────────────┴──────────────────────────────────────────────────────────────┘
```

桌面宽度大于 1120px 使用 216px 导航栏；760–1119px 收缩为 72px 图标栏；小于 760px 使用顶部标题和底部五项导航。任何宽度下主动作都在拇指/键盘可预测的位置，辅助侧栏可隐藏，不能覆盖表单错误或提交按钮。

## 4. 设计规范

### 4.1 颜色：使用语义角色，不直接写色值

现有 `src/ui/tokens.scss` 的独立浅色/深色板作为实现基础。组件只能引用语义角色，不能把品牌紫色当作所有状态色。

| 角色 | 浅色基线 | 深色基线 | 用途 |
|---|---|---|---|
| `canvas` | `#F7F7FC` | `#141419` | 页面背景 |
| `surface` | `#FFFFFF` | `#1D1E24` | 卡片、抽屉、表单 |
| `surface-raised` | `#FFFFFF` | `#23242C` | 弹窗、悬浮、键盘导航 |
| `surface-muted` | `#EFF0FA` | `#26272F` | 筛选条、次级区块 |
| `border` | `#E4E6F4` | `#2C2D38` | 分隔和输入边界 |
| `text` | `#2A2B35` | `#EFEFF6` | 主文本 |
| `muted` | `#63657A` | `#9FA0AC` | 帮助、时间、次要信息 |
| `accent` | `#5B65E8` | `#8B93F8` | 主动作、当前页、焦点 |
| `success` | `#3BA55D` | `#4CBB7F` | 已保存、已完成 |
| `warning` | `#E89A2B` | `#F0B45C` | 待确认、即将过期 |
| `danger` | `#E5484D` | `#F07C7C` | 删除、失败、冲突 |
| `warm` | `#F6A94B` | `#F6B04E` | 轻量庆祝、日期事项 |

对比要求：正文和主按钮文字至少 4.5:1，非正文至少 3:1；焦点环与相邻背景至少 3:1。深色不使用纯黑大块文字，不用金色表示失败，不用红色表示普通未完成。

### 4.2 字体、间距和几何

```text
字体：Inter, PingFang SC, Microsoft YaHei, ui-sans-serif
display 28/36 720 · page 24/32 720 · section 18/26 680
body 14/22 450 · label 13/20 600 · help 12/18 450 · metric 30/36 720
间距：4 / 8 / 12 / 16 / 22 / 32px
控件：36px 默认、44px 触控、52px 主动作；卡片圆角 14px，弹窗 20px
内容最大宽度：1200px；文本行最大宽度：72ch；卡片内边距：16–22px
```

密度有 `comfortable`、`compact` 两档。密度只改变留白和一屏可见数量，不改变顺序、文案和动作语义。用户设置的 200% 字体、中文长名称和辅助技术文本不能被截断。

### 4.3 动画、层级和声音

```text
fast 120ms · normal 180ms · page 240ms；只做透明度、颜色和小幅位移
z：banner 2 · header 5 · nav 20 · action dock 21 · popup 30 · modal 40
```

禁止自动滚动、闪烁、连续数字跳动和会改变主按钮位置的庆祝动画。`prefers-reduced-motion`、低刺激模式和无声音模式必须让页面仍能完成同一任务。声音/振动只能补充文字反馈。

### 4.4 状态词典

所有页面和 API 文档共用以下词：

```text
草稿 draft → 保存中 saving → 本地已保存 saved
待同步 pending-sync → 冲突 conflict → 失败 failed
已确认 confirmed → 已撤销 undone → 已归档 archived
```

“完成”只描述项目规则是否达成，不能代替“写入完成”或“同步完成”。每个状态必须同时有文字、图标/形状和位置，不得只用颜色。

### 4.5 组件契约

| 组件 | 必须提供 | 交互要求 |
|---|---|---|
| `PageShell` | 标题、目标说明、上下文、返回、状态槽 | 返回保留上下文，标题不随加载闪烁 |
| `ContextBar` | 日期/范围、项目、来源、保存状态 | 点击可展开详情，刷新不丢筛选、焦点、滚动 |
| `PrimaryButton` | 动词 + 对象 + 处理中状态 | 提交后幂等锁定；成功显示事实和撤销 |
| `FilterBar` | 已选条件、清除、保存视图 | 条件变化显示影响范围，移动端进抽屉 |
| `TaskRow` | 名称、规则、事实状态、来源、主动作 | 整行可聚焦，主动作位置稳定，支持键盘 |
| `StatusChip` | 文案、图形、可选详情 | 不用红点表达普通未完成 |
| `MetricCard` | 数值、单位、分母、日期、来源 | 点击可回到事件；空值有解释，不显示伪 0 |
| `EmptyState` | 当前原因、下一步、可跳过动作 | 空库、筛选无结果、未配置、离线分别处理 |
| `ErrorState` | 发生了什么、已保护什么、现在做什么、详情 | 保留输入和草稿，重试不重复写入 |
| `Drawer/Dialog` | 标题、上下文、关闭、返回、保存状态 | 关闭前按风险提示；Esc/系统返回等价 |
| `UndoBar` | 影响对象、截止时间、撤销结果 | 撤销后展示前后差异，过期给替代修复路径 |
| `AISuggestion` | 建议、依据、不确定性、影响 | 只能草稿；采用前可编辑，拒绝后不重复打扰 |

## 5. 页面级原型

### 5.1 Today：行动台

**目标**：在 30 秒内完成一条记录或明确稍后处理。首屏只问“今天现在要做什么”。

```text
┌ 上下文：2026-10-03 周六 · 本地时间 · 已保存 ─────────────── [⌘K] ┐
│ 今天                                                          │
│ 还有 3 项 · 已完成 5/8                 [＋ 快速记录]           │
├ 下一步 ────────────────────────────────────────────────────────┤
│ 阅读 30 分钟   规则：每天 · 今天未记录       [记录] [稍后]      │
├ 待完成 · 3 ────────────────────────┬ 今日事实 / 建议 ─────────┤
│ ○ 喝水 2000 ml       [记录]         │ 记录节奏：稳定            │
│ ○ 深度工作 90 分钟   [开始专注]     │ 依据：过去 7 天 5 次        │
│ ○ 背单词              [记录]         │ [查看原始记录] [隐藏建议]   │
├ 已完成 · 5（可折叠） ───────────────────────────────────────────┤
│ [撤销] [查看今天时间线]                         [更多]          │
└───────────────────────────────────────────────────────────────┘
```

规则：主按钮始终是“记录/开始专注”，完成后变为“已记录 · 撤销”；数字输入采用内联微表单，不打开多余页面。搜索、筛选、分组在第二层。空态、离线态、待同步态、失败态都在同一个上下文条和行内状态槽表达。

### 5.2 Quick record：一件事的快速闭环

```text
┌ 快速记录 · 2026-10-03 · 阅读 ──────────────── [关闭] ┐
│ [完成一次] [30 分钟] [自定义数值]                       │
│ 数值（可选）  [ 30 ] [分钟 ▾]                           │
│ 备注（可选）  [今天读到……                         ]     │
│ 来源：手动记录                         [查看规则]       │
├───────────────────────────────────────────────────────┤
│ [取消]                 [保存草稿] [确认记录]            │
└───────────────────────────────────────────────────────┘
```

自然语言输入可以先生成待确认草稿：“今天读了 30 分钟”；解析结果必须分字段展示，时间、项目、单位、日期可逐项改。保存成功后依次提供继续记录、查看来源、撤销、回顾四项，不用庆祝动画打断连续输入。

### 5.3 Review：证据工作台

**结构**：范围选择 → 概览/记录/分析 → 证据 → 项目钻取。概览先展示事实计数，分析才展示解释。

```text
┌ 回顾 · 本周 ▾ · 2026-09-28—10-03 · [导出] [报告] ─────────────┐
│ [概览]                 [记录]                 [分析]            │
├ 本周事实：42 条 · 7 个项目 · 4 个来源 · 数据截至 18:24       │
├ 完成节奏（派生，按日） ────────────────────────────────────────┤
│ ▂ ▅ ▇ ▆ ▇ ▄ ▆       点击柱 → 当日事件，返回保留本图范围       │
│ 口径：已确认记录 / 有效安排；跳过不计入分母  [查看定义]         │
├ 项目证据 ───────────────────────────────┬ 原始事件/来源 ──────┤
│ 阅读 5/7  · 71%  [钻取]                  │ 10-02 20:14 手动     │
│ 运动 3/3  · 100% [钻取]                 │ 10-01 18:03 文档块   │
│ ……                                      │ [打开完整时间线]     │
└────────────────────────────────────────┴──────────────────────┘
```

记录工作区是可搜索的时间线，分析工作区允许比较但默认隐藏排名和压力文案。每张图必须有数据更新时间、分母、来源、无数据语义和回到事件的入口。

### 5.4 Insight detail：一个项目的长期解释

```text
┌ ← 回顾  洞察 · 阅读 · 本月 · 本地已保存 ─────── [导出] [调整规则] ┐
│ 身份：阅读 · 单位：分钟 · 目标：30/天 · 有效安排 22 天           │
├ 状态日历：完成 / 跳过 / 未配置 / 无数据 / 冲突（图例固定）        │
├ 趋势：事实折线 + 目标线 + 解释点；点击点进入当天原始事件          │
├ 周期：启动 → 稳定 → 波动 → 休息（只描述数据，不诊断用户）         │
├ 下一步建议：把目标改为 20 分钟？ [查看依据] [编辑草稿] [忽略]       │
└ 统计定义、来源、更新时间、撤销链                                    │
```

状态日历不把没有记录写成失败；“未配置”和“无数据”分开。AI 或规则解释必须以建议卡呈现，保持用户可以只看事实。

### 5.5 Editor：创建/编辑向导

```text
┌ ← 返回    新建打卡项       1 定义 ── 2 安排 ── 3 确认 ─── [关闭] ┐
│ 名称 [阅读]          类型 [数值 ▾]          图标 [📖]             │
│ 你想记录什么？ [阅读时长]   单位 [分钟 ▾]                       │
│ 常用模板：阅读 · 运动 · 喝水       [从空白开始]                 │
├ 右侧预览：Today 会显示 ────────────────────────────────────────┤
│ 阅读 · 30 分钟 · 每天                                               │
├ [保存草稿]                                  [下一步：安排]       │
```

第二步只处理频率、有效安排、跳过和提醒，并给出未来 7 天预览。第三步展示规则差异、历史统计影响、绑定影响和可撤销窗口。离开时恢复卡区分未保存、待同步和冲突。

### 5.6 Occasions：日期事项

```text
┌ 日期事项 · 今天 / 即将 / 逾期 · [+ 新建] ───────────────────────┐
│ 已设置 8 项 · 今日触发 2 项 · 下一提醒 14:00                    │
├ 列表（主）                                  ┌ 编辑抽屉 ────────┐ │
│ 今天  送礼物       [完成] [推迟]              │ 名称              │ │
│ 今天  还款         [打开]                     │ 日期/重复/提醒    │ │
│ 10-08 妈妈生日    [打开]                     │ 来源/备注         │ │
│ 空态：从模板开始 / 手动新建                  │ [保存] [取消]     │ │
└─────────────────────────────────────────────┴───────────────────┘
```

列表优先、编辑可关闭。提醒的推迟、静默、关闭、暂停都在同一动作菜单中，结果写入状态条和最近操作，不靠红点施压。

### 5.7 Archive：恢复中心

Archive 是恢复工具，不是“垃圾桶”。分为暂停、归档、待删除和可恢复草稿四个筛选；每行显示原因、最后事实、绑定、可恢复期限和影响预览。批量恢复前展示数量与规则冲突，永久删除要求先给导出/备份选项，并在完成后保留短审计。

### 5.8 Settings：按目标设置

```text
设置
[我想改变什么？ 搜索设置] [舒适模式：低刺激] [保存状态]

┌ 记录体验 ┐   今天显示、默认日期、记录后动作、数值输入
├ 提醒与专注 ┤ 安静时段、频率预算、Focus、声音/振动
├ 规则与统计 ┤ 单位、分母、跳过、周期、历史重算预览
├ 数据与连接 ┤ 文档绑定、导入导出、备份、权限、同步队列
├ 外观与无障碍 ┤ 浅色/深色、高对比、密度、字号、动效
└ 关于与诊断 ┘ 版本、能力、日志、复制安全摘要、恢复默认
```

设置项默认使用“当前值 + 一行解释 + 影响预览 + 恢复入口”。变更规则先显示未来计划、历史口径、提醒和外部绑定的差异，确认后才写入。

### 5.9 Reminder inbox、Diary/Questionnaire、Focus

- **Reminder inbox**：把提醒配置、导入冲突、AI 草稿和诊断合并为“稍后处理”队列；支持排序、批量忽略、暂停和来源。红点只表示有明确待处理项，不能催促用户。
- **Diary / Questionnaire**：一问一屏或一组同类型问题，支持跳过、保存草稿、回到上一问；答案与派生建议分层，提交前显示会写入哪些字段。
- **Focus**：开始前显示项目、计时口径、结束后的入账选择；切换窗口、锁屏、休眠和系统时钟变化都显示实际计时并允许调整后确认。Dock 只保留计时、暂停、结束和返回来源。

### 5.10 Command palette、AI workspace 和数据中心

`⌘/Ctrl+K` 打开命令面板：搜索页面、项目、动作和帮助；按最近上下文排序，显示快捷键和结果范围。命令执行后回到原页面并保留筛选。

AI workspace 采用四步：**解释 → 生成草稿 → 用户编辑 → 确认写入**。建议卡必须列出输入范围、来源、置信度/不确定性、预计影响和隐私开关。AI 不直接改变目标、规则或历史；用户拒绝后不重复展示相同建议。离线或没有模型时，界面仍可完成手动记录。

数据中心提供导入、导出、备份、恢复、健康扫描、绑定和同步队列。所有批量动作先展示预计数量、去重依据、部分失败行为和取消方式；结果可回到原始事件。

### 5.11 Dock、嵌入块和移动端

| 形态 | 保留 | 收起/延后 |
|---|---|---|
| Dock | 当前项目、记录、撤销、同步状态、返回来源 | 图表、解释、批量设置 |
| 嵌入块 | 日期、项目、事实状态、最小记录按钮、来源 | 导航、全局设置、复杂编辑 |
| 移动端 | 标题、上下文、主动作、底部导航、撤销 | 侧栏、诊断字段、次级筛选 |

移动端小于 390px 时采用单列和底部 Sheet；输入法出现时提交区跟随键盘上方。安全区、系统返回、屏幕阅读器、字号放大和横屏均有等价路径。

## 6. 核心交互契约

### 6.1 记录闭环

```text
意图（我要完成/补记/修正）
  → 选项目和日期（上下文条可见）
  → 输入最小字段（高级字段延后）
  → 提交（按钮锁定、显示处理中）
  → 事实结果（写入内容、来源、统计影响）
  → 继续 / 查看来源 / 撤销 / 回顾
```

本地幂等操作可以乐观反馈；外部写入、统计重算、导入和 AI 采用 pending。超过 300ms 有轻反馈，超过 1s 有阶段、可取消和可离开说明。失败保留输入，成功项和失败项分开，重试不能重复写入。

### 6.2 统一中断和返回

刷新、切页、关闭、宿主重载、锁屏、系统时间跳变和网络恢复都先恢复 `SurfaceContext`，再恢复草稿/队列/计时。上下文不可恢复时显示恢复卡：继续、另存、放弃；不能静默丢弃。

### 6.3 空态、加载态、错误态

```text
加载：骨架保留标题、上下文和主动作位置
空库：告诉用户尚未配置，提供模板/空白/跳过
筛选无结果：显示当前筛选，可一键清除，不暗示没有数据
未配置：解释缺少哪一项，提供就地设置
离线：显示数据更新时间和可用动作，事实不伪装成同步完成
失败：发生了什么 / 已保护什么 / 现在做什么 / 查看详情
```

### 6.4 AI 与隐私

默认本地优先、最小数据范围、明确提供者和保留期。发送前按字段预览，敏感备注默认不发送。AI 文案用“可能、依据、建议”，不做健康诊断、不做道德评价、不把未完成改写为失败。所有 AI 写入都是草稿并可撤销。

## 7. 实现顺序与设计交付

1. **P0 契约层**：状态词典、SurfaceContext、页面壳、语义 token、键盘/返回/撤销契约。
2. **P1 核心层**：Today、Quick record、Review、Insight、Editor；先迁移主动作和状态，再迁移装饰。
3. **P2 运营层**：Occasions、Archive、Settings、Reminder inbox、Focus、Diary/Questionnaire。
4. **P3 扩展层**：AI workspace、数据中心、导入导出、绑定、Dock、嵌入块和移动端。
5. **P4 证据层**：视觉 harness、宽度走查、键盘/读屏、弱网/离线/中断恢复、长文案和多窗口。

每一阶段交付：页面截图（浅色/深色/高对比）、状态矩阵、交互录屏或脚本、SurfaceContext 样例、可访问性检查、性能预算和回归任务。静态原型只用于确认信息架构和视觉方向；接入真实 API 前不得把示例数字当成业务事实。
