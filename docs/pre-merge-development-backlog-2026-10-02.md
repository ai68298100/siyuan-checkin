## 2. 产品定位

### 2.1 一句话定位

小驴打卡是运行在思源笔记中的本地优先习惯与行为记录工作台：用户在今天完成记录，在可追溯的事件账本中保留事实，在复盘页面理解变化，再把结果连接到笔记、提醒和经过明确授权的外部来源。

### 2.2 它解决的问题

用户通常需要在行动、记录、复盘和知识管理之间反复切换。单纯的打卡工具难以解释数据，单纯的笔记又缺少稳定的日常操作和统计语义。小驴打卡将这几个环节放在同一个工作流中：

1. 先用低摩擦操作记录事实。
2. 用稳定的日期、单位、计划和事件语义保存事实。
3. 允许用户修正历史，同时保留修正过程。
4. 用日、周、周期和自定义指标进行复盘。
5. 在用户主动选择后，把数据写入思源文档或接收外部来源。
6. 在桌面、移动端、浏览器、停靠栏和嵌入块之间保持一致的含义。

### 2.3 产品北极星

- 今天打开后，用户能在一个屏幕内知道现在应该做什么、已经做了什么、下一步怎么记。
- 每一条记录都能回答日期、单位、来源、修改过程和是否真正保存。
- 复盘结果能解释数据，而不是只给出装饰性图表。
- 外部集成失败时不会污染本地账本，重试不会产生重复记录。
- 新用户能在几分钟内完成第一个可复用的打卡项目，老用户能快速完成批量记录和复盘。

### 2.4 目标用户

| 用户类型 | 主要目标 | 关键界面 |
| --- | --- | --- |
| 第一次使用者 | 快速理解概念并完成第一次记录 | 首次引导、模板、今天 |
| 日常轻量用户 | 用最少操作完成一次打卡 | Today 卡片、快速记录、快捷对话框 |
| 数值习惯用户 | 记录次数、时长、重量、金额等连续数据 | 编辑器、局部记录、图表 |
| 复盘型用户 | 看趋势、偏差和周期变化 | Review、Insights、历史详情 |
| 笔记原生用户 | 把记录绑定到思源文档和段落 | 文档目标、绑定块、编辑器嵌入 |
| 集成型用户 | 从外部来源导入并保持幂等 | 来源设置、映射、导入历史 |
| 多设备用户 | 在桌面、移动端、浏览器间继续工作 | 响应式 Today、导航、同步状态 |
| 维护者和生态消费者 | 使用稳定 API 或适配器 | API、契约、诊断、兼容性文档 |

### 2.5 产品边界

- 记录的是用户确认过的事实，不替用户推断未完成原因。
- 计划、记录、修正、跳过、归档、删除和外部导入要有可解释的状态。
- 本地数据是默认权威；外部来源是可追溯的输入，不直接覆盖本地历史。
- 集成入口必须显示来源、最后同步时间、失败原因和重试动作。
- 产品保持低压力体验，不用连续天数或奖励机制强迫用户完成任务。
- 产品可以给出建议，但建议不能静默修改记录或把未完成判为失败。

## 4. 核心领域模型和交互规则

### 4.1 领域对象

| 对象 | 作用 | 必须能回答的问题 |
| --- | --- | --- |
| Habit | 用户想持续记录的项目 | 记录什么、单位是什么、目标是什么 |
| Schedule | 项目在什么时候应出现 | 今天是否应出现、下一次何时出现 |
| RecordEvent | 一次事实记录 | 何时发生、值是多少、从哪里来 |
| Revision | 对历史记录的修正 | 谁在何时为何修改了什么 |
| Reminder | 促使用户采取行动的提示 | 为什么现在提醒、如何关闭或恢复 |
| Occasion | 与日期相关的事件 | 事件发生在哪一天、是否重复 |
| ExternalBinding | 项目和外部来源的绑定 | 来源是什么、映射如何解释 |
| SourceItem | 外部来源返回的候选 | 原始 id、时间、值和可追溯信息 |
| Template | 可复用的项目和计划预设 | 应用后会创建或覆盖哪些字段 |
| DocumentTarget | 记录写入的思源目标 | 写入哪个文档、块或段落 |
| FocusSession | 专注计时会话 | 开始、暂停、结束和是否已经写入 |

### 4.2 统一事实语义

- 日期展示与聚合统一使用项目的 localDate 规则，不能直接用浏览器 UTC 日期替代。
- 一次保存要先建立本地事件状态，再显示成功；失败时保留输入并给出可重试动作。
- 同一个 externalRef 在同一来源、同一项目下重复到达时必须幂等。
- 删除是可审计的 tombstone 语义；恢复、重导入和冲突解决要能解释结果。
- 修改历史记录不应该改变原始记录的来源和时间，除非用户明确编辑这些字段并能看到差异。
- atMost、abstinence、quota、duration 等词在界面、统计和导出中保持同一含义。
- “跳过”“未完成”“没有数据”“来源失败”是四种不同状态，不用一个布尔值混淆。

## 5. 用户使用逻辑

### 5.1 新用户首条记录

1. 首次打开显示产品用途、数据位置、主题选择和隐私边界。
2. 用户选择一个 starter 模板，或从空白创建项目。
3. 创建流程先询问想记录的行为，再选择类型、单位、目标和计划。
4. 预览今天会出现的卡片和下一次出现时间。
5. 保存后直接进入 Today，卡片显示可执行动作。
6. 第一次记录完成后显示保存成功、事件时间和可进入 Review 的入口。
7. 若中途退出，恢复草稿或明确放弃，不丢失用户输入。

### 5.2 日常 Today

1. 用户进入 Today，先确认日期和当前上下文。
2. 顶部展示今日进度、待处理数量和需要注意的提醒。
3. 卡片按紧急性、计划时间、连续等待和用户固定顺序排列。
4. 二值项目提供完成和跳过；数值项目提供快速增量、输入完整值和编辑详情。
5. 完成后卡片显示记录值、来源和撤销入口，避免按钮突然消失导致不确定。
6. 对过期、未计划、已归档和外部来源项目显示不同的状态提示。
7. 页面结束前允许快速添加、回填其他日期、进入复盘或打开项目编辑。

### 5.3 数值、时长和局部记录

- 次数项目支持加一、减一、输入总数和修改单次记录。
- 时长项目支持手动输入和 Focus Timer 写入，两种来源在详情中区分。
- 数量项目显示单位、精度、范围和累计目标，拒绝无法解释的字符串。
- 局部记录必须说明它是当天总量、一次增量还是一个区间。
- 输入错误保留原输入，显示字段级原因，提交按钮不应静默失效。

### 5.4 跳过、atMost 与 abstinence

- 跳过需要选择或填写可选原因，但不自动等于失败。
- atMost 项目同时展示已用量、上限、剩余空间和超出后的处理规则。
- abstinence 项目显示连续天数和最近一次事件，但不把空白日期写成虚假记录。
- 复盘中分别统计完成、跳过、无数据、超额和被删除事件。
- 用户能在历史详情中把跳过改为完成，或把完成改为跳过，并看到修正轨迹。

### 5.5 历史修正和批量回填

1. 用户从 Today、Review 或记录详情进入具体日期。
2. 页面显示该日期原始计划、已有事件、来源和计算结果。
3. 编辑单条记录时预览统计如何变化。
4. 批量回填提供范围、项目、值、来源和冲突提示。
5. 提交后逐条报告成功、跳过、冲突和失败，不用一个总成功覆盖部分失败。
6. 可撤销动作要明确截止范围，过期后保留审计记录。

### 5.6 复盘

1. 选择日期范围或周期预设。
2. 先看结论卡，再看趋势、日历、事件时间线和单条记录。
3. 每个结论显示样本量、缺失日期、计算规则和最后更新时间。
4. 用户可以按项目、标签、来源、状态和计划过滤。
5. 点击图表节点可回到对应记录和原始事件。
6. 复盘结束提供调整计划、导出、绑定文档和创建提醒的动作。

### 5.7 提醒和日期事件

- 提醒卡必须说明触发原因、关联项目、推迟、关闭和今日静默的区别。
- 关闭是当前提醒实例的结束，今日静默只影响当前 localDate，暂停规则影响未来计划。
- 日期事件和里程碑在 Today 与 Occasions 中显示相同日期含义。
- 农历、重复和时区换日要有预览和可验证示例。

### 5.8 外部来源和文档绑定

1. 用户先选择来源，再查看可查询的候选列表。
2. 映射步骤展示原始名称、来源 id、时间字段、单位转换和目标项目。
3. 导入预览显示新增、更新、忽略、冲突和无法解析项。
4. 执行后保存导入批次、原始引用和重试信息。
5. 写入思源文档前显示目标文档、块或段落，失败时本地事件仍可用。
6. 再次同步按 externalRef 和来源时间幂等，不创建重复事件。

### 5.9 Focus Timer

- 选择项目和预设时长后显示开始、暂停、继续、完成、取消。
- 页面刷新、切换 tab 或打开第二个 Focus 面板时，计时状态只有一个权威来源。
- 计时完成后先确认本地保存成功，再显示庆祝或完成动画。
- 用户修改预设或关闭页面时，如有未保存会话，必须给出保留、结束或取消选择。

## 6. UI 原型与信息架构

### 6.1 总体壳层

桌面端：

- 顶部：品牌、当前空间或文档上下文、日期切换、全局搜索、主题与设置。
- 左侧或页内导航：Today、Review、Occasions、Templates、Archived、Settings。
- 主区：页面标题、摘要和主要操作，下方是卡片或表格内容。
- 右侧可选：提醒、快速记录、当前项目详情或诊断面板。
- 停靠栏和 tab 使用同一页面状态，但拥有各自的宿主尺寸和关闭行为。

移动端：

- 顶部保留日期、页面标题和一个主操作。
- 底部导航固定 Today、Review、Add、Occasions、More。
- 卡片动作保持 44px 以上触摸区域，次要字段折叠。
- 对话框改为底部抽屉，保存与取消固定在安全区域内。

嵌入块和浏览器：

- 以单任务为中心，只显示目标项目、状态和最短操作路径。
- 提供打开完整插件的入口，不能把完整导航强行塞进窄容器。
- 宿主上下文变化时，组件重新读取 root context，不使用上一个窗口的 currentPage。

### 6.2 Today 原型

页面顺序：

1. 日期和上下文条：上一天、今天、下一天、返回当前日。
2. 今日摘要：已完成、待完成、跳过、提醒和保存状态。
3. 注意事项：失败重试、过期项目、来源异常和草稿恢复。
4. 主任务卡：项目标题、目标、当前值、计划信息和主动作。
5. 次任务卡：折叠的备注、来源、最近记录和快捷增量。
6. 提醒卡：触发原因、推迟、关闭、今日静默。
7. 快速添加：选择已有项目、创建项目、录入历史日期。
8. 页面底部：进入 Review、导出、打开设置。

卡片状态：

- 空状态：解释为什么没有项目，并提供模板和创建入口。
- 计划中：显示下一次出现时间。
- 待完成：主按钮高对比，显示目标和剩余量。
- 已完成：显示实际记录和撤销。
- 跳过：显示原因和恢复完成入口。
- 过期：显示补记、忽略和调整计划。
- 保存中：按钮禁用但保留输入。
- 保存失败：保留输入、错误原因、重试和查看诊断。
- 来源冲突：显示本地值、外部值和选择规则。

### 6.3 Add 与项目编辑原型

采用意图优先的分步或单页渐进展开：

1. 我想记录什么。
2. 记录类型和单位。
3. 目标、方向和计划。
4. 今天及未来的出现预览。
5. 提醒、文档目标和外部绑定。
6. 保存前总结，提示哪些字段会创建新项目、哪些会覆盖已有设置。

不同类型的动态字段：

- 二值：完成方式、跳过规则。
- 次数：单次增量、每日目标、上限。
- 时长：计时器、手动输入、分钟精度。
- 数量：单位、精度、最小最大值。
- 自定义：值域、显示文本、统计方式。

编辑器底部固定显示保存、取消、恢复默认和查看历史。离开页面时保护未保存输入。

### 6.4 Review 原型

页面层次：

- 摘要：完成率、总量、连续变化、缺失日期、来源状态。
- 时间线或日历：按日期点开事件和计划。
- 图表：趋势、分布、对比、atMost 余量、时长累计。
- 过滤条：项目、日期、来源、状态、标签、计划。
- 详情抽屉：原始事件、修订历史、绑定文档和导出。
- 复盘动作：调整目标、复制计划、创建提醒、写入文档。

图表必须有空数据、低样本、异常值、加载失败和无障碍文本状态。小屏优先显示摘要与时间线，图表通过横向滚动或分段展开。

### 6.5 Settings 原型

- 设置首页先显示当前主题、数据位置、备份状态、来源连接和未完成事项。
- 左侧或顶部显示分组，内容区只显示当前分组。
- 设置搜索返回字段级结果，点击后定位并展开字段。
- 所有字段统一显示默认值、当前值、保存状态、恢复默认和帮助说明。
- 来源设置使用连接、候选查询、映射、导入历史、诊断五步结构。
- 文档选择器采用一个搜索框加候选列表，不再保留两个语义重叠的输入框。
- 长候选列表必须分页或增量加载，不能静默截断。

### 6.6 视觉和交互规则

- 颜色、间距、圆角、阴影和文字层级使用统一 token。
- 明暗主题各自定义背景、卡片、边框、主色、警示色和图表色，不直接跟随思源主题。
- 键盘焦点、错误提示、保存结果和动态更新必须有清晰的可视与读屏反馈。
- 触摸目标至少 44px，窄屏 320px 仍能完成主流程。
- 支持减少动态效果、输入法组合、系统字体放大和安全区域。
- 任何用户输入、来源文本、文档标题、URL 和动态 HTML 都必须经过适当转义或白名单处理。

## 7. 分阶段路线

| 阶段 | 目的 | 主要交付 |
| --- | --- | --- |
| Wave 0 事实与质量 | 先固定语义、时间、错误和测试基线 | 领域状态机、now 注入、数据契约、核心回归 |
| Wave 1 核心使用闭环 | 让新用户和日常用户顺畅完成记录 | Today、Add、编辑器、提醒和历史修正 |
| Wave 2 多表面与多窗口 | 让不同宿主看到一致状态 | RootContext、路由隔离、快速对话框、移动和停靠栏 |
| Wave 3 设置、国际化和安全 | 让配置可发现、内容可安全渲染 | 字段注册、i18n、ARIA、输入和 URL 审计 |
| Wave 4 复盘和模板 | 让数据真正指导调整 | Review、图表、周复盘、模板包、导入导出 |
| Wave 5 生态和 API | 让外部来源在真实边界内可维护 | API v5、适配器、能力探测、同步诊断 |
| Wave 6 条件性研究 | 在产品决策后试验高风险方向 | points、Story、CalDAV、同步、代理建议 |

优先级含义：

- P0：数据语义或核心保存可靠性问题，阻塞后续功能。
- P1：核心用户路径和合并质量必须完成。
- P2：体验、生态、性能和维护性优化。
- R：需要真实外部条件或产品决策，先做研究、契约和验证。
- 依赖使用 PM 编号；同组任务应按依赖顺序推进。

第一批先完成 PM-001、PM-002、PM-003、PM-007、PM-009、PM-020、PM-057、PM-097。这批任务决定后续实现是否会建立在错误的日期、保存和状态语义上。

第二批进入 PM-013 至 PM-024、PM-025 至 PM-032、PM-049 至 PM-060，形成 Today、编辑器、提醒和 Focus 的完整闭环。

第三批处理 PM-061 至 PM-072、PM-073 至 PM-096，解决多表面、设置、国际化、无障碍和动态内容安全问题。

第四批推进 PM-037 至 PM-048、PM-033 至 PM-036、PM-099 至 PM-110，补齐复盘、模板、性能和测试质量。

第五批只在本地契约稳定后推进 PM-111 至 PM-120。外部来源没有真实会话或消费者时，任务停在能力探测、适配器、夹具和诊断，不将模拟通过写成接通。

PM-121 至 PM-130 属于研究或产品决策，应该用短 spike、原型和决策记录推进。没有明确结论时，不把它们混入核心数据模型。

## 10. 每个开发批次的执行协议

1. 一次选择一到三个相互依赖的 PM 任务，先写数据语义和失败路径。
2. 优先新增边界清晰的模块、适配器、夹具和测试，避免为了整理而重写入口文件。
3. 先运行与任务直接相关的测试，再运行 check、build 和必要的视觉或宽度检查。
4. 记录命令、结果、环境和未解决外部阻塞；不要编造测试结果。
5. 每个批次完成后进行一次小提交，提交信息包含 PM 编号和行为变化。
6. 推送仅使用当前开发分支 dev/thispc-1002，不推 main，不创建发布 tag。
7. 合并前再次确认受保护文件未修改、没有版本漂移、没有未解释的测试失败、没有把模拟生态当成真实接通。
8. 只有当 P0/P1 任务有实现、测试和验收证据后，才进入合并讨论；条件性任务保留清晰的决策和阻塞状态。

## 12. 调研后新增的产品判断

本节把外部资料转成适用于本插件的设计假设，所有假设都要通过本地原型、用户走查或数据验证后再固化：

- Fogg Behavior Model 将行为发生归因于动机、能力和提示在同一时刻相遇。提示应匹配用户此刻能做的最小动作，不能把复杂目标压缩成一条高压力通知。[Fogg Behavior Model：Prompts](https://www.behaviormodel.org/prompts)
- UCL 对习惯形成的研究显示，达到稳定自动性的时间个体差异很大，研究样本的中位数约为 66 天，范围为 18 到 254 天。因此产品不应把 21 天或固定连续天数包装成科学承诺，而应展示个人趋势和不确定性。[Lally 等人的研究 PDF](https://discovery.ucl.ac.uk/id/eprint/10118622/1/Jan%20paper.pdf)
- if-then 计划把可感知线索和目标动作绑定。近期系统综述发现它可能改善行为结果，但效果会受行为、目标和人群影响，应该作为可选计划和实验记录，而不是对所有人强制开启。[PubMed 系统综述](https://pubmed.ncbi.nlm.nih.gov/41987207/)
- UCL 的 BCTTv1 整理了 93 类行为改变技术，并建议从可接受性、可实施性、效果、成本、外溢影响和公平性等维度评估方案。插件可以记录自己采用了哪种干预方式，便于解释和复盘，而不应该把黑盒建议当成医学结论。[UCL Behaviour Change Centre](https://www.ucl.ac.uk/behaviour-change/resources/other-resources)
- WCAG 2.2 强调焦点不能被遮挡、状态消息要能被辅助技术感知、自动更新和非紧急打断应能暂停或推迟。这些要求适用于 Today 卡片、提醒、计时器、图表和动态同步。[W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- Loop、Habitica、TickTick、Streaks 等公开资料显示，灵活重复规则、统计反馈、提醒、专注、快捷入口、模板和可选游戏化是用户熟悉的能力；其中开源或本地优先产品把离线、隐私、导出作为信任的一部分。[Loop](https://loophabits.org/)、[Habitica](https://habitica.com/static/features)、[TickTick](https://ticktick.com/features)、[Streaks](https://streaksapp.com/)

由此形成的产品原则：

1. 连续天数只是一个视图，不是唯一目标。
2. 允许最小行动、部分完成、休息、补记和恢复，避免把一次中断解释为失败。
3. 提醒要有上下文、最小动作和推迟或静默选项。
4. 所有建议都显示依据、置信度、可关闭方式和影响范围。
5. 行为数据、备注、附件、来源和实验结果默认留在本地，任何外发都要显式授权。
6. 游戏化、社交和 AI 只能作为可选层，不得改变事实账本或制造惩罚。

## 20. 页面级原型补充

### 20.1 页面与表面状态矩阵

所有页面都必须显式处理以下状态：loading、empty、no-match、draft、saving、saved、failed、retry、offline、readonly、permission-denied、unsupported、stale 和 destroyed。状态消息应能被键盘和辅助技术感知；自动更新允许暂停或改为手动刷新。

| 页面/表面 | 主任务 | 空或无匹配 | 失败/无权限/离线 | 保存成功与返回 |
| --- | --- | --- | --- | --- |
| Today | 完成或记录今天的项目 | 显示模板、创建和导入入口 | 保留输入，显示重试、诊断和本地记录替代 | 卡片保留结果和撤销，返回当前日期 |
| Add/Edit | 创建或修改项目 | 显示最小必填字段和示例 | 字段级错误、草稿恢复、外部绑定可稍后配置 | 显示创建或修改范围，回到来源页面 |
| Review | 理解周期并找到下一步 | 解释没有数据、范围为空或样本不足 | 图表降级为列表，计算失败可重算 | 保存筛选或报告批次，返回原过滤视图 |
| Occasions | 查看、创建和编辑日期事件 | 提供创建事件和导入入口 | 农历、权限或重复规则失败时显示明细 | 详情关闭后回到日期列表和滚动位置 |
| Archived | 找回、恢复或永久删除项目 | 解释归档为空，提供历史搜索 | 损坏或旧版本项目只读打开并可导出 | 恢复后回到 Today 或原筛选，永久删除二次确认 |
| Templates | 浏览、预览、应用和管理模板 | 提供 starter 模板、导入和创建入口 | 包损坏、冲突、版本不兼容逐项列出 | 应用批次可撤销，回到模板详情 |
| Quick Dialog | 用最少操作完成一次记录 | 显示最近项目和搜索入口 | 宿主不支持时打开完整插件，不丢输入 | 显示一条结果和继续记录动作 |
| Focus | 开始、暂停、完成或取消会话 | 解释需先选择项目或预设 | 休眠、时钟回拨、保存失败可恢复会话 | 事件确认写入后显示完成，关闭回到 Today |
| Embed/Block | 在文档上下文完成单一动作 | 显示绑定或配置入口 | 块销毁、文档移动、权限失败时可重新绑定 | 更新块状态并保留宿主滚动位置 |
| Dock/Tab | 快速查看或记录 | 显示打开完整页面入口 | 宿主关闭、窗口变化、根节点失效时清理监听器 | 关闭后重新打开不复用错误页面状态 |
| Settings | 找到并修改一个配置 | 显示分组说明和搜索入口 | 保存失败保留字段，权限问题指向诊断 | 显示分组级保存结果，不丢其他分组草稿 |

### 20.2 关键页面主流程补充

**Occasions**：Today 日期条或导航进入 → 选择公历/农历和重复规则 → 预览未来日期 → 保存草稿 → 保存成功后显示事件 → 点击事件进入详情 → 编辑、暂停、归档或删除 → 返回时恢复筛选、日期和滚动位置。

**Archived**：设置或项目菜单进入 → 按归档原因、日期、标签筛选 → 打开只读详情 → 选择恢复、复制为新项目、导出或永久删除 → 恢复前展示会重新生成哪些计划和提醒 → 完成后回到原列表并标注结果。

**Templates**：模板画廊 → 搜索或按目标类型筛选 → 预览将创建的项目、计划、提醒、文档绑定和默认值 → 选择完整应用或部分应用 → 冲突预览 → 确认批次 → 逐项成功/忽略/失败 → 撤销或进入创建的项目。

**Backup/Restore**：设置进入数据安全 → 查看主数据、设置、附件和队列的备份范围 → 创建备份并校验 → 选择备份比较差异 → 先打开只读预览 → 选择整体恢复或按项目恢复 → 自动创建当前快照 → 恢复结果和失败项可导出。

**Quick Dialog / Dock / Embed**：从宿主触发 → 读取所属 root context → 选择项目或读取绑定 → 输入最小值 → 显示解析与日期预览 → 本地保存 → 外部写入异步排队 → 保留成功或失败状态 → 宿主关闭时清理自己的监听器和焦点。

**Focus**：选择项目与预设 → 开始 → 页面隐藏或休眠 → 用单一时间源恢复 → 暂停/继续 → 完成前确认记录值和发生时间 → 事务写入事件 → 保存成功后庆祝 → 保存失败保留会话并提供重试或取消。

**插件生命周期**：onload 注册一次 → 创建每个根节点的 context → 加载数据和设置 → 宿主销毁时卸载监听、timer、队列订阅和 DOM → 重复加载检测并复用或拒绝 → 卸载插件不删除用户事实，只清理运行时和可选缓存 → 重新安装后提示可恢复数据绑定。

### 20.3 附件与文档绑定状态

附件流程必须独立于文字备注验收：选择文件或拍摄 → 校验类型、大小和权限 → 显示哈希或本地引用 → 上传/复制失败时保留原记录输入 → 预览和删除 → 引用计数检查 → 备份包含与否预览 → 导出可选择原文件、缩略图或仅元数据 → 恢复后重新校验路径 → 文档权限失效时本地事实仍可读。

### 20.4 插件卸载和宿主降级

- 插件停用、重复加载、思源窗口关闭、浏览器刷新和嵌入块销毁都必须释放事件监听、定时器、观察器、焦点陷阱和异步队列。
- 宿主不支持通知、剪贴板、文件选择、文档 API 或移动返回栈时，页面要显示能力状态和替代动作。
- 权限被撤回后保留已保存数据，新的外部动作进入待授权或本地队列；重新授权不能重复写入。
- 卸载只移除运行时注册、缓存和可选绑定，用户事实、备份、模板和导出文件按照用户选择保留。

## 25. AI 产品路线：本地优先、可解释、可撤销的助手（PM-361—PM-410）

AI 待办以“事实账本由用户确认、建议可追溯、能力可关闭”为硬约束。AI 先服务于查找、解释、起草和检查，再逐步扩展到受确认保护的写入；任何 provider 都不能绕过现有 mutation、revision、备份和权限边界。

## 26. AI 安全、隐私、评测与治理待办（PM-411—PM-440）

这一组任务把 AI 从“能调用模型”推进到“可证明地适合发布”。治理参考 NIST AI Risk Management Framework 的 Govern、Map、Measure、Manage 思路和 NIST 生成式 AI profile，并吸收 OWASP Top 10 for LLM Applications 的提示注入、敏感信息泄露、过度代理和供应链风险；这些是设计输入，不能替代本仓库自己的离线夹具与用户验收。

| ID | 优先级 | 待办与验收 |
|---|---|---|

| PM-412 | P0/R | 建立“无证据不陈述、无确认不写入”规则；模型不能凭空生成事件、完成率、引用、用户偏好或历史对话。 |

## 27. 性能、可靠性、兼容性、可观测性与生态收口（PM-441—PM-480）

## 29. 新增任务的依赖、优先级和执行顺序

### 29.1 先修实现边界，再做 AI

第一批应优先处理 PM-321—PM-350 中 P0 的日期、配额、索引、streak、focus 写入和生命周期问题。它们是 AI 读取和提议的事实基础；若底层日期或事件索引不稳定，AI 只会把错误解释得更像正确答案。

第二批建立 PM-361—PM-380 的 adapter、context compiler、脱敏、来源、schema、缓存和审计骨架，再实现 PM-381 之后的具体能力。任何“AI 功能完成”都不能绕过这些边界。

第三批执行 PM-411—PM-440 的安全评测和 PM-441—PM-480 的容量/兼容性/恢复验证，最后以 PM-481—PM-500 的原型和 fixture 收口。若资源不足，保留只读、可解释、规则降级的能力，延后语音、OCR、自动个性化和远端写入。

### 29.2 任务完成证据

新增任务标记完成时，至少记录：

1. 代码、原型或决策记录位置，以及任务依赖是否已满足。
2. 成功、空态、加载、失败、重试、取消、离线、权限撤回、过期和卸载路径。
3. 对历史数据、索引、revision、备份、导入导出和回滚的影响。
4. 桌面、窄屏、移动和至少一个 dock/tab/embed 宿主表面的检查。
5. AI 任务额外记录 context 白名单、来源覆盖率、schema 版本、外发同意、成本/延迟和红队夹具。
6. 未执行的真实 provider、真实思源版本、用户研究或外部权限联调必须明确标注，不能用本地 stub 代替结论。

### 29.3 本轮研究输入

- [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)：用于 Govern、Map、Measure、Manage 的治理结构。
- [NIST Generative Artificial Intelligence Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)：用于生成式 AI 的风险识别和测量问题。
- [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/)：用于提示注入、敏感信息泄露、过度代理和供应链风险的测试清单。

以上资料只约束待验证方向，不构成插件已经满足的安全证明；发布前仍以本仓库的脱敏 golden dataset、红队夹具、宿主矩阵和用户可复核证据为准。

## 30. 产品总纲：从插件到“可信行动工作台”（PM-501—PM-540）

前 500 项主要回答“要补哪些功能、缺哪些验证”。这一组先回答“整个产品到底是什么”。当前最稳固的定位基础是：**小驴打卡是思源笔记里的本地优先、低压力、可追溯的行动记录与复盘工作台**。它的价值链是：

> 设定可行规则 → 低成本记录真实行动 → 核对事实来源 → 看懂变化和阻力 → 做出下一项小调整 → 保留可回看的长期记忆。

它不是通用任务管理器、医疗健康诊断器、社交排名产品、游戏化积分系统、云同步服务或无边界 AI 代理。所有新增方向都要能回答“它怎样让行动记录更可信、更容易理解或更容易调整”，否则进入长期候选或拒绝。

| ID | 优先级/类型 | 待办与验收 |
|---|---|---|
| PM-501 | P0/D | 写出一页产品北极星：一句话定位、核心用户、核心问题、核心闭环、三项原则、五项非目标；仓库中所有路线文档链接到同一版本。 |

## 33. 美观度、视觉语言与设计系统（PM-601—PM-630）

产品定位最终必须被看见、被读懂、被操作出来。视觉不是给功能清单加装饰，而是把“事实、理解、调整、治理”四层能力变成稳定的感知秩序。精品感来自每次进入都知道自己在哪里、当前最重要的动作是什么、结果是否已经写入，以及遇到异常时仍然能继续前进。

| PM-627 | P1/R | 建立视觉债务台账：重复 SCSS、legacy/v4 规则、旧 DOM hook、主题覆盖、平台特例；每项有影响、删除风险和清理证据。 |
| PM-628 | P0/R | 建立 page×surface×width×theme×state 的视觉快照矩阵，固定日期、时区、字体、数据、随机种子，并定义宿主噪声白名单。 |
| PM-629 | P0/R | 建立视觉评审清单：品牌、层级、留白、对比、密度、对齐、截断、动作、空错状态、焦点、滚动和宿主遮挡。 |
| PM-630 | P0/R | 精品视觉合并门槛：主任务一眼可见、状态不靠颜色单独表达、关键动作不跳动、空态有下一步、浅深主题同义、窄屏可操作。 |

## 34. 研究、指标与证据系统（PM-631—PM-660）

“精品”不能只凭主观审美或单次演示判断。需要把用户是否理解、是否完成、是否信任、是否能够恢复、是否愿意长期使用，转成可复现的研究脚本、指标口径和证据链。指标服务于决策，不服务于制造压力。

| ID | 优先级/类型 | 待办与验收 |
|---|---|---|
| PM-631 | P0/D | 定义北极星指标：用户在不被强迫的情况下完成一次可信记录并能解释其来源；明确计算口径、观察窗口和不应优化的代理指标。 |
| PM-632 | P0/R | 建立指标分层：激活、记录成功、事实可追溯、回顾理解、调整完成、恢复成功、长期留存、性能、错误、无障碍和隐私。 |
| PM-633 | P0/R | 为每个指标写数据字典：事件名、触发条件、属性、去重规则、时区、版本、采样、隐私级别、缺失值和解释限制。 |
| PM-634 | P0/R | 区分事实指标、推导指标和体验指标，禁止把点击量、连续天数或提醒打开率直接当作用户价值。 |
| PM-635 | P1/R | 建立核心漏斗：首次理解→创建目标→首次记录→首次撤销→首次回顾→首次调整；每层记录失败原因而不只记录流失。 |
| PM-636 | P1/R | 建立“信任漏斗”：能找到来源、能读懂口径、能修正错误、能撤销写入、能备份恢复；任何一层失败都有用户可见的补救。 |
| PM-637 | P1/R | 设计定性研究脚本，覆盖首次用户、30 项重度用户、数值型用户、上限/戒除用户、移动用户、隐私敏感用户和无网络用户。 |
| PM-638 | P1/R | 设计任务完成观察表：目标理解、首次动作、误操作、回退、求助、情绪负担、恢复策略和最终是否获得可信结果。 |
| PM-639 | P1/R | 建立 usability benchmark：首次成功时间、记录耗时、错误恢复时间、回顾理解率、撤销成功率、键盘完成率和屏幕阅读器阻断率。 |
| PM-640 | P1/R | 建立性能基准：首屏 paint、首次可交互、记录提交、撤销、图表渲染、导入、批量操作、AI 预览和低端 WebView。 |
| PM-641 | P0/R | 为每个错误码定义用户影响、可恢复性、重试次数、数据是否写入、诊断字段和优先级；错误趋势可按版本和宿主拆分。 |
| PM-642 | P1/R | 建立数据质量指标：孤儿事件、重复事件、非法日期、冲突记录、丢失模板、异常 tombstone、派生值漂移和恢复失败。 |
| PM-643 | P1/R | 建立提醒质量指标：触达后行动、误触、重复提醒、过期提醒、暂停后触达和一键关闭成功率；不以提醒数量作为成功。 |
| PM-644 | P1/R | 建立 AI 质量指标：引用正确率、事实/建议混淆率、用户采纳后修改率、拒绝率、越权尝试、敏感信息暴露和无模型降级成功率。 |
| PM-645 | P1/R | 建立视觉质量指标：布局偏移、截断主动作、对比度失败、焦点不可见、颜色单通道状态、主题污染和组件漂移。 |
| PM-646 | P1/R | 建立隐私指标：默认采集面、授权覆盖面、撤回完成时间、清理残留、导出脱敏率和诊断包最小化程度。 |
| PM-647 | P0/R | 让所有统计卡片显示口径、范围、来源和更新时间，并允许跳回事实；无法解释的数字不得作为主卖点。 |
| PM-648 | P1/R | 设计匿名且本地优先的诊断快照，用户可以预览字段、删除字段、导出、复制和撤销，不上传整库。 |
| PM-649 | P1/R | 建立固定 golden datasets：空库、单项目、复杂规则、跨时区、损坏数据、海量事件、AI 注入和多 Surface 并发。 |
| PM-650 | P0/R | 为 golden datasets 记录预期事实、派生值、排序、统计、UI 状态、错误码和撤销结果；任何核心改动都能比较。 |
| PM-651 | P1/R | 建立人工研究与自动化测试的分工表，避免用截图替代交互测试、用点击量替代理解测试、用单元测试替代宿主验收。 |
| PM-652 | P1/R | 建立每月问题复盘：新增问题、重复问题、已关闭问题、误报、回归、用户影响、证据缺口和下一步负责人。 |
| PM-653 | P1/R | 建立反馈分类与合并规则，把“不会用”“不信任”“性能慢”“数据错误”“视觉不适”“宿主兼容”分开统计。 |
| PM-654 | P1/R | 设计版本前后对比模板，分别展示事实可靠性、用户路径、视觉回归、性能、无障碍、AI 安全和迁移风险。 |
| PM-655 | P1/R | 设定停止条件：某功能连续造成数据质量下降、压力指标上升、性能超预算或支持成本高于价值时，自动进入重做/下线评审。 |
| PM-656 | P1/R | 建立用户可见的“数据健康”检查入口，显示问题数量、风险等级、建议动作和已解决历史。 |
| PM-657 | P1/R | 建立合并前证据包模板：需求理由、主任务、状态矩阵、fixture、测试、截图、性能、无障碍、数据迁移和回滚方案。 |
| PM-658 | P0/R | 让每条产品承诺都能链接到证据：本地优先、可追溯、可解释、可撤销、可迁移、低压力、无模型可用。 |
| PM-659 | P0/R | 研究验收必须包含真实思源宿主和浏览器 stub 两类证据，明确 stub 不能代替宿主兼容性结论。 |
| PM-660 | P0/R | 形成季度精品评审：北极星、用户研究、数据质量、性能、无障碍、视觉一致性、隐私、AI 安全和生态兼容同时签收。 |

## 35. 路线、质量与产品运营治理（PM-661—PM-690）

产品定位要能持续约束路线，而不是只在文档里出现一次。后续开发应按依赖、质量门槛、观察窗口和停止规则推进，让每项能力都有进入理由、验证方法、维护责任和退出路径。

| ID | 优先级/类型 | 待办与验收 |
|---|---|---|
| PM-661 | P0/D | 将路线分成稳定核心、体验增强、生态联动、AI 实验四条泳道，规定每条泳道的容量上限、风险等级和质量门槛。 |
| PM-662 | P0/R | 绘制依赖图：日期与事实账本→索引与统计→记录与回顾→联动→AI；任何上层能力不得绕过下层契约。 |
| PM-663 | P0/D | 把路线主题固定为可靠事实、低摩擦记录、可解释复盘、可迁移数据、生态扩展、AI 辅助，并为每项写完成、暂停和放弃条件。 |
| PM-664 | P0/R | 建立季度路线评审包：问题、用户、证据、非目标、依赖、资源、风险、观察窗口、回滚和退出条件；不把功能数量当作进展。 |
| PM-665 | P1/R | 设立技术债、视觉债、兼容债、文案债和数据债预算；新增功能需要明确支付债务或记录延期。 |
| PM-666 | P1/R | 建立变更影响分级：数据模型、统计口径、公开 API、外部联动、视觉 Token、文案术语和 AI 权限分别触发对应检查。 |
| PM-667 | P0/R | 固化合并前准入：核心记录链路、迁移回退、浅深主题、移动/窄屏、API 兼容、文档、无障碍、性能和证据全部通过。 |
| PM-668 | P1/R | 统一功能生命周期枚举：候选、研究、原型、开发、验证、稳定、观察、弃用；TODO、PROGRESS、决策和发布说明使用同一枚举。 |
| PM-669 | P1/R | 每个路线主题写观测窗口和复盘日期，禁止因为代码已经合并就默认用户价值成立。 |
| PM-670 | P0/D | 建立停止规则：增加事实歧义、阻塞核心记录、依赖不可控宿主/网络、无法撤销、造成压力或维护成本失控时立即暂停扩张。 |
| PM-671 | P1/R | 为每项功能创建 owner、备份 owner、支持入口、文档入口、测试夹具、故障告警和退出负责人，避免无人维护的孤岛能力。 |
| PM-672 | P1/R | 建立从产品地图到代码、文档、测试、fixture、帮助和诊断的链接索引，一级能力必须能沿链路追踪。 |
| PM-673 | P1/R | 设计变更影响报告：输入任务 ID 后列出受影响对象、页面、路由、Token、统计、API、AI 提示、迁移和发布证据。 |
| PM-674 | P1/R | 将“该不该做”评审固化为模板：问题、用户、证据、替代、风险、非目标、成本、停止条件、恢复路径；没有结论不进入实现。 |
| PM-675 | P1/R | 建立产品决策记录 ADR：独立主题、低压力、事实优先、单一账本、可撤销、无强制云账号、AI 受确认等长期原则可被检索。 |
| PM-676 | P1/R | 建立弃用流程：提前公告、影响页面、迁移工具、兼容窗口、数据保留、替代能力、回退方案和最终清理证据。 |
| PM-677 | P1/R | 建立发布分级：文案/样式、纯读取、事实写入、统计口径、数据迁移、外部联动、AI 权限；不同等级使用不同回归深度。 |
| PM-678 | P0/R | 设计发布候选 checklist：构建、类型、单测、UI、移动、生态、性能、数据回放、视觉、无障碍、隐私、AI 红队和回滚均有责任人。 |
| PM-679 | P1/R | 建立版本后观察包：错误码、数据质量、记录成功、撤销、性能、宿主差异、AI 风险、反馈和回滚触发条件。 |
| PM-680 | P1/R | 设计问题分级与响应：数据丢失/误写、核心阻断、宿主兼容、性能退化、视觉回归、文案问题和建议分别定义响应时限。 |
| PM-681 | P1/R | 建立用户反馈→分类→脱敏复现→根因→修复→验证→发布说明闭环，反馈包默认不包含整库、备注正文和隐私字段。 |
| PM-682 | P1/R | 建立回归库：真实 bug、边界日期、跨时区、重复提交、宿主重载、权限撤回、AI 注入、长文本、低性能和无障碍问题都能重放。 |
| PM-683 | P0/R | 建立历史样本回放门槛：数据模型、统计算法、归一化、排序或时间语义变化必须对旧数据比较结果并解释差异。 |
| PM-684 | P1/R | 建立容量测试档位：30/100/500 项、1 万/10 万事件、长备注、大待处理箱、多来源、多标签和多窗口并发。 |
| PM-685 | P1/R | 建立降级矩阵：图表关闭、AI 不可用、外部源超时、宿主只读、网络断开、低端设备、存储异常时核心记录如何继续。 |
| PM-686 | P1/R | 建立灾难演练：损坏 store、半写入、重复导入、迁移中断、版本回退、外部写入失败和恢复后重算；每次记录恢复耗时和数据差异。 |
| PM-687 | P1/R | 建立支持诊断码体系：用户能复制最小诊断码，开发者能定位版本、宿主、能力、状态和失败阶段，诊断码不泄露内容。 |
| PM-688 | P1/R | 建立文档新鲜度检查：帮助、API、截图、术语、状态文案、迁移说明和产品地图与代码能力定期对照。 |
| PM-689 | P1/R | 设立“精品 council”审查机制：产品定位、交互、视觉、无障碍、性能、数据可信、隐私、生态和 AI 共同签收。 |
| PM-690 | P0/R | 路线与质量合并门槛：每项主线能力有明确用户问题、依赖顺序、证据窗口、维护 owner、失败恢复、退出条件和可审计决策。 |

## 36. 生态、互操作、社区与长期可持续（PM-691—PM-720）

小驴打卡应成为事实与复盘中枢，而不是把所有伙伴能力复制进来。生态能力必须尊重本地优先、最小权限、来源可见、受确认写入、可撤销和断开后仍可用。

| ID | 优先级/类型 | 待办与验收 |
|---|---|---|
| PM-691 | P0/D | 明确插件与思源边界：不改宿主核心；插件保有可恢复账本；文档、块、任务、番茄、阅读和外部源都是可选连接层。 |
| PM-692 | P0/R | 建立宿主能力矩阵，按桌面、Tab、Dock、移动 WebView、渲染块、只读和能力缺失列出支持、限制、替代和解释文案。 |
| PM-693 | P0/D | 定义公共 API 产品承诺：读取事实、受确认写入、来源登记、幂等、撤销、审计、版本兼容和错误可解释；新增 API 必须附安全边界。 |
| PM-694 | P1/R | 建立第三方集成准入：来源身份、字段白名单、最小权限、幂等键、失败待处理箱、撤销墓碑、数据保留、卸载清理和维护责任。 |
| PM-695 | P1/R | 设计开发者体验：能力发现、最小示例、沙箱 store、失败注入、时间/时区夹具、权限撤回、契约测试、升级和迁移说明。 |
| PM-696 | P1/R | 建立跨插件对象身份映射：项目、事件、来源、文档块和 externalRef 使用稳定标识；未知身份不得模糊合并。 |
| PM-697 | P1/R | 绘制跨插件能力地图，识别重复存储、重复提醒、重复统计、互相覆盖和循环依赖；只依赖公开契约。 |
| PM-698 | P1/R | 建立宿主/API 变更雷达和兼容预警，升级前自动生成受影响能力、页面、测试和迁移清单。 |
| PM-699 | P1/R | 设计生态熔断：单个来源失败不阻塞手动记录；可暂停来源、批量重试、清理队列、查看影响和恢复历史。 |
| PM-700 | P0/R | 设计“断开连接仍可用”演示和验收：任何外部源解绑后，记录、回顾、导出、备份和修正仍然可完成。 |
| PM-701 | P1/R | 若未来提供集成目录，先设计用途、权限、来源、维护者、更新时间、配置预览、断开和删除绑定，不引入强制云账号。 |
| PM-702 | P1/R | 设计导出/导入互操作格式，包含事实、规则、来源、修订、撤销、模板、时区、版本和冲突报告；导入前必须预览。 |
| PM-703 | P1/R | 建立数据所有权声明：可导出、可删除、可离开、格式有文档、历史事实不被云锁定，任何云联动都不能降低本地可用性。 |
| PM-704 | P0/D | 明确商业边界：无广告、无数据售卖、无强制登录、无核心事实锁定；未来收费方向必须单独通过隐私、迁移和用户价值决策。 |
| PM-705 | P1/R | 估算长期维护成本：宿主兼容、移动端、生态适配、AI provider、文档、翻译、支持、安全响应和迁移；路线必须标注成本。 |
| PM-706 | P1/R | 建立社区贡献指南：issue 模板、最小复现、good first issue、契约测试、设计资产、翻译、无障碍审核和行为准则。 |
| PM-707 | P1/R | 定义社区反馈 SLA 和公开状态：数据问题、兼容阻塞、可用性、视觉、建议和安全问题分级处理。 |
| PM-708 | P1/R | 建立公开路线和弃用摘要：候选、研究中、已承诺、已交付、观察、弃用和放弃都说明理由，不留下永久实验入口。 |
| PM-709 | P1/R | 设计隐私友好的反馈包：环境、能力、诊断码、最小复现和脱敏状态，用户能预览、编辑、删除和复制。 |
| PM-710 | P1/R | 建立安全事件响应：发现、隔离、修复、告知、回溯、撤销、迁移、复盘；覆盖导入、外部联动、AI 和供应链。 |
| PM-711 | P2/R | 评估非金钱贡献的认可方式：翻译、测试宿主、模板、无障碍和生态适配可以被感谢，但不引入社交排名和压力。 |
| PM-712 | P1/R | 建立插件包和模板的来源、授权、版本、完整性、预览、撤销和隔离策略，外部资产不能修改事实账本或主题安全边界。 |
| PM-713 | P1/R | 设计离线生态队列：来源事件有来源、幂等键、时间、状态、重试次数、冲突和撤销，最终一致性对用户可解释。 |

## 39. 自上而下的合并地图与优先级

前面的任务应按依赖关系合并，而不是按页面数量或实现快慢排列。建议把“方向正确”作为第一道门，把“事实可靠”作为第二道门，把“体验统一”作为第三道门，把“生态和 AI 扩展”作为最后一道门。

| 层级 | 主要任务 | 进入条件 | 退出证据 |
|---|---|---|---|
| L0 产品边界 | PM-501—520、PM-631—640、PM-661—670 | 主类目、用户、价值闭环、非目标、核心承诺和停止规则已冻结 | 一页产品宪章、对象词典、价值链、路线泳道和评审记录 |
| L1 事实可信 | PM-301—330、PM-741—755，以及现有模型/迁移/索引任务 | 归一化、日期、排序、幂等、撤销、冲突、模板和缓存有确定性 | golden replay、迁移报告、数据健康检查、公开 API 契约 |
| L2 核心行动 | PM-521—540、PM-571—600，以及今日/记录/撤销/补记任务 | 首次记录、日常记录、错记修复、跳过/休息和离线降级均可完成 | 30 秒、首日、首周、异常和移动旅程证据 |
| L3 理解与调整 | PM-541—570、PM-601—620、PM-631—660 | 页面职责、图表口径、来源下钻、调整草案和撤销闭环统一 | 事实→解释→建议的回链、视觉快照、可用性和性能报告 |
| L4 治理与恢复 | PM-581—590、PM-681—690、PM-721—740 | 设置、备份、导入、帮助、数据健康、删除和恢复可审阅 | 恢复演练、隐私预览、诊断包、弃用和支持流程 |
| L5 生态与 AI | PM-421—500、PM-691—720 | 核心记录无外部依赖；权限、来源、撤销、注入防护和成本可控 | 断开仍可用、真实宿主矩阵、AI 红队、schema/成本/延迟报告 |
| L6 精品发布 | PM-625—630、PM-650、PM-667—690、PM-740/755 | 视觉、无障碍、性能、兼容、数据和文档全部签收 | 发布候选证据包、回滚演练、版本后观察窗口和用户反馈闭环 |

合并前的单项任务应至少写清六件事：用户问题、所属产品层、主动作和返回路径、事实/推导/建议边界、空错恢复状态、验证证据。涉及数据、路由、Token、API、AI 或宿主能力的任务，还要增加迁移、权限、兼容和退出方案。任何任务若只能描述“增加一个入口/卡片/按钮”，却无法说明它帮助用户完成哪一步行动，应退回产品评审。

最终的产品判断标准是：用户可以用很少的动作记录真实发生的事，可以知道数字从哪里来，可以在发现不合适时调整规则，可以修正或撤销错误，可以在没有外部来源和 AI 时继续工作，也可以在暂停、迁移和离开时带走自己的事实。视觉、交互、生态和 AI 都应服务于这条主线；新增能力越强，越需要更清楚的边界、证据和恢复路径。

## 40. 用户顺畅度与舒适度总审计（PM-756—PM-821）

前面的章节回答“产品应该是什么”，这一组回答“用户实际用起来是否舒服”。顺畅度不是单纯减少点击，而是让用户在每一步都知道自己要完成什么、当前作用于哪个对象、结果是否已经生效、出了问题如何继续。舒适度也不等于弱化反馈，而是让用户拥有节奏、选择、解释和退出权。

每个场景都使用同一套验收维度：到达成本（入口、步骤、等待、记忆）、理解成本（对象、日期、单位、状态、来源）、操作舒适（鼠标、键盘、触控、输入法、焦点、反馈）、心理负担（催促、羞耻、噪声、控制感）、失败恢复（撤销、重试、草稿、离线、冲突）、长期维护（调整、暂停、迁移、删除）、视觉状态（层级、留白、动效、暗色、窄屏）和证据（时间、误操作、恢复成功率、访谈）。每个主流程至少覆盖成功、空数据、加载、失败、部分成功、离线、无权限和撤销状态，并在桌面、窄 Dock、移动端和键盘路径复验。
