# 数据、隐私与停用卸载指南

本文按 2026-10-06 的源码说明小驴打卡怎样保存、读取和导出数据。小驴打卡的核心打卡、统计和复盘在本地完成；可选来源、思源同步和 AI 的数据流需要分别判断。

## 先备份什么

在回顾页导出 JSON，可以备份**打卡主档**：项目、记录和删除标记。记录中的备注、图片附件、来源身份也随主档保存。JSON 不是整个插件的一键备份，不包含头像、显示偏好、来源配置、微信读书 Key、周复盘草稿、个人模板、问卷配置、日期事项等独立数据。

迁移或清理前，建议按以下顺序准备：

1. 导出主档 JSON，打开文件检查项目数、记录数和日期范围，并保留在独立位置。
2. 如需回退历史，另行在设置的数据分区导出本地恢复点。恢复点也只覆盖主档，不能恢复独立配置。
3. 在项目编辑器中分别导出需要的个人模板；保存自建问卷配置文本，并记下日期事项、来源绑定和文档输出目标。模板分享文件经过字段筛选，不包含打卡事件，但仍可能含你填写的模板名称、分组和规则，分享前应查看。
4. 如果要完整搬迁插件配置，应使用适合当前思源版本的工作区备份方式，并另行验证恢复。本文没有验证所有客户端的工作区备份、云端同步和卸载保留策略，不保证主档导入能恢复这些配置。

恢复主档时先查看导入预览，再确认；不要用另一设备上的空白主档覆盖有记录的工作区。格式细节见[导入导出说明](export-formats.md)，事件身份和删除合并见[身份与合并约定](identity-and-merge.md)。

## 数据存在哪里

插件通过思源插件 SDK 的 `loadData` / `saveData` 保存以下独立存储桶。表中名称是排查线索，**不要直接编辑正在运行的存储文件**。

| 数据 | 存储桶 | 是否在主档 JSON 中 |
| --- | --- | --- |
| 项目、规则历史、记录、备注、图片附件、删除标记 | `checkin-store` | 是 |
| 历次主档恢复点，可能含已删除记录的旧副本 | `checkin-store-backup` | 否，恢复点另有导出入口 |
| 合并、恢复、迁移、锚点等审计上下文 | `checkin-store-audit` | 否，审计另有导出入口 |
| 外观、照片头像、保存视图、提醒设置、来源绑定、微信读书 Key、文档目标、周复盘草稿等 | `checkin-view-preferences` | 否 |
| 个人模板、自定义图标 | `checkin-user-templates`、`checkin-custom-icon-library` | 否 |
| 日期事项及完成日期 | `checkin-occasions` | 否 |
| 自建问卷模板、问卷日记输出目标 | `journal.json` | 否 |
| 提醒延期、跳过等用户动作 | `checkin-reminder-actions` | 否 |
| AI 分析历史、建议工作流及其审计 | `agent-analysis-history.json`、`checkin-suggestion-workflow` | 否 |
| 专注入账诊断、番茄完成收件箱、外部失败待处理记录 | `checkin-focus-diagnostics`、`checkin-docktomato-inbox`、`checkin-external-pending` | 否 |

本次会话的保存失败等原因码另存在内存中，最多保留 20 条，会话结束后不能依赖它们继续排查。专注诊断与会话诊断是不同的数据，不要混同。

思源文档也是独立的数据位置：问卷日记、日报、摘要驻留、锚点绑定等可能在你选择的笔记本或文档内写入块。关闭联动、删除项目或卸载插件，不等于删除已经写进笔记的内容。

插件没有自建账号或自建同步服务。思源如何同步插件存储、工作区文档与 assets 文件，取决于宿主版本、同步配置和备份方式；“本地优先”不表示启用思源同步后这些数据永远只在一台设备上。

## 哪些操作会读取或发出数据

| 场景 | 数据流与用户控制 |
| --- | --- |
| 普通打卡、历史、统计、复盘 | 读取本地插件主档；基础使用无需 AI 或外部账号。插件代码没有新增遥测入口。 |
| 思阅、思播、番茄等跨插件联动 | 启用后通过约定的本地 API、事件或状态读取来源，换算成目标项目记录。来源插件本身的网络与隐私行为应查看其说明。 |
| 健康收件箱、笔记推导、叶归 LifeLog | 启用后读取你指定的本地文档、笔记本或固定查询结果。来源文档可能含健康、生活等个人信息；先选择最小必要范围。 |
| 微信读书 | 启用并填写 Key 后，经思源 `/api/network/forwardProxy` 向微信读书官方 Agent 网关请求阅读数据，鉴权头携带 Key；基础打卡不调用该网关。 |
| 日报、摘要驻留、问卷日记 | 写入你选定的思源文档或日记；文档后续同步、分享由思源设置决定。 |
| 宿主智能体能力 | 智能体可以请求项目、日期事项、统计上下文等，部分能力包含事项备注或写入结果；注册能力标明 `dataEgress`。宿主是否调用、使用哪个模型、发送到哪里由宿主配置和权限控制。 |
| 总结适配器 | 点击生成总结后，注册的提供方接收所选范围的项目副本、完整事件副本和统计上下文。事件可能含备注、图片附件及 `externalRef`；提供方是否转发外部模型由其实现决定。 |
| AI 提示词复制 | 回顾助理的“复制并打开智能体”复制范围和读取指令；周复盘的自足提示词会复制所选范围的事实摘要、项目摘要、阻力及下周调整草稿。复制本身不调用外部模型；粘贴到第三方服务后按该服务的数据规则处理。 |

同一工作区的其他插件可以调用公开的 `window.siyuanCheckin` API，其中 `getStore`、`getEvents` 等可能返回完整本地数据。该 API 不是逐插件授权的隐私沙箱；应只启用你信任的插件。日历投影等特定接口会省略备注、附件和外部身份，不能据此推断所有接口都脱敏。接口范围见[公开 API](api-v5.md)。

微信读书 Key 作为偏好字段保存，插件没有实现 Key 加密存储。它不进入打卡主档 JSON、主档恢复点或普通报告，但完整工作区备份可能含偏好桶。停用微信读书联动保留 Key；需要移除时在来源设置中使用“清除 Key”，该操作同时停用联动并保留项目绑定。清除本地 Key 不等于撤销微信读书端的凭据，也不会清理此前已有的备份副本。

## 导出与求助前检查

| 文件或操作 | 需要检查的内容 |
| --- | --- |
| JSON 主档、主档恢复点 | 项目名称、备注、图片附件、锚点关联、来源身份；恢复点可能保留旧内容。 |
| CSV 记录 | 项目名称、数值、单位、备注、来源和 `externalRef`；CSV 不包含图片附件内容。 |
| Markdown 报告、迁出文件、复盘提示词 | 项目名称、时间范围和统计事实；自足复盘提示词另外含你填写的草稿。它们不是匿名分享文件。 |
| 会话诊断 JSON | 原因码、时间、可选 `detail`；预览展示原因码计数和时间范围，不展示每条 detail 的全文。 |
| 数据审计、AI 建议审计、专注诊断 | 不同导出入口含不同上下文，不能把它们全部视作相同的脱敏日志。 |

主档导出会提示备注和图片数量，但该提示**不删除或模糊敏感内容**。诊断 `detail` 会限制长度，并遮罩常见 `token`/`apiKey`/`password`/`Authorization` 赋值和常见 Windows、用户目录绝对路径；这是一层有界规则，不是完整匿名化。公开发 issue 前仍应打开文件，移除不必要的备注、图片、项目名、文件路径、文档/来源身份和任何 Key；保留能定位问题的原因码、时间、客户端版本和操作步骤。需要实际数据复现时，优先使用自己构造的最小样例。

有原生保存桥的 Android、iOS、鸿蒙容器会先将导出内容写入工作区 `assets/siyuan-checkin-…` 文件，再请求系统保存。即使取消系统保存，工作区暂存文件也可能已经存在；插件当前不会自动清除这些文件。请在确认另存结果后按思源的附件管理方式检查和清理，工作区备份/同步也需考虑这些副本。提示“已写入 assets”证明的是工作区写入与保存请求，不能代替查看系统目录中的最终文件。

桌面或没有原生保存桥的浏览器走临时 Blob 下载，不通过该导出函数写入工作区；下载目录中的文件由你自行管理。

## 关闭、停用、删除与卸载有什么区别

| 操作 | 实际影响 |
| --- | --- |
| 关闭面板或弹窗 | 关闭展示入口，不等于关闭整个插件或停止后台来源。 |
| 停用某个来源 | 停止该来源后续采集；已经入账的记录及幂等身份保留。已写入的失败待处理记录也不是已确认事实，需到相应待处理入口单独检查。重连只按已有身份防重复，不保证补回所有停用期间数据。 |
| 归档项目 | 保留项目和记录，移出日常活跃列表；可以在归档页恢复。 |
| 删除记录或项目 | 按操作确认删除主档内容，并保留防旧设备重放的删除标记。旧恢复点、导出文件、文档副本和宿主备份不会因此一起消失。 |
| 清空本地恢复点 / 清空审计 | 只处理对应桶，不能当作清空当前打卡数据或全工作区痕迹。后续操作还可能生成新的恢复点或审计。 |
| 恢复默认视图 | 仅恢复分组、排序、折叠、当前筛选、分析项目选择与周视图显示。主档、来源绑定、Key、头像、周复盘草稿、保存视图，以及外观、语言和辅助功能偏好保留。 |
| 恢复全部显示偏好 | 恢复默认视图，并恢复主题、语言、动效、振动、默认打开方式、弹窗尺寸及位置、个人头像。保留来源绑定、Key、复盘草稿、保存视图、报告输出设置及主档；不会删除独立的自定义图标库或笔记内容。 |
| 在思源中禁用插件 | 拆除定时器、监听器与界面；停止运行。正在进行的专注会尝试结算，待写入队列会在宿主拆除时间预算内收尾；应先结束专注并确认保存成功。 |
| 从工作区卸载插件 | 先拆除运行实例，插件卸载钩子尽力清理已有锚点块的 `custom-lv-checkin` 属性；钩子自身不删除存储桶、笔记内容或 assets 导出文件。宿主安装管理器是否保留各类存储尚未按客户端验证，不能保证重装一定恢复。 |

如要彻底移除个人数据：先决定是否保留备份，再停用来源、结束专注、确认保存、卸载插件；随后分别检查插件存储、写入的思源笔记、assets 导出副本、系统下载、其他设备和同步/备份副本。当前没有经验证的“清除整个插件所有数据”单一入口，也没有跨客户端统一的物理清除步骤；需要时应按当前思源版本核对路径与保留策略。不要靠删除主档中的墓碑或手改活动存储来清理，否则旧窗口或设备可能重新带回记录。
