# 小驴打卡 × Task Horizon 日历可见性规划

更新时间：2026-09-22  
状态：**可行性与范围研究完成；仅登记开发计划，未修改运行代码、数据结构、公开 API 或 Task Horizon 机器契约。**

## 一、结论先行

这个需求可行，而且应该作为 Task Horizon 联动的下一层基础能力来做：

1. 新建打卡项目默认出现在 Task Horizon 的「打卡」日历图层。
2. 每个项目在编辑器高级设置中提供「在 Task Horizon 日历中显示」开关，默认开启。
3. 关闭后只撤掉 Task Horizon 的日历投影；小驴打卡自己的 Today、回顾、统计、导出、历史事件和本地提醒不受影响。
4. 日历隐藏不等于归档、删除或禁止外部回写。Task Horizon 完成任务是否写入某个打卡项目，仍由任务管理器的明确映射/用户授权决定；如果以后要限制写回，应新增独立开关，不能复用“日历显示”开关。
5. 日历显示应是“项目 × 日期”的只读投影，而不是把每条历史事件复制成 Task Horizon 原生任务。这样既能看见打卡内容，也不会制造重复任务、重复提醒和双重完成状态。

现有 P0 合作契约已经证明“读摘要 + 任务完成回写”方向可行，但还不能满足项目级隐藏：

- `getEventRangeSummary()` 只按本地日期聚合所有事件，没有项目维度或可见性过滤；
- `queryItems()` 没有外部日历可见性选项；
- `CheckinItem` 没有 Task Horizon 日历显示字段；
- 当前 bridge 用 `getItems()` 找回写目标、用 `getEventRangeSummary()` 刷新图层，因此只增加一个 UI checkbox 而不改读投影，隐藏会在日历端失效。

## 二、现有证据与缺口

### 已有可复用能力

| 现有能力 | 证据 | 对本需求的作用 |
| --- | --- | --- |
| 公共 facade 与能力协商 | `window.siyuanCheckin`、`whenReady()`、`hasCapability()`、`describe()` | Task Horizon 可在插件缺失、未就绪或版本不兼容时降级 |
| 项目查询 | `items.read` / `items.query`、`queryItems()` | 提供项目名称、类型、排期、单位和未来可见性字段 |
| 有界日期读取 | `events.range.read`、`getEventsInRange()` | 读取指定本地日期范围，不从 UTC 时间戳推导日期 |
| 日期摘要 | `analytics.read`、`getEventRangeSummary()` | 现有聚合图层可继续兼容；不能独立完成项目级隐藏 |
| 刷新事件 | `checkin:event-recorded`、`checkin:analytics-updated`、`checkin:item-archived`、`checkin:item-updated` | 项目开关变化可经 `item-updated` 触发日历重读，无需轮询 |
| 外部回写 | `recordEvent()` + `taskhorizon:<blockId>:<localDate>` | 任务完成回写已有幂等身份和墓碑语义，不应被日历显示开关悄悄改变 |

### 当前必须补齐的能力

1. **项目级显示策略**：新增一个可迁移、默认显示的字段；旧数据缺失字段时必须视为 `true`。
2. **不泄露私有事件的日历投影**：Task Horizon 不应为了过滤项目而读取备注、附件和完整外部身份；需要新增有界的项目/日期摘要投影，或在双方契约中明确最小组合方式。
3. **状态口径**：排期、配额、`SKIP`、`atMost`、归档、历史事件必须由小驴侧给出稳定语义，不能让 Task Horizon 自己重算一套“完成率”。
4. **旧消费者的安全降级**：旧版 Task Horizon 只懂 v1 聚合摘要时，不能假装支持项目级隐藏；应明确标记为 legacy projection，或在新能力未协商成功时不启用该细粒度图层。
5. **跨日回写边界**：当前单条 `recordEvent()` 由小驴侧捕获调用时刻，`externalRef` 中的 `localDate` 主要用于身份校验；Task Horizon 若允许补录历史日期，双方需要在新契约中锁定 `occurredAt`/本地日期的来源，不能只依赖当前时刻。

本轮只对小驴仓库中已经公开的 facade、机器契约、bridge 示例和测试取证；没有把 Task Horizon 的私有源码、内部块结构或未公开 API 当作实现依据。真正的日历渲染、原生任务发现和用户映射仍属于对方消费端，须在双方公开契约和真实宿主联调时补证。

## 三、推荐用户语义

### 1. “显示”只管日历显示

推荐字段名：`taskHorizonCalendarVisible?: boolean`。

- `undefined` 或 `true`：显示；这样旧数据无需批量迁移，默认行为保持“全部显示”。
- `false`：不进入 Task Horizon 的「打卡」日历投影。
- 字段只表达 Task Horizon 日历展示策略，不表达数据删除、项目生命周期或任务回写权限。
- 如果未来出现第二个任务/日历消费方，再拆成通用 integration namespace；当前不为尚未存在的消费者预埋一组复杂配置。

### 2. 隐藏与其他状态分离

| 状态 | Task Horizon 日历 | 小驴本地项目/事件 | 任务完成回写 |
| --- | --- | --- | --- |
| 可见、未归档 | 显示符合排期的项目/日期摘要 | 正常 | 按独立映射和用户授权执行 |
| 日历隐藏 | 不显示项目及其日期摘要 | 完整保留 | 不因隐藏自动拒绝；仍以明确映射为准 |
| 归档 | 沿用现有 `archived` 生命周期语义；不产生新的未来日历条目 | 项目和历史保留，可恢复 | 继续按现有归档/阻塞语义处理 |
| 删除 | 日历项消失；历史事件按现有删除/墓碑语义处理 | 现有级联删除语义不变 | 旧回调不能复活数据 |
| 恢复/重新显示 | 按当前日期、排期和可见性重新投影 | 本地数据不变 | 不生成额外事件 |

明确禁止把“隐藏”实现为：删除项目、归档项目、从 `getItems()` 全局消失、清空历史事件、停止所有 `recordEvent()` 写入，或在 Task Horizon 端用 CSS/缓存假隐藏。

### 3. 日历显示什么

MVP 采用“项目 × 日期”的只读投影：

- Task Horizon 日历有一个「小驴打卡」图层；图层内可按项目查看当天状态，月视图可再折叠为日期聚合徽章。
- 不把每条历史事件渲染成独立任务，不把打卡项目复制成可编辑的 Task Horizon 原生复选框。
- 只显示 `taskHorizonCalendarVisible !== false` 且未归档的项目；归档和恢复仍由小驴生命周期控制。
- 只在项目对该本地日期有效/有排期时生成计划摘要；非排期日不伪造“未完成任务”。
- 当天状态由小驴侧统一计算并返回：`pending`、`complete`、`skipped`、`at-most-safe`、`at-most-breach` 等；Task Horizon 只负责呈现。
- `SKIP` 是中性状态，不渲染成失败；`atMost` 无事件的“守住”与发生事件的“破戒”不能套普通至少型完成率。
- 周/月配额以“周期进度 + 当天是否贡献”表达，不拆成 N 个伪任务；数值/单位沿用项目当前日期修订。
- 日期归属只使用事件 `localDate` 和本地排期，不用 UTC `occurredAt` 重新推导，避免跨时区倒日。

这样处理可以同时满足“默认都显示”和“单项关闭后不显示”，又不会让任务管理器与小驴各自计算出不同的完成口径。

## 四、推荐数据流与 API 方向

### 读取（日历图层）

1. Task Horizon 探测 `window.siyuanCheckin`，等待 `whenReady()`，协商基础只读能力与新的日历投影能力。
2. 小驴侧只返回有界、只读、无备注/附件/私有存储字段的日历投影。服务端按 `taskHorizonCalendarVisible !== false` 过滤隐藏项目，不能让消费者先读全量再靠 UI 过滤。
3. 投影按 `[startDate, endDateExclusive)` 返回项目摘要和日期状态，并附 `truncated`/限制信息；范围、项目数和日期点均有限制。
4. Task Horizon 缓存当前范围；收到既有四类刷新事件后取消旧请求、合并刷新并重读。`item-updated` 覆盖显示开关变化，`item-archived` 覆盖生命周期变化。
5. 投影不可用、超时、能力缺失或版本不兼容时，图层进入可诊断的 `unavailable/degraded`，不显示陈旧的全量内容，也不影响小驴本地使用。

首选 API 方向是新增一个**通用只读 `calendar.read` 能力及有界 `getCalendarProjection()`**，而不是让 Task Horizon 复制排期、配额、跳过和负向习惯算法。具体字段和上限在 T-1389/T-1391 的双方契约评审中冻结。若双方决定暂不增加新能力，最低可行退路是：`queryItems()` 返回可见性字段，`getEventsInRange()` 只读取可见项目并由消费方按文档口径聚合；这只能作为兼容/实验路径，不能替代长期投影契约。

### 写入（任务完成 → 打卡）

- 继续使用 `recordEvent()` 和 `taskhorizon:<blockId>:<localDate>`，重复回放仍返回已有事件而不新增。
- 日历隐藏默认不影响写回；Task Horizon 只有在用户明确选择目标项目后才可写入。
- 如果未来需要“项目可以显示，但不允许任务完成回写”或“隐藏日历且禁止回写”，新增独立 `taskHorizonWriteBackEnabled`（或等价设置）并走单独契约，不把两个动作绑在一个 checkbox 上。
- 补录历史日期、跨午夜、多个窗口同时完成、任务被撤销/重新勾选等情况，必须先冻结日期与撤销语义，再扩展 bridge；不能用随机 externalRef 或当前时刻猜测历史归属。

### 上游公开 API 协同（T-1395，双轨保障）

如果 Task Horizon 消费端缺少 `calendar.read`、投影刷新、能力降级或任务回写所需的公开入口，不能通过读取私有块、私有存储、DOM、缓存或未公开函数来“补齐”。应准备对方消费端的最小 API/bridge issue 或 PR 方案，并同时保留小驴侧的能力探测、兼容 fallback 和可诊断降级。

上游提案至少要有版本/能力发现、输入输出与刷新时序、旧版 fallback、contract fixture、最小示例、桌面/移动/多窗口/热重载验收和隐私说明。API 合并、版本发布、真实思源宿主验收必须分别通过后，才能把它作为稳定主路径；在此之前最多进入实验/仅观察模式，不默认写入或显示陈旧全量内容。若上游 API 与本地 fallback 同时存在，必须指定唯一 canonical source，使用 `source + externalRef` 幂等，不能把两路同一任务结果重复累计。

当前不修改 Task Horizon 仓库或提交外部 PR；只在本地准备契约草案、bridge 示例和测试夹具，待维护者入口、版本基线和用户授权明确后再决定是否发出。

## 五、边界与可行性判断

| 场景 | 推荐处理 | 可行性 |
| --- | --- | --- |
| 新建项目 | 缺省显示；不写 `false` 之外的冗余字段 | 高 |
| 编辑器关闭显示 | 立即保存项目级字段，广播 `item-updated`，Task Horizon 下次刷新消失 | 高 |
| 再次打开显示 | 重新按当前范围投影；不补写历史事件 | 高 |
| 今日无排期 | 不生成计划项；若有真实历史记录，按历史投影规则处理 | 高，需契约锁口径 |
| 周/月配额 | 返回周期进度与当天贡献，不拆成多个伪任务 | 中高，需单一计算入口 |
| `SKIP` | 中性状态，不当作失败或完成 | 高 |
| `atMost` | “守住/破戒”专用状态，不套至少型百分比 | 高 |
| 归档/恢复 | 沿用生命周期，不复用隐藏字段 | 高 |
| 删除与旧回调 | 现有事件墓碑优先，不能复活 | 高 |
| 多窗口 | 存储锁与 `item-updated`/数据重读收敛；不可只依赖窗口内缓存 | 中高，需真实宿主 |
| Task Horizon 未安装/未加载 | 本地功能完整，图层降级隐藏 | 高 |
| 跨时区/夏令时 | 以 `localDate` 和本地排期为准，不从 UTC 反推 | 高 |
| 旧 v1 消费方 | 不宣称支持项目级隐藏；能力协商失败时不显示细粒度图层 | 中，取决于对方升级 |

## 六、明确不做

- 不修改思源内核，不读取 Task Horizon 私有块、私有存储、DOM 或未公开函数。
- 不把小驴项目批量写成 Task Horizon 原生任务，不制造第二份任务主数据。
- 不因隐藏而删除小驴项目、事件、历史、统计或导出。
- 不用归档字段代替日历可见性，不用全局设置代替项目级控制。
- 不在没有双方公开契约和真实宿主证据时新增轮询、随机同步、后台自动回写或跨窗口猜测。
- 不修改当前 `task-horizon-v1.json` 机器契约来“提前宣称”新能力；新投影必须在双方评审后新增版本/能力并同步 manifest、文档和 contract test。
- 不把 issue/PR 草案、上游合并或本地 fallback 当作已发布、已验证的 Task Horizon 契约；当前不创建或提交真实外部 PR。

## 八、验收门槛

实现批次必须至少证明：

1. 新建项目默认出现在 Task Horizon 日历；旧项目升级后也保持显示。
2. 只关闭一个项目后，该项目从日历投影消失，其他项目不受影响；重新开启后按当前范围恢复。
3. 小驴 Today、回顾、统计、导出、历史事件和本地提醒与开关无关。
4. 隐藏不会删除历史事件，也不会通过旧缓存重新出现；归档/删除/恢复不误用隐藏字段。
5. `SKIP`、`atMost`、quota、修订生效日、跨月/跨年、夏令时和本地日期口径与小驴一致。
6. Task Horizon 任务回写仍按显式映射、稳定 `externalRef`、幂等和墓碑处理；隐藏开关不会静默改变写回语义。
7. 插件缺失、加载顺序反转、API 不兼容、超时、双窗口和热重载均可诊断并降级，不阻断小驴核心。
8. 自动化测试、真实思源桌面/页签/dock/Android、多窗口联调证据分开记录；浏览器假宿主不能代替现场验收。
