# 小驴打卡移动端 UI 研究储备

研究日期：2026-09-06

本文把优秀习惯应用在手机端已经验证的机制，转译为小驴打卡可以逐步实现的方案。参考对象包括 [Loop Habit Tracker](https://github.com/iSoron/uhabits)、[Streaks](https://streaksapp.com/)、[Habitify Journal](https://intercom.help/habitify-app/en/articles/12520095-understanding-your-journal-view) 和 [Daylio](https://apps.apple.com/us/app/daylio-daily-life-tracker/id6760725710)。

## 研究结论

手机端最重要的不是把桌面页面压窄，而是让“今天要做什么”和“完成一次”始终处在拇指可达区域。优秀产品普遍把当天计划作为唯一主列表，利用时间段或自定义区域过滤，完成后立即移动到已完成区，并保留补记、撤销或追加记录的入口。

小驴打卡应吸收这些低成本机制：今日页单屏聚焦、模板快速开始、分组筛选、进度可解释、完成后可撤销、数量/时长使用真实单位。连续天数、游戏积分、社交排行和强制提醒会增加压力，不作为移动端默认交互。

## 产品对照

| 产品 | 手机端优点 | 潜在问题 | 小驴打卡可借鉴 |
| --- | --- | --- | --- |
| Loop Habit Tracker | 开源、离线、轻量；支持每日、每周次数和间隔计划；通知可直接完成；图表与 CSV/SQLite 导出完整 | 强度分数公式需要解释；信息量增加后详情页容易变重 | 今日页只显示当日计划；把周期配额和间隔规则交给规则引擎；保持本地优先与可导出 |
| Streaks | 大图标和强对比色让完成动作非常直接；支持固定星期、每周次数；Apple Watch 和小组件缩短记录路径 | 以连续不断链为核心，缺席容易产生压力；任务数量有限 | 保留大触控目标和清晰完成状态；不把连续天数作为唯一评价；移动端可预留小组件/API 入口 |
| Habitify | Journal 按晨间/午后/晚间和自定义 Area 过滤；主列表只展示今天；重复规则按 Weekly、Interval、Monthly 分开；完成后仍可 Log 额外努力 | 功能层级较多，设置页容易变长；提醒和跨平台能力依赖账号/服务 | 采用顶部可横向滚动的分组筛选；编辑页用分步设置；完成项目保留“追加记录”入口 |
| Daylio | 两步记录、日历与列表结合；备注和上下文让统计更可解释 | 心情、标签、照片、语音等功能容易造成输入负担 | 备注作为可选项，不阻塞完成；历史页支持从日期进入当天事件明细 |

## 移动端交互规范

### 今日页

- 首屏只保留日期、完成进度、今日计划和新建入口。
- 核心动作触控区域至少 44×44px；卡片的图标、完成按钮和数量输入不能挤在同一小块区域。
- 二元项目点击一次完成；数量/时长项目提供预设增量和自定义数值，避免每次打开编辑器。
- 记录成功后显示短时撤销条，撤销只删除最近一次事件；完成项目移动到末段并保留追加记录入口。
- 分组采用横向筛选条或可折叠区，优先显示“全部、晨间、午后、晚间、自定义组”。筛选状态不应改变数据，只改变视图。
- 搜索输入使用 `type=search`，提供清除按钮，键盘打开时列表仍可滚动到输入框。

### 新建与编辑

- 新建先展示模板，模板卡片直接显示图标、名称、目标和频率；选择模板后只需修改名称或目标即可保存。
- 将名称、类型、目标作为首屏字段；分组、重要性、时间段、频率等放在“更多设置”中渐进展开。
- 类型选择必须改变目标标签、单位、步长和示例，不允许“按时长”和“按数量”仍显示同样的“次”。
- 保存按钮固定在底部安全区上方，使用 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`；软键盘打开时避免遮住输入框。
- 图标选择使用分组、搜索和最近使用，网格按钮至少 44px；不依赖远程图标服务。

### 导航与系统行为

- mobile/browser-mobile 不显示桌面页签入口；页面返回优先回到今日页，编辑页返回前保留未保存表单提示。
- 内容容器使用 `min-height: 100dvh`，同时兼容 `100vh`；滚动只发生在插件内容区，避免与思源外层滚动互相抢手势。
- 顶部和底部按钮避开刘海与手势条：使用 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。
- 深色模式不只反转背景；进度、重要性标签、错误提示和完成状态要保持足够对比度。

## 可直接复用的代码模式

### 安全区与动态视口

```scss
.lc-checkin {
    min-height: 100vh;
    min-height: 100dvh;
    padding-top: calc(16px + env(safe-area-inset-top));
    padding-bottom: calc(16px + env(safe-area-inset-bottom));
}
```

### 移动端触控尺寸

```scss
@media (hover: none), (pointer: coarse) {
    .lc-checkin button,
    .lc-checkin input,
    .lc-checkin select {
        min-height: 44px;
    }

    .lc-checkin__small-button {
        width: 44px;
        height: 44px;
        opacity: 1;
    }
}
```

### 键盘打开时滚动到焦点

```ts
input.addEventListener("focus", () => {
    window.setTimeout(() => input.scrollIntoView({block: "center", behavior: "smooth"}), 80);
});
```

### 可逆记录反馈

记录事件成功后暂存事件 ID 和项目名称，在 4 到 6 秒内显示撤销条。撤销动作调用现有 `removeEvents`，不能直接改数组或覆盖历史数据。

## 实施优先级

1. 移动端壳层、安全区、动态视口和 44px 触控目标。
2. 今日页快捷记录、完成项移动、撤销条和分组筛选。
3. 新建/编辑页模板优先、渐进字段和固定保存栏。
4. 移动端历史日历、事件详情和备注入口。
5. 小组件、系统快捷指令和提醒适配；完成稳定事件 API 后再做。

## 验收清单

- 320px 宽度下项目名称、单位、进度和操作按钮不重叠。
- 软键盘打开时，名称、目标、单位和分组输入都能滚动到可见区域。
- 触控设备上设置、返回、分组和清除按钮始终可发现，不依赖 hover。
- 完成一项后，卡片进入已完成区；撤销后恢复原位置和进度。
- 深色模式下完成、重要、错误和禁用状态仍能区分。
- 打开 mobile 与 desktop 两种前端时，不出现页签入口或容器高度溢出。
