## 铁律与坑（全部踩过，勿再踩）

1. **Mimosa 安全钩子**：用 Bash 直接写 `src/**` 或 `package.json` 会被拦——必须用 Edit/Write 工具。`.exec(` 等字样也可能误报（改用 `.match(`）。
2. **Bash heredoc/node -e 写文件会因反引号转义损坏内容**（多次踩）——一律用 Edit/Write。
3. **测试加载器同步**：改 `view-preferences.ts` 的 import 或 `model.ts` 依赖时，10+ 个测试文件的转译清单要同步（grep `view-preferences` tests/ 找全）；新来源适配器归一尽量**内联进 view-preferences**（sireader/yeguif 模式）避免级联。
4. **新外部来源 checklist**：types source 联合 → ecosystem 前缀注册表 → model 两处白名单 → api.ts 防伪造回落 → 日报 sources 列表 → review 过滤器+knownSources → history-filter/insight-records 标签 → privacy 控制面 → 架构守门 SOURCE_MANIFEST+CLOCK_FREE → 设置面板+守门 → i18n 双语（兄弟适配器测试的防伪造断言要同步更新）。
5. **assert 参数顺序**：`assert.ok(x >= n, "msg")` 不是 `assert.equal(x >= n, "msg")`；正则断言转译产物时注意花括号内空格。
6. **SiYuan 写后索引异步重建**：SQL 查询刚写的内容要用轮询（e2e 已知坑）。
7. **发版流程**：`node scripts/release.cjs <version> "标题"`——前置=工作区干净；**README「当前版本」声明必须先同步新版本号**（release-assets 守门会拦）；发布说明 SHA-256 行由脚本回填；gh 提交 push+tag+Release 一气呵成。
8. **文档真值同步**：每批交付后 TODO（勾选+状态行含提交号）+ PROGRESS（prepend）+ 相关文档（api-v5 前缀清单/证据报告/benchmark）当场更新——账本滞后是 R-A0 泳道要防的头号漂移。
9. commit 用英文多行 message（feat/fix/docs + 任务号），不 push（除非用户明示发版/推送）。
