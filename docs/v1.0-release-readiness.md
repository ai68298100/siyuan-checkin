## 发布前必须补齐

1. 在真实思源浏览器环境完成侧栏、弹窗、页签和移动宽度的截图验证，并记录思源版本、浏览器、窗口尺寸和结果。结构测试只能作为辅助证据。
2. 执行 `pnpm test`、`pnpm run test:mobile:visual`、`pnpm run check:release` 和 `pnpm run build`，保存命令输出和 `package.zip` 的 SHA-256。
3. 使用旧版本数据完成一次升级安装，检查模板、事项、事件、删除标记和外部引用去重；再安装回滚版本确认数据仍可读取。
4. 发布前同步 `README.md`、变更记录、迁移说明和 `docs/release-rollback.md`，并确认 `package.json`、`plugin.json`、压缩包和 Release 标签使用同一版本号。

## 阻塞记录格式

每个未通过项记录：检查日期、环境、复现步骤、影响范围、临时规避方式、负责人和重新验证结果。没有真实浏览器证据的项目标记为“待验证”，不能标记为“通过”。
