# 设置页与外部联动梳理（2026-09-25）

## 结论

原设置页把外部来源、宿主能力、数据恢复和自定义图标放在同一个「集成」组里。用户需要先理解实现边界，才能知道某个开关是在接收外部事件、读取外部数据，还是把小驴打卡写到思源文档。此次调整采用两层结构：

- 「外部联动」只放真正的来源与文档写入：日记报告、摘要驻留、思阅、健康收件箱、思播、微信读书、叶归 LifeLog。
- 「宿主与插件」放提供方或能力注册：Dock Tomato、思源 Agent、Task Horizon。它们的状态不能被误读成某个来源已经连通。

外部联动卡片统一显示三种本地配置状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待配置 | 缺少目标项目、文档、笔记本、Key 或指标映射 | 先完成卡片里的配置 |
| 已配置，待启用 | 本地配置完整，但仍是 opt-in 关闭 | 确认数据方向后打开开关 |
| 已启用 | 本地配置完整且已打开开关 | 查看今日计数或最近结果 |

这个状态只说明本地设置完整度，不冒充上游插件已安装、事件已到达或网络请求成功。每张卡片另外说明数据流、触发方式、隐私边界和停用后的保留规则。保存或开关重绘后，当前展开的卡片会保留，设置顺序按「绑定目标 → 保存策略 → 启用 → 验证」排列。

## 设置页分组

| 分组 | 内容 | 判断依据 |
| --- | --- | --- |
| 外观与交互 | 主题、语言、动效、触感、强调色、头像和自定义图标计数 | 只改变本插件表面 |
| 今日与提醒 | 分组、排序、完成项、周条、安静时段、每日提醒 | 只改变本地工作台行为 |
| 对话框 | 尺寸、缩放和固定尺寸 | 只改变容器布局 |
| 快捷键 | 打开、快速记录、排序 | 本地操作入口 |
| 数据与恢复 | 导入导出、快照、诊断、审计、恢复和重置 | 数据生命周期，不是联动配置 |
| 宿主与插件 | Dock Tomato、思源 Agent、Task Horizon 能力状态 | 外部能力提供或消费契约 |
| 外部联动 | 七个外部来源和文档写入目标 | 读入、写出或转换外部事实 |
| 关于 | 版本与主页 | 项目元信息 |

## 宿主与插件能力

### Dock Tomato

1. **方向和入口**：小驴打卡调用 Dock Tomato 的公开 focus 能力启动专注；完成事件回到小驴后，按实际投入时长写入本地事件。设置页的默认提供方选择、诊断状态、完成异常和待回写收件箱都在「宿主与插件」中。
2. **设置过程**：先安装兼容版本并确认公开 API 状态为 ready，再把默认专注提供方切到 Dock Tomato。具体项目的专注入口会继续做项目类型、当天修订和会话身份校验；缺少提供方能力时，设置页给出切回内置计时的入口。
3. **验证和失败**：状态分为缺失、版本不兼容、能力不完整、加载中、就绪、运行、暂停和错误；完成事件缺字段、项目归档、跳过日或写入失败会进入异常/收件箱，不静默改记为成功。
4. **隐私与断开**：只走公开桥接和已有本地事件通道，不读取 Dock Tomato 私有存储。停用或解绑只停止后续接收，已经确认落盘的事件和 `docktomato:<sessionId>` 幂等身份保留。

### 思源 Agent

1. **方向和入口**：`addAgentCapability` 注册小驴打卡的公开能力，Agent 可以调用工具；小驴不会反向调用模型，也不保存模型 Key。
2. **设置过程**：不需要用户填写来源目标；只展示能力注册状态、已注册能力数量、失败原因和建议工作流审计入口。
3. **验证和失败**：`pending / registered / unsupported / failed` 只描述宿主能力注册，不表示任何外部来源已启用。注册失败时保留本地打卡和手动回顾路径。
4. **隐私与断开**：建议文本和审计留在本地；导出审计前仍遵循数据导出敏感字段提示。

### Task Horizon

1. **方向和入口**：当前小驴打卡只提供 Task Horizon 可消费的公开契约和投影能力，不主动声称已经连上消费方。
2. **设置过程**：不新增虚假的连接开关；卡片显示「API 已提供 · 未检测到消费方」以及契约就绪说明。
3. **验证和失败**：`data-dependency-state="healthy"` 表示本插件的 provider contract 已就绪，不表示 Task Horizon 消费端握手成功。真正的消费端联调、刷新时序和现场验收仍属于外部任务。
4. **隐私与断开**：本地项目和事件仍由小驴掌握；没有消费方时不复制任务、不写外部任务。

## 外部来源与文档写入

### 日记报告

1. **数据流**：小驴打卡 → 用户指定的思源文档。写入的是当前报告 Markdown，不读取第三方私有存储。
2. **设置过程**：在卡片中搜索或选择已有块，或选择笔记本后创建文档；保存合法块 ID；确认报告目标后打开开关；用「立即写入」验证一次。写入失败走有界重试并记录审计。
3. **触发与幂等**：当前入口是用户手动写入周期报告，不建立常驻定时器；报告内容沿用回顾报告口径。
4. **隐私与断开**：文档内容由用户持有；停用只停止后续追加，不删除已经写入的报告。

### 摘要驻留

1. **数据流**：一次本地打卡完成 → 目标摘要文档追加一行 → 外部工具可通过思源公开读接口读取。
2. **设置过程**：填写并保存目标文档 ID；确认白名单字段后打开开关；用「立即写入今日摘要」验证。开关置于文档配置之后，避免先打开一个没有目标的空联动。
3. **内容和幂等**：只写日期、完成/计划数、记录数和来源计数；写入前按文档、日期和标记查询，命中则跳过。没有常驻轮询任务。
4. **隐私与断开**：不写备注、照片、事件明细或 externalRef；停用后摘要文档和既有行保留。

### 思阅阅读

1. **数据流**：思阅公开生命周期事件 `reader:open/focus/blur/close` → 小驴按本地墙上时间累计有效阅读分钟 → 达到阈值后写入绑定项目。
2. **设置过程**：选择目标项目；设置每日阈值（1–1440 分钟）；保存阈值；确认来源边界后打开开关。开关放在项目和阈值之后。
3. **触发与幂等**：没有公开事件就不产生数据；跨午夜按本地日切分；每日以 `sireader:<itemId>:<localDate>` 只写一次；重载时丢弃未完成区间，宁少记不补猜。
4. **隐私与断开**：只监听公开生命周期，不读取思阅统计文件或私有数据库。停用停止监听，已经落盘的事件和幂等身份保留；上游事件版本化仍待提案合并和真实宿主验证。

### 健康数据收件箱

1. **数据流**：iOS 快捷指令或用户脚本 → 思源收件箱文档 → 小驴严格解析 → 步数/体重目标项目。
2. **设置过程**：先保存收件箱文档 ID；分别绑定步数和体重项目（至少绑定一个）；检查项目单位；最后打开开关。没有文档或指标映射时，开关会拒绝启用并给出对应原因。
3. **触发与幂等**：插件每 5 分钟轮询一次，保存设置后立即尝试摄取；只接受 `health:steps:YYYY-MM-DD value` 和 `health:weight:YYYY-MM-DD value`；同一项目、指标和日期只入账一次。
4. **隐私与断开**：插件只读指定文档中严格匹配的行，不读取其他健康数据，也不改写收件箱；停用后文档、行和已落盘事件保留。

### 思播观看（实验）

1. **数据流**：思播公开 controller 的 `isPlaying()` → 小驴每 15 秒采样在播墙上时间 → 达到阈值后写入目标项目。
2. **设置过程**：选择目标项目；设置每日阈值（1–1440 分钟）；保存；确认「实验、默认关闭」后再启用。
3. **触发与幂等**：只累计在播墙上时间，不使用不可靠的播放位置差值；跨午夜切分；每日以 `siplayer:<itemId>:<localDate>` 只写一次。找不到 controller 时保持不动作。
4. **隐私与断开**：不读取标题、路径或私有播放库。停用停止采样，已有事件保留；上游公开事件/能力协商和真实播放时序仍是现场验收项。

### 微信读书

1. **数据流**：微信读书官方 Agent API → 思源内核公开转发 → 小驴本地结算。三条链路独立：阅读时长、完读事件、前一日新增笔记计数，可以绑定不同项目。
2. **设置过程**：选择时长目标项目；按需选择完读和笔记项目；粘贴并保存 `wrk-` Key；设置阈值；打开开关；点击「立即拉取」验证。已保存 Key 只显示占位状态，新增「清除 Key」会确认后清空并停用联动，同时保留项目绑定。
3. **触发与幂等**：立即拉取或每 30 分钟轮询；时长、完读和笔记各用独立 externalRef，每日/每本书只写一次；Key 无效时显示最近拉取错误，不伪造成功。
4. **隐私与断开**：Key 只在本地偏好，不能导出或写入思源；请求只读官方数据，不回写微信读书。停用或清除 Key 不删除既有事件和幂等身份。

### 叶归 LifeLog

1. **数据流**：指定笔记本内当日新建的日记段落 → 行首时间 Marker（例如 `12:00 工作：写日报`）→ 相邻 Marker 的时间差 → 目标项目。
2. **设置过程**：选择目标项目；加载并选择日记笔记本；确认读取范围后打开开关。目标项目下拉使用同一份当前项目列表，已选值会保留。
3. **触发与幂等**：插件每 5 分钟读取指定笔记本的当日新块；每份文档按相邻 Marker 结算，最后一个开放 Marker 不计时；用 `yeguif:<blockId>:<localDate>` 防重复。
4. **隐私与断开**：只读用户指定笔记本的块内容，不读取叶归私有存储；停用停止轮询，既有事件和幂等身份保留。真实叶归插件与 Android/桌面现场摄取仍需用户工作区验证。

## 验收边界与后续

本轮自动验收覆盖设置 HTML 结构、双语键、状态分桶、叶归已选值、健康前置校验、微信读书 Key 清除入口、来源卡片展开状态保留和 CSS marker。浏览器视觉走查只能证明插件假宿主中的布局；它不能替代思源桌面、页签、dock、Android WebView 的触摸/安全区，也不能替代思阅、思播、Dock Tomato、Task Horizon 或微信读书的真实双插件时序。现场证据继续按交接文档的 `host-pending` 与 `external` 分类保留。
