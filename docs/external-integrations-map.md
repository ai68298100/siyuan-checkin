# 外部联动逻辑总账

> 目标：把“小驴打卡与外部发生关系”的能力按真实数据流分类，明确每个联动的触发、身份、隐私、失败方式和应提供的用户功能。运行时事实以源码、公开 API 契约和各专项文档为准；本文负责产品层总览。

## 一、先分清五种联动

外部联动不是同一种“同步”。当前能力应分为五类：

| 类别 | 数据方向 | 当前来源 | 核心风险 | 合适的产品功能 |
| --- | --- | --- | --- | --- |
| 插件事件监听 | 外部插件 -> 小驴 | 思阅、思播 | 宿主缺失、生命周期不完整、重复计时 | 宿主探测、今日累计、启停；不提供伪造的“全量同步” |
| 官方服务拉取 | 官方服务 -> 小驴 | 微信读书 | Key、网络、窗口上限、历史重建 | 立即拉取、最近结果、分指标绑定、Key 管理、窗口说明 |
| 用户文档摄取 | 思源文档 -> 小驴 | 健康收件箱、叶归 LifeLog、笔记推导 | 目标丢失、格式不匹配、窗口截断、重绑重放 | 目标体检、立即读取、格式预览、上限提示、重绑风险说明 |
| 外部消费/写入 API | 双向契约 | Task Horizon、Dock Tomato、脚本/其他插件 | 协议不兼容、幂等失败、消费方重试 | 能力协商、契约示例、诊断、稳定错误码；不在设置页伪装成本地开关 |
| 文档输出 | 小驴 -> 思源文档/外部读取方 | 日记报告、摘要驻留、问卷写入、笔记锚点 | 覆盖用户内容、旁路失败、敏感文本泄露 | 目标选择、预览/手动写入、审计与重试；事件事实不因文档写入失败回滚 |

共同底线：自动摄取默认关闭；所有外部记录经统一写入边界；同一外部事实使用稳定 `externalRef` 幂等；撤销写墓碑，停用或重绑不删除历史；不得读取其他插件私有存储或臆造未公开 API。

## 二、逐项逻辑与功能边界

| 联动 | 真实逻辑 | 身份与口径 | 失败/停用后的行为 | 应提供的功能 |
| --- | --- | --- | --- | --- |
| 思阅 | 监听公开阅读器 open/focus/blur/close 生命周期，在窗口可见且阅读器聚焦时按焦点片段写入实际整分钟；同日 20 分钟和 15 分钟是两条记录 | 新身份 `sireader:<itemId>:<开始时间的 Unix 毫秒>:<localDate>`；旧日和分钟桶身份仍可读；分钟项目 | 宿主未加载时不累计；停用丢弃未完成片段，已写记录保留 | 宿主状态、今日分钟、目标项目、启停、公开契约说明；不要提供“导入思阅历史” |
| 思播 | 实验性读取公开 controller 的播放状态并采样有效墙上时间；播放段结束后按该段实际整分钟写入，不读取播放器内部对象或私有存储 | 新身份 `siplayer:<itemId>:<播放段开始时间的 Unix 毫秒>:<localDate>`；旧日和分钟桶身份仍可读；分钟项目 | 控制器缺失或 `isPlaying()` 不可用时静默不写；历史保留 | 明确“实验”、宿主探测、今日分钟和启停；在上游事件契约稳定前不升级为稳定同步 |
| 微信读书 | 经思源内核 `forwardProxy` 调官方 Agent API；分别摄取阅读分钟、完读、前一日划线/笔记计数 | `weread:` 家族身份；时长近 62 天、完读每轮核实至多 10 本、笔记每轮有界；各指标独立项目 | 断网不破坏本地数据；Key 只存本地偏好；重绑可能让窗口内历史按新项目重建 | Key 保存/清除、三个指标独立绑定、立即拉取、最近成功/失败、查询上限与重绑提示 |
| 健康收件箱 | 快捷指令向专用文档追加严格文本；插件前台每 5 分钟按块窗口读取 `steps/weight` | `health:<itemId>:<metric>:<localDate>`；同指标可映射多个项目；步数/体重单位严格校验 | 非法行忽略；单轮最多 500 行；目标或单位失效时不写；历史事件保留 | 文档目标体检、指标映射、立即读取、格式样例、窗口占用/截断提示；暂不提供任意指标名 |
| 叶归 LifeLog | 只读绑定笔记本的当日日记 Marker；上一条到当前条的时间差归入当前 Marker 项目 | `yeguif:<blockId>:<localDate>`；第一条和同分钟不记；目标必须为分钟 | 单轮最多 200 块；有显式映射时未命中项目跳过；无映射时仅唯一同名匹配；不读叶归私有 petal 数据 | 笔记本体检、项目映射、立即读取、解析预览/跳过原因、窗口提示；不要提供历史全量回补 |
| 笔记推导 | 在用户绑定的单一文档或笔记本内执行固定只读 SQL 模板，识别显式 frontmatter/tag | `notequery:<itemId>:<blockId>:<localDate>`；同日手动记录优先；最多 200 行 | 非法字段、目标、日期或标记 fail-closed；不得悄悄替换成默认查询；不写回笔记 | 模板、范围、目标项目、立即读取、匹配预览/跳过原因；不开放任意 SQL 或自然语言猜测 |
| 外部失败待处理箱（T-1509） | 上述来源经 `recordExternalEvent` 写入遇到可重试存储失败（persist 抛错）时，最少字段持久化到独立有界箱（容量 40、保留 14 天，D-293）；配置拒绝不入箱 | 身份 = source+itemId+externalRef，重复失败合并不膨胀；重试前全量重查项目/修订/单位/映射/启用/墓碑 | 满箱显式提示不静默覆盖；箱自身保存失败在设置页可见；启动恢复每条自动尝试一次并出摘要；重试拒绝给出可见原因，绝不自动转投新项目或绕过墓碑 | 设置页外部来源区重试/丢弃（带确认）；摄取报告以 storageRetryable 与配置拒绝区分；不承诺恢复从未收到的监听事件（T-1508 上游边界不变） |
| Task Horizon | 对方读取小驴日历/摘要投影并订阅刷新事件；原生任务真实完成时调用 `recordEvent` 回写 | `taskhorizon:<blockId>:<localDate>`；重复返回已有事件；消费方保留原身份重试 | 对方未实现时小驴本地没有可开启功能；协议/能力不匹配时明确降级 | 保持 API、机器清单、bridge 示例和诊断；等待消费端实现，不添加虚假的本地联动开关 |
| Dock Tomato | 外部专注 provider 通过版本化 facade 启停；完成通知进入有界收件箱并决定写入、拦截或重试 | provider/session 身份稳定；同一完成只处理一次 | provider 缺失、恢复中、上下文非法、写入失败均有稳定状态；积压可导出/重试 | provider 选择、状态说明、积压收件箱、重试/导出诊断；不读取外部历史或污染手动会话 |
| 公开 API v5 | 其他插件/脚本经 `window.siyuanCheckin` 查询只读投影或写入事件 | 调用方负责稳定 `externalRef`；批量写逐条返回 recorded/duplicate/discarded/blocked/rejected | 未就绪、能力缺失和保存失败有稳定错误语义；写入失败由消费方保留身份重试 | 契约文档、能力协商、批量结果、诊断快照；设置页只展示授权/能力，不逐个模拟消费方配置 |
| 摘要驻留 | 小驴把白名单汇总数字幂等追加到用户指定文档，外部工具经内核读取 | 日期级标记；只追加插件自写块；不含事件备注和 externalRef | 写文档失败不回滚打卡事实；记录审计并可重试 | 目标体检、立即写入、预览字段、最近写入/失败；与“外部来源摄取”分组显示 |
| 日记报告/问卷/锚点 | 用户动作后向指定文档、日记或块写入报告/答案/进度 | 插件自写块或锚点身份；更新仅限插件拥有的内容 | 旁路写入失败保留事实与表单草稿，绝不改写用户已有内容 | 目标体检、打开目标、预览、失败重试和隐私说明；不称为双向同步 |

## 三、统一状态不能只用一个徽标

设置页当前的“待设置 / 可启用 / 已启用 / 需重绑”只描述本地配置，不能代表宿主真的可用。后续统一来源面板应拆成四个正交维度：

1. **配置状态**：未配置、可启用、已启用、目标失效。
2. **运行状态**：未探测、宿主缺失、空闲、运行中、暂停、读取中。
3. **活动状态**：最近成功时间、今日写入数/分钟、最近扫描数量。
4. **问题状态**：稳定错误码、用户可执行的修复动作、最近失败时间。

状态必须来自事实：没有运行时探测的来源显示“未探测”，不能因本地开关开启就显示“可用”。最近错误有界保留，成功后可清除；默认不把正文、书名、URL、Key 或 externalRef 放进诊断。

## 四、按渠道提供不同操作

- 监听型（思阅/思播）：`启停 + 宿主探测 + 今日累计`，每段新增整分钟独立入账，不显示“立即同步”。
- 拉取型（微信读书）：`立即拉取 + 最近结果 + 凭据管理 + 窗口说明`。
- 文档摄取型（健康/叶归/笔记推导）：`检测目标 + 立即读取 + 匹配预览 + 跳过原因 + 窗口占用`。
- 对外 API 型（Task Horizon/Dock Tomato/API v5）：`协议状态 + 能力 + 诊断/示例`；消费方尚未实现时明确写“等待对方接入”。
- 文档输出型（日记/摘要/问卷/锚点）：`目标体检 + 预览/立即写入 + 审计/重试`，与自动来源分组分开。

## 五、功能排期

### P0：来源状态模型与设置页纠偏

- 已交付统一只读 `IntegrationStatus` 投影，覆盖配置、运行、活动、问题四轴；现有来源按五类数据流分组。文档摄取报告/匹配预览归 T-1505。
- 为每个来源显示“数据从哪里来、写到哪里、多久触发、停用后怎样”四项固定摘要。

### P1：文档摄取可解释性

- 健康、叶归、笔记推导统一返回有界摄取报告：扫描、匹配、计划写入、实际写入、重复、墓碑、手动冲突、非法、未匹配、拦截及窗口读满风险。读满不等于已证实截断，不显示无法获知的截断数量。
- 设置页展示最近一次报告并允许手动重跑；报告不含正文和敏感值。

### P1：重复累计冲突提示

- 同一个目标项目同时绑定多个自动时长来源时给出非阻断警示，尤其是思阅与微信读书阅读时长；不自动关闭任何来源。
- 提示只基于已配置映射与指标语义，不猜测书目或用户行为。

### P2：对外契约中心

- 把 API v5、Task Horizon、Dock Tomato 的版本、能力、就绪状态和诊断入口集中展示；本地设置与外部消费方状态严格分开。
- 不新增远程账号、Webhook 服务或未获授权的后台网络通道。

## 六、明确不做

- 不做一个含义模糊的“全部同步”按钮。
- 不读取其他插件私有数据库、私有 petal 文件、未版本化 DOM 或内部播放器对象。
- 不把停用解释为删除历史，不自动迁移旧事件到新项目。
- 不让非法配置静默回落到另一条真实查询。
- 不自动合并来自不同渠道、可能描述同一现实行为的数值。
- 不为尚未实现消费端的合作方伪造“已连接”状态。
