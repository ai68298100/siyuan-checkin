# AI 双轨能力规划

小驴打卡的基础功能始终在本地完成。AI 是可选的解释、规划和自动化入口；没有配置思源智能体模型时，打卡、编辑、历史、总结、复盘、导出、同步和第三方插件 API 都必须完整可用。

## 已有功能审查

| 功能 | 无 AI 基础能力 | 思源智能体增强 | 权限边界 |
| --- | --- | --- | --- |
| 今日打卡 | 本地列表、分组、排序、记录与撤销 | 用自然语言查询项目并在确认后记录 | 写入能力单独声明 `localWrite` |
| 历史记录 | 搜索、来源筛选、备注、撤销、导出 | 按问题选择时间范围并解释记录变化 | 默认只读；撤销暂不开放给智能体 |
| 日周月总结 | 本地聚合、完成率和自定义范围 | 使用思源已配置模型生成自然语言复盘 | 只读并声明 `dataEgress` |
| 单项复盘 | 本地完成率、连续记录、热力图、趋势和行动建议 | 结合结构化证据解释原因、比较阶段 | 本地建议不联网，AI 只读 |
| 项目设置 | 模板、类型、目标、单位、频率、分组和优先级 | 根据用户目标提出配置草案 | 当前只建议，不允许 AI 直接修改 |
| 外部集成 | 番茄钟、任务、总结提供者和事件订阅 | Agent 与外部插件共用稳定结构化上下文 | 外部写入校验单位、版本和重复引用 |
| 同步可靠性 | 合并、锁、冲突提示和存储保护 | 将可解释的冲突状态提供给 AI 辅助排查 | AI 不介入底层存储合并 |

## 设计规则

1. 每项 AI 能力先有可测试的本地数据模型或规则，界面不得等待模型响应才能使用。
2. Agent 能力使用思源 `addAgentCapability` 注册，不重复保存模型地址、密钥或计费配置。
3. 查询和写入拆成不同能力；任何修改数据的能力必须声明 `localWrite`，并复用普通界面的校验、锁和持久化流程。
4. 发送给模型的上下文保持最小化、结构化和有日期边界，不默认发送全部历史与备注。
5. 思源版本不支持 Agent、用户未配置模型或模型调用失败时，只隐藏或停用 AI 入口，不影响基础页面。
6. 插件目标保持 ES2020 和思源既有最低容差；AI 增强不得抬高基础运行环境。

## 后续开发块

### A. 可解释的本地建议

- 从完成率、连续记录、最近趋势和当天进度生成确定性建议
- 在复盘页展示建议及其数据依据
- 将相同建议加入 `checkin-item-insights` 结构化输出
- 后续允许智能体基于建议解释，但不能把模型输出当作统计依据

### B. AI 复盘工作话入口

- 在总结和单项复盘页提供“用思源智能体继续分析”入口
- 传递选中的项目和日期范围，避免用户重复描述上下文
- 未配置智能体时给出普通复盘页，不增加 API 配置表单

### C. 计划草案与用户确认

- AI 可生成新项目或调整项目的结构化草案
- 用户在普通编辑器中检查名称、目标、单位、频率和分组后保存
- 第一阶段不允许模型直接创建、归档或批量修改项目

### D. 冲突和失败诊断

- 为保存失败、版本冲突和同步合并生成机器可读原因
- 普通界面提供明确恢复操作，AI 只负责解释原因和建议顺序
- 补齐并发写入、锁超时、迁移失败和退出前写入测试

### E. 生态上下文

- 完善番茄钟、任务、日历和自动数据源的来源说明
- 为第三方插件提供最小上下文示例、幂等引用和超时约定
- Agent 输出与 `window.siyuanCheckin` API 使用同一字段语义
