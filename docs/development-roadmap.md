- 唯一红灯是 CSS 体积预算：`release-assets` 断言 294502 > 283000 字节（B-005）。同工具链下 v9.6.1 实测 264920 字节，增量全部来自未发布的 dock 宽度工作，属真实增长而非环境差异。（2026-09-14 已处置：经全量类名核查无死样式后，预算按 T-109 机制上调至 318000 并更新基线注释，四档样式的合并精简立项为 15.0-A。）
- CI 根因已修复：此前 GitHub Actions 全部倒在 Install dependencies（pnpm 11 拦截 esbuild/@parcel/watcher 构建脚本）。allowBuilds 白名单与 `.gitattributes` LF 固定已入库；QA 脚本的硬编码机器路径已改为按检出位置解析（D-055）。9.7.0 发布后需以远端运行结果作为最终 CI 证据。
- 4 个历史乱码文件已按字节证据修复：DECISIONS.md、PROGRESS.md、desktop-dialog 与 responsive-layout 守门测试（D-054）。
- T-023/T-129 真机验收仍然独立阻塞：需要真实思源桌面端、移动端、页签与 dock 操作。

## 路线复盘结论（2026-09-14）

本轮桌面事项页、设置页折叠、Today 卡片密度与完成反馈修复后，原路线需要做三项调整：

1. **9.x 不再新增功能**：先以 9.8.x 作为现场验收与稳定化窗口，集中完成 T-023/T-129、番茄钟双窗口 smoke、发布包与 CI 复核；集市审核必须以后置现场证据为门槛。
2. **10.0/11.0 的核心模型已基本落地**：恢复/迁移/审计自动化和提醒中心、延期跳过等能力已完成，后续只补跨端事件契约、时区/跨日边界和兼容性，不再重复规划同类 UI。
3. **建议工作流不应继续等待 13.0**：确认、取消、撤销、持久化、生命周期防护、跨窗口事件和只读 API 已在 TODO 中完成；13.0 改为“受控执行收口与生态试点”，重点验证真实宿主冲突和第三方消费，而不是继续堆模型层。

调整后的依赖顺序为：

`9.8 现场验收 → 10.0 恢复兼容维护 → 11.0 提醒跨端契约 → 12.0 分析与生态稳定 → 13.0 受控执行试点 → 14.0 发布工程 → 15.0 UI 系统整合`。

每个阶段都必须先清理前一阶段的真实客户端阻塞；如果 T-023/T-129 未关闭，只允许修复反馈和测试，不扩展新的用户可见功能。

## 环境能力

- 可用：Node、pnpm（corepack 或 PATH shim）、TypeScript、Webpack、Git、系统 Chrome。
- 浏览器测试：`CHECKIN_BROWSER` 指向系统 Chrome；QA 脚本项目根默认按检出位置解析，可用 `CHECKIN_QA_PROJECT_ROOT` 覆盖。
- 不可用：当前没有真实思源客户端，不编造 T-023 结果。

## 后续大版本顺序

### 9.x 收尾（当前）

1. ~~处置 B-005~~（已完成：预算上调至 318000 并记录依据，见 B-005 与 D-056），`test:quality` 全链恢复绿灯。

3. 发布后优先收集真实思源客户端验收证据，完成 T-023/T-129 后再决定集市审核与后续 15.0 工作。

#### 9.8.x 稳定化清单

- 完成桌面事项页顶栏/列表、设置页历史折叠、Today 卡片密度等现场复测。
- 完成手机、页签、dock 的局部刷新焦点/滚动验收，以及番茄钟双窗口 CAS smoke。
- 仅修复现场发现的问题；不引入新的数据字段或智能体写入口。
- 现场清单、截图、版本号、构建产物哈希和 CI 结果齐全后，再开启集市审核。

### 10.0 数据安全与迁移（自动化已完成）

1. 将快照、恢复、冲突和审计能力整理为统一迁移服务。
2. 增加迁移前预检、迁移后校验和失败回滚报告。
3. 覆盖旧版本数据、非法字段、重复事件和多窗口写入冲突。

状态：自动化验收已完成，见 `docs/v10-recovery-acceptance.md`；真机部分并入 T-023。

### 10.0 智能体协作增量（基础能力已前置完成）

1. `checkin-summary-context` 与 `checkin-action-suggestions` 仅提供结构化只读上下文。
2. 回顾页展示截止日期、亮点、薄弱项目和本地行动建议；智能体分析失败时离线降级。
3. 任何项目设置或记录变更必须先展示差异、影响范围和撤销方式，再由用户确认执行。
4. 建议执行写入统一进入审计与可回滚队列，不允许智能体静默修改数据。

当前实现进度：只读上下文、行动建议能力、建议状态机、变更白名单、差异预览、分析缓存、历史版本浏览与正文对比，以及确认/取消/撤销、持久化、审计和生命周期防护均已完成；后续仅保留真实宿主冲突与生态试点。

### 11.0 计划与提醒平台（模型与 UI 已落地，进入跨端契约阶段）

1. **11.0-A 计划实例模型**：为每天/工作日/指定星期/间隔/周期配额生成稳定实例 ID；明确计划日期、状态（待处理/完成/跳过/延期/过期）和来源。
2. **11.0-B 提醒中心**：回顾页与今日页提供统一提醒卡片，支持按紧急度、日期和来源筛选；移动端保持低干扰，不使用系统顶栏强提醒。
3. **11.0-C 延期与跳过**：用户可对单次实例延期或跳过，保留原因和审计记录；延期不篡改原始打卡事件，统计口径可追溯。
4. **11.0-D 跨端一致性**：桌面弹窗、页签、dock 和移动端共享同一实例状态与事件协议，处理跨日、时区、夏令时和多窗口合并。
5. **11.0-E 番茄钟联动增强**：将番茄钟 session 与计划实例关联，重复回调幂等，失败进入可观察队列，不阻塞手动打卡。
6. **11.0-F 智能体建议只读接入**：智能体可解释逾期、延期和完成趋势，但仍不得静默修改计划；任何批量调整继续走确认、差异、审计和撤销流程。

当前实现进度：投影模型层、提醒中心 UI、逾期提醒、筛选、延期/跳过/恢复及跨日自动过期均已落地；剩余重点是 11.0-D 跨端状态事件契约、时区/DST 边界和 11.0-E 番茄钟 session 幂等联动。计划细节见 `docs/v11-planning-reminders.md`。

### 12.0 分析与生态

当前已完成分析快照基础模型：周/月/日趋势、版本化信封、安全解析、迁移、摘要、跨窗口单调合并，以及 `analytics.read` 只读能力和 `checkin:analytics-updated` 更新事件。下一阶段接入回顾页并补充真实客户端验收。

1. 扩展日/周/月/自定义范围分析和报告导出。
2. 稳定第三方插件能力发现、来源追踪和去重协议（`window.siyuanCheckin` v4 契约之上做版本化保证）。
3. 在核心离线能力稳定后再扩大 AI 协作；自动化写入的收口归入 13.0。

### 13.0 AI 受控执行与可解释审计（基础闭环已完成，转试点）

1. 打通"确认写入 → 审计 → 可撤销"闭环：智能体触发的任何写入先展示差异与影响范围，执行进入统一审计队列，用户可撤销；不允许静默修改数据。
2. 承接 `docs/ai-integration-plan.md` C 块：项目创建与调整为结构化草案，回填普通编辑器由用户确认保存；第一阶段不允许批量创建、归档或修改项目。
3. 承接同文档 D 块：保存失败、版本冲突、迁移失败输出机器可读原因码；普通界面提供恢复操作，智能体只解释原因和建议顺序。
4. 承接同文档 E 块：Agent 输出与 `window.siyuanCheckin` 字段语义对齐，提供最小上下文示例、幂等引用与超时约定。

当前状态：建议工作流确认/取消/撤销、审计、恢复、跨窗口事件和只读 API 已完成。后续只做真实宿主冲突注入、第三方试点和错误码可观测性，不再新增未经现场验证的批量写入能力。

完成门槛：离线与未配置模型时全部基础能力可用；每次受控写入有审计记录且可撤销；真实宿主冲突、重放和失败恢复均有证据。

### 14.0 规模化与发布工程（新增）

1. 包体积正式预算化：CSS 采用 318KB 正常线、340KB 警告线、360KB 硬阻断线；webpack 性能警告不等同于发布硬门禁。按 D-051 的可证明性原则清理死样式，完成 15.0-A 后再下修基线。
2. 性能基线常态化：万级事件渲染、dock 四档宽度、低端真机加载耗时纳入 `test:perf` 固定断言。
3. 发布工程：集市升级通道验证、`docs/release-rollback.md` 回滚演练、发布产物哈希与回滚包自动化。
4. 兼容矩阵维护：思源版本升级与 `addAgentCapability` 等宿主 API 变化的适配与降级测试（`docs/siyuan-compatibility.md`）。

完成门槛：真机（桌面 + 移动）验收清单全绿并留档；回滚演练通过；体积与性能预算成为常规门槛的一部分。

### 15.0 UI 与使用体验全面提升（新增，2026-09-14 立项）

目标：在不改数据协议的前提下，对全部界面做一轮整体的视觉与体验升级；升级后的界面要"更清楚先做什么、反馈更即时、宽窄两端都顺手"。延续 `docs/ui-product-roadmap.md` 的主线与验收门槛。

1. **15.0-A 视觉系统整合**：dock 四档宽度样式合并精简（B-005 的后续，目标 CSS 回落到 270KB 内并下修预算基线）；颜色、圆角、阴影、动效时长收敛回 `tokens.scss` 单一来源；层级顺序按 D-050 固化为显式清单，杜绝层叠打架回归。（2026-09-14 首批落地：8 个孤儿 v4 补丁层删除、归档工具行活规则实装、`docs/architecture.md` 模块地图与 `scripts/module-map.cjs` 入档）
2. **15.0-B 反馈与状态统一**：加载、空态、保存中、成功、冲突、失败恢复六类状态用同一套组件呈现；每次操作后焦点与滚动位置恢复全场景覆盖（T-112/T-114 的推广）；危险操作双确认 + 可撤销全覆盖。
3. **15.0-C 今日页体验升级**：与 11.0-B 提醒中心协同，"现在最该处理的一项"置顶、其余折叠；键盘流（T-107）与触控流完全对齐；完成反馈动效与"减少动效"偏好平衡。
4. **15.0-D 移动端打磨**：主操作收敛到底部拇指区；无新手势依赖，按钮轨道稳定；处理真机滚动惯性与键盘弹起视口适配（detail-checklist 的 🔬 项）。
5. **15.0-E 无障碍与可读性**：在现有对比度审计之上补焦点顺序、动态区域（aria-live）语义、减少动效全覆盖与大字号换行验证。
6. **15.0-F 文案与引导**：中英文案统一审校（语气、长度、等价性）；首用引导与四类空态补"下一步动作"入口；设置项帮助文本补齐。

完成门槛：每个切片过宽度走查、双主题无障碍审计与真实客户端截图记录；预算与性能断言随 15.0-A 完成下修；全部常规门槛绿灯。

## 每个大版本的完成条件

- 代码、数据迁移、测试和文档形成可审查提交，且 push 后 CI（verify + browser-audit）全绿。
- `pnpm run test:quality`（环境诊断、类型、单元、UI、移动端、生态、性能、发布资源、生产构建）通过。
- 浏览器自动化使用显式可用的 Chrome；真实客户端验证单独记录，不用自动化结果替代。
- 不 push 到未确认的版本策略，不在未确认前修改远程 Release。
