## 后续大版本顺序

### 9.x 稳定维护

1. 等待并处理 T-023 真机反馈。
2. 只修复真实反馈和自动化回归，不继续堆叠孤立 UI 功能。
3. 保持发布资源、版本元数据和测试证据一致。

### 10.0 数据安全与迁移

1. 将快照、恢复、冲突和审计能力整理为统一迁移服务。
2. 增加迁移前预检、迁移后校验和失败回滚报告。
3. 覆盖旧版本数据、非法字段、重复事件和多窗口写入冲突。

### 10.0 智能体协作增量

1. `checkin-summary-context` 与 `checkin-action-suggestions` 仅提供结构化只读上下文。
2. 回顾页展示截止日期、亮点、薄弱项目和本地行动建议；智能体分析失败时离线降级。
3. 任何项目设置或记录变更必须先展示差异、影响范围和撤销方式，再由用户确认执行。
4. 建议执行写入统一进入审计与可回滚队列，不允许智能体静默修改数据。

当前实现进度：只读上下文、行动建议能力、建议状态机、变更白名单、差异预览、分析缓存、历史版本浏览与正文对比已完成；确认写入、审计和回滚仍待后续阶段实现。

### 11.0 计划与提醒平台

1. 统一计划、日期事项、提醒和完成历史的数据语义。
2. 增加提醒中心、延期/跳过和跨日边界处理。
3. 为桌面、移动端和外部入口提供一致的事件协议。

### 12.0 分析与生态

1. 扩展日/周/月/自定义范围分析和报告导出。
2. 稳定第三方插件能力发现、来源追踪和去重协议。
3. 在核心离线能力稳定后再扩大 AI 协作和自动化写入。

## 每个大版本的完成条件

- 代码、数据迁移、测试和文档形成可审查提交。
- `pnpm test`、`pnpm run test:ui`、`pnpm run test:mobile`、`pnpm run test:ecosystem`、`pnpm run test:perf` 和生产构建通过。

## 下一大版本计划：11.0「计划与提醒平台」

### 目标

把日期事项、周期计划、提醒状态和打卡历史统一为可解释的“计划实例”模型，在不改变现有离线数据可靠性的前提下，让用户知道“为什么今天提醒、错过后怎么办、完成后如何计入统计”。

### 分阶段交付

1. **11.0-A 计划实例模型**：为每天/工作日/指定星期/间隔/周期配额生成稳定实例 ID；明确计划日期、状态（待处理/完成/跳过/延期/过期）和来源。
2. **11.0-B 提醒中心**：回顾页与今日页提供统一提醒卡片，支持按紧急度、日期和来源筛选；移动端保持低干扰，不使用系统顶栏强提醒。
3. **11.0-C 延期与跳过**：用户可对单次实例延期或跳过，保留原因和审计记录；延期不篡改原始打卡事件，统计口径可追溯。
4. **11.0-D 跨端一致性**：桌面弹窗、页签、dock 和移动端共享同一实例状态与事件协议，处理跨日、时区、夏令时和多窗口合并。
5. **11.0-E 番茄钟联动增强**：将番茄钟 session 与计划实例关联，重复回调幂等，失败进入可观察队列，不阻塞手动打卡。
6. **11.0-F 智能体建议只读接入**：智能体可解释逾期、延期和完成趋势，但仍不得静默修改计划；任何批量调整继续走确认、差异、审计和撤销流程。

### UI/体验重点

- 移动端顶栏保持紧凑，提醒以页面内轻量卡片和底部短提示呈现。
- 今日页优先显示“现在最该处理的一项”，其余提醒折叠。
- 回顾页二级栏目增加“计划”概览，先展示结论，再进入明细。
- 所有列表在窄屏下采用单列、内部滚动和稳定按钮轨道，避免内容错位。

### 11.0 完成门槛

- 计划实例、延期/跳过、提醒状态和番茄钟关联均有模型级测试。
- 覆盖跨日、时区、DST、重复回调、多窗口冲突和恢复回滚。
- `pnpm run test:quality`、浏览器宽度走查和双主题无障碍检查通过。
- 真机验收单独记录，重点验证移动端提醒位置、滚动、焦点和低干扰动画。
