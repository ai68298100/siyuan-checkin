# 发版前目标尺寸与暗色审计

范围：本地浏览器构建，1280px 桌面宿主样本，今日、回顾、事项、设置，浅色和深色两种主题。审计使用实际 DOM 几何；被完整 `label` 包裹且整行目标不小于 24px 的原生控件按目标扩展处理。此报告不冒充 Android/iOS 真实宿主验证。

| 检查 | 结果 | 处理 |
| --- | --- | --- |
| 可访问名称 | 0 缺失 | 维持既有浏览器门禁 |
| 正向 tabindex | 0 | 维持既有浏览器门禁 |
| 文本对比度 | 浅/深主题共 808 对，0 违规 | 维持既有 4.5:1 / 大字 3:1 门禁 |
| WCAG 2.2 目标尺寸 | 首轮 2 个目标：项目名称约 24px（实际略小于 24px）、连续徽章 22px | 名称最小高度改为 28px，徽章改为 28px；复测 0 个小目标 |
| 新增批量补卡 | 操作按钮最小高度 44px；复选框由整行 label 扩展 | 回顾页窄宽度/双主题走查继续覆盖 |

自动门禁：`tests/accessibility-audit.test.cjs` 对实际渲染目标要求不小于 24px，允许整行 `label` 扩展；`tests/low-pressure-baseline.test.cjs` 保留移动主要动作 44px 基线。狭窄 dock 的月历格是桌面指针密度布局；移动宿主应使用移动布局，不把桌面 dock 的 28px 格子当作移动触控证明。

暗色复核基于插件独立主题的浏览器渲染，不依赖思源主题色；本轮没有发现文本对比度违规，也没有为了达标把主题改成纯黑底。浏览器门禁不能证明系统缩放、触控命中偏差或原生安全区行为。
