# 小驴打卡整体 UI 与产品路线

这份文档把今日打卡以外的页面、桌面端与移动端差异，以及智能体和外部插件预留放到同一条产品主线上。当前版本已经有独立的 `*-v4.scss` 表面层和稳定的数据/API 层；后续工作优先调整信息层级和交互路径，避免继续在业务逻辑中堆叠视觉补丁。

## 一、产品主线

小驴打卡打开后的第一任务是“现在要完成什么”。今日页承担快速查看、快速记录和快速恢复上下文；历史页回答“我哪天做了什么”；总结页回答“这段时间整体如何”；复盘页回答“为什么会这样、下一步怎么调整”；设置、日期事项和归档属于维护入口，默认放在“更多”中。

桌面端利用宽度形成工作台，允许日历、记录、统计或表单并列；移动端只保留当前任务、进度和一个主要操作，其余筛选、编辑和解释采用抽屉、折叠区或二级页面。两端共享颜色角色、状态语义、图标和文案，不强行共享相同的排列方式。

## 二、页面审查与下一步

| 页面 | 主要问题 | 桌面端方向 | 移动端方向 | 优先级 |
| --- | --- | --- | --- | --- |
| 今日 | 信息很多时筛选和卡片争夺首屏，完成状态不够聚焦 | 顶部摘要 + 紧凑双列项目卡；右侧保留复盘/最近记录上下文 | 摘要压缩为一行，筛选收进按钮，卡片只突出名称、进度和记录按钮 | P0 |
| 新建/编辑 | 配置项多，首次进入容易迷路 | 基础信息、目标、安排、预览双列布局 | 基础字段先显示，高级安排和图标库折叠 | P0 |
| 历史 | 日历、筛选、记录在窄窗口容易形成长页面 | 日历固定左栏，所选日期记录固定右栏 | 月份切换和搜索置顶，记录操作分行，备注二级展开 | P1 |
| 总结 | 统计、项目列表和智能总结层级还可以更明确 | 先显示结论摘要，再显示统计卡和项目排行 | 日/周/月切换固定，统计卡横向滚动或两列排列 | P1 |
| 复盘 | 热力图、趋势和建议较多，重点不够单一 | 项目选择与关键结论置顶，证据和建议分栏 | 关键指标 → 趋势 → 建议纵向排列，日期网格减少装饰 | P1 |
| 日期事项 | 管理表单和列表同时存在，移动端操作密度较高 | 表单与事项列表双栏，列表支持状态分组 | 新建采用独立表单层，列表只显示日期、名称和完成操作 | P1 |
| 已归档 | 当前低噪声但恢复后缺少上下文 | 显示归档时间、原分组和恢复操作 | 只保留名称、归档状态和恢复按钮 | P2 |
| 设置 | 显示偏好、主题、动效与生态设置还没有明显分组 | “界面”“数据与集成”“恢复”三个面板 | 面板折叠，危险操作置底并二次确认 | P1 |

每个页面都遵循“页面标题与返回 → 当前结论/状态 → 主要操作 → 证据或列表 → 次要操作”的顺序。空状态、加载、同步失败和保存成功使用同一套反馈组件，避免每个页面自行设计提示。

## 三、视觉和交互基线

1. 颜色只表达角色：强调色表示主要动作和完成进度，成功/部分/遗漏表示记录状态，表面色表示层级。项目卡不再依赖灰度区分重要性。
2. 卡片使用清晰边界、轻量色带和稳定的操作列。名称、进度和主按钮永远处于一级层级；单位、来源、时间段和备注处于二级层级。
3. 桌面内容宽度控制在 880–1160px，避免宽屏出现大块空白；移动端左右安全边距为 12–16px，底部导航和浮动按钮兼容安全区。
4. 所有主要按钮至少满足 40px 触控高度，图标按钮提供可读的 `aria-label` 和悬浮说明；焦点环不依赖颜色 alone。
5. 长名称、长备注、自定义图标和大字号必须允许换行或滚动，不能挤压主要操作；深色主题使用同一角色变量重新计算对比度。

## 四、4.x 迭代顺序

### 4.1 信息架构收敛（P0）

- 固定今日页为默认入口，移动端底部只保留今日、历史、总结、复盘和更多。
- 将日期事项、归档、设置放入“更多”二级菜单，桌面端仍可提供快捷入口。
- 为所有页面增加统一页面状态：初始化、空数据、保存中、保存成功、同步冲突和失败恢复。
- 把编辑器的图标、模板、番茄钟来源和高级安排纳入统一的渐进展开结构。

### 4.2 复盘工作台（P1）

- 总结页先给出一句本地可解释结论，再给出记录数、完成项和计划项。
- 复盘页将指标、趋势、证据和行动建议分成四个可折叠区，智能体入口只作为增强操作。
- 历史页支持从日期记录直接跳转到项目复盘，并保留当前筛选上下文。

### 4.3 集成与数据工作台（P1）

- 设置页增加“数据与集成”面板，显示 API 版本、事件来源、番茄钟联动说明、智能体能力状态和导出入口。
- 番茄钟项目显示计量模式；兼容插件通过 `source: "tomato"` 与稳定 `externalRef` 写入，重复事件自动去重。
- 自定义图标支持本地图片、图标库和 Iconfont 入口；导入内容限制数量和大小，导出数据时保留图标值。

### 4.4 智能体增强（P2）

智能体分成三层，不把模型调用混入普通页面：

| 层级 | 能力 | 写入权限 | 页面表现 |
| --- | --- | --- | --- |
| 读取 | 日/周/月总结、项目列表、单项趋势、日期事项 | 无 | 显示“可向思源智能体提问”入口 |
| 建议 | 目标和频率草案、复盘解释、异常原因 | 无 | 输出草案或解释，标注数据范围和依据 |
| 执行 | 记录一次打卡、完成日期事项 | 仅明确确认后 | 复用普通校验、锁和保存队列，显示确认摘要 |

当思源版本不支持 `addAgentCapability`、模型未配置或调用失败时，隐藏或降级智能体入口；本地总结、统计、导出和行动建议必须继续可用。模型输入只包含用户选择的日期范围、项目和必要的聚合数据，不默认发送全部备注或历史。

## 五、数据与兼容性预留

- 保持现有 `CheckinStore`、事件来源和删除标记语义；新 UI 不直接修改历史事件结构。
- 新增显示偏好、图标库和集成状态时使用独立存储键，旧版本读取不到时回退默认值。
- 外部插件只依赖 `window.siyuanCheckin` 的能力发现，不读取私有存储；能力缺失时必须保留离线流程。
- 未来可增加 `integrationStatus`、`completionSource` 和 `tomatoMode` 的展示信息，但不让 UI 直接假设某个番茄钟插件存在。
- 智能体草案先回填普通编辑器，第一阶段不允许直接批量创建、归档或修改项目。

## 六、验收门槛

每个页面改动都需要同时通过：

- 1280px、1024px 桌面宽度；760px、600px 窄窗口；390px、360px 移动宽度；横屏与安全区场景。
- 浅色、深色、思源高对比主题；键盘焦点、较大字体和减少动效。
- 页面结构、数据模型、API 契约、移动交互和发布资源测试。
- 真实思源桌面端与移动端人工截图确认。自动化 mock 只能验证结构和交互，不能替代客户端视觉验收。

当前优先顺序是先收敛页面信息架构和状态反馈，再做复盘工作台，最后接入智能体和更丰富的生态集成。这样可以保持基础打卡在没有网络、AI 或第三方插件时仍然完整可用。
