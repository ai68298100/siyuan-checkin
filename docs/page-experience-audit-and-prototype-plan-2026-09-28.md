# 全页面体验审查与统一原型计划（2026-09-28，研究稿，先不开发）

> 本稿为页面方向；源码复核后“已有能力/实际缺口”、正确性任务和实施依赖以 [统一实施计划](consolidated-experience-plan-2026-09-28.md) 为准。回顾三工作区、提醒共用投影、设置行搜索、快速弹窗窗控及渲染块 Today 记录都已存在，实施时只做增量优化。

## 统一判断标准

小驴打卡的页面越来越多，但用户每天只需要完成几类任务：**现在记录、回看事实、理解趋势、管理长期事项、配置规则与联动、恢复数据**。每个页面应有一个主任务，其他能力作为当前任务的辅助入口。页面之间需要共享同一套状态语言：草稿、已保存、进行中、已完成、未配置、未探测、无数据、失败可重试；不能用一个“已启用”同时表示配置完整、宿主存在和已经产生记录。

页面级原型应遵守四条规则：

- 首屏说明“我能在这里完成什么”，并给出一个主动作。
- 复杂内容按工作区或抽屉分层，列表、表单、报告和诊断不互相争夺首屏。
- 所有结果都能回到事实：从卡片跳到记录详情，从来源跳到目标项目，从统计跳到对应日期；跳转前后的筛选、日期和焦点有明确保留规则。
- 空态、加载、权限/宿主不可用、失败和无结果都给出下一步动作；视觉状态有文字或结构冗余，不依赖颜色。

## 各页面原型方向

### 今日：行动台

原型结构：顶部日期与入口 → 一条“当前完成度/下一步”摘要 → 今日待做列表 → 已完成折叠 → 辅助卡片（提醒、事项、那年今天、未来负荷）按需展开 → 最近记录反馈。首屏只保留一个明显的主路径：选择项目、执行记录/专注、看到成功事实。

- 快速输入识别结果应成为列表上方的确认条，明确目标项目、数值和日期；无法唯一匹配时只给选择，不自动写入。
- 筛选、排序、分组和批量操作放入同一个工具条；进入批量模式后固定显示选择数和退出动作，避免和单项记录按钮混在一起。
- 提醒/事项只显示需要行动的异常；没有行动时折叠，不以大卡片占据首屏。未来负荷和那年今天默认折叠，保留跳转目标。
- 空态按“没有项目 / 今天没有排期 / 搜索无结果 / 全部完成”四种情境显示不同下一步。

### 回顾：调整既有的事实、解释、调整三个工作区

回顾已设概览、记录、分析三工作区；下一步调整各区的职责：

1. **概览**：范围、完成/适用分母、主要变化、项目摘要和需关注项。
2. **记录**：日期/项目/来源/计量方式筛选，事实详情、批量补记和撤销。
3. **分析与复盘**：趋势比较、分母解释、周复盘、确定性洞察和已有回顾助手提示词复制；T-1539 的周复盘专用提示词仍是条件候选。

已有报告复制/导出/保存视图入口可收束到“报告操作”；回顾直达文档写入目前未提供，如增加应复用设置页现有目标与输出动作，不新造写入语义。高级筛选显示已启用条件和清除动作。图表/摘要提供“查看原始记录”和日期跳转，回到记录时保留筛选与排序。已有复盘草稿与回顾助手提示词各自有用途，T-1539 的周复盘专用提示词仍是条件候选。

### 单项洞察：从数据到行动

顶部固定项目身份、统计范围、单位和当前修订；摘要指标旁边直接显示分母/无适用原因。主区按“状态日历 → 趋势 → 周期/成熟度 → 行动建议”排列，稀疏数据、配额和排期无效明确显示。每个异常点提供跳转回顾记录或编辑规则；改变范围只刷新当前图表，不重置项目选择。

### 事项：列表优先，编辑抽屉

默认先显示事项列表：保留已有搜索、状态/类型/时间筛选、里程碑、补标/改期与转打卡，增加 Today/Upcoming/Overdue agenda 层级。新建或编辑改为抽屉/独立表单，模板作为“从模板开始”的次级入口；长备注和周期高级规则折叠。保存后返回原筛选位置。删除、停用、永久结束和补标分别说明影响，避免把事项完成误认为打卡事件。

### 归档：恢复中心

顶部说明“归档项目的历史仍保留”。沿用已有暂停生效日、持续天数、最后记录和完成天数，补原规则与关联状态；操作日和次日生效的暂停日分别说明。恢复后明确会回到今日还是保持不排期。已有批量和删除确认保留，危险区增影响预览；搜索无结果和空态提供回今日/新建入口。

### 设置与编辑器

设置页采用 D-303 的“首页总览 + 任务分区 + 详情”原型；新建/编辑页采用 D-304 的类型驱动步骤。两个页面都需要项目/来源/文档目标回链：在编辑器看到来源状态，在设置看到目标项目与“回到项目”动作，避免复制同一套配置控件。

### 快速弹窗、专注和嵌入表面

快速弹窗保留已有关闭、全屏、拖动缩放与记录能力，重点补当前上下文、会话/草稿恢复、实际数值和提交结果；专注弹窗已有预设/暂停/结束，重点补跨表面状态、重载策略、实际入账值和失败重试。渲染块 Today 已可记录；页签、dock 和渲染块根据容器能力隐藏不适用入口，但保持标题、日期、空态、真实记录结果和错误语义一致；打开完整页面作为明确升级入口。

## 需要单独收口的功能面

### 提醒中心

今日页的优先提醒和回顾页的提醒区已有共用投影；应在此基础上统一呈现与动作入口。中心按“需要处理 / 即将到期 / 已处理”分组，每行显示来源、原定日期、当前到期日和可执行动作；“稍后、今天、跳过一次、完成/记录”要说明是改变本次实例还是长期规则。今日页只投影前 1～3 条和“查看全部”，回顾页复用同一筛选和状态；安静时段只影响呈现，不隐藏历史。批量处理、无结果和恢复应与普通打卡事实分开。

### 问卷与日记

问卷答题窗口不应同时承担目标配置。首次打开只显示当前目标摘要和“更换目标”，目标配置使用统一思源选择器；答题区按步骤显示进度和必答错误，提交前提供答案预览及“会写入什么”。提交后明确显示两条结果：“打卡事实已保存”和“文档写入成功/失败，可重试”；`alreadyWritten`、重复填写和目标失效都有独立状态。问题多时移动端分步而非超长滚动，滑块显示端点和当前值。

### 专注计时与快速弹窗

专注计时需要跨页的持久小条，显示已用/剩余时间、预计入账值和当前项目；切换预设、放弃、结束分别确认，少于 1 分钟的结果说明不入账原因。重载后恢复或明确失效，完成后展示事实和外部写入的双结果。快速弹窗已有关闭、最大化、拖动和缩放，需加强可发现性及当前页面上下文；关闭后按会话保留页签/草稿，移动端把次要入口收进溢出菜单。

### 事项和归档的边界

事项落地页先是 Today/Upcoming/Overdue agenda，再进入全部和历史；创建按“是什么→何时→重复→提醒→可选关联→备注”分步，模板只负责起点。已有转打卡入口增加项目/排期/重复检测预览。归档行显示暂停生效日、最后记录和可证实的外部来源/文档/锚点状态；现有模型不存手动/自动归档原因，旧记录只能标未知。恢复前预览是否重新进入今日，已有永久删除确认增加可读的事件、externalRef、锚点和关联事项影响。

### 单项洞察口径

洞察页应支持 28/84/365/自定义范围和可搜索项目选择器。戒除/上限显示“守住/破戒/超额”，不能套用普通完成色阶；配额显示周期贡献和适用分母。成熟度的“机会日”和“自然日”只能选定一个定义并在页面解释。日历格、趋势点和周行都可以通过键盘/触屏跳到对应记录日期；教练建议必须带“查看证据 / 记录 / 调整排期”动作，项目删除或归档提供恢复入口。

## 统一交互与视觉规范

- 顶部导航统一显示页面名称、上下文（日期/项目/范围）和返回路径；详情页返回原工作区，不把用户送回今日首页。
- 统一“主动作 / 次动作 / 危险动作”按钮层级，危险操作远离保存与记录按钮；成功反馈说明写入了什么、是否产生事实、是否需要重试。
- 折叠区默认按任务重要性决定，不把长文本全部展开；展开/收起、筛选、分页、图表范围和滚动状态按页面会话保存并有界。
- 卡片和图表使用颜色、图形、文字和 `aria` 四通道表达；触控目标至少 44px，桌面宽度增加时内容保持可读最大宽度。
- 所有页面支持键盘焦点可见、中文 IME 不被重渲染打断、异步结果过期丢弃、失败不清空草稿；动画遵循 reduced-motion。

## 分阶段统一改进计划

1. **页面能力与入口矩阵**：为每个页面登记主任务、主动作、输入/输出、状态、空态、失败动作、跳转目标和宿主表面；清理重复入口和互相矛盾的文案。
2. **统一页面壳与导航**：抽取标题/上下文/返回/状态/底部动作的原型和可访问结构；保留当前 DOM 钩子或提供兼容映射，先不改变业务存储。
3. **先做今日行动台**：按待做→记录→结果收束首屏，重排辅助卡片、筛选/批量工具条和空态，验证记录口径不变。
4. **再做回顾三工作区**：概览、记录、分析/复盘分层，统一报告操作和日期/事实回链；迁移已有筛选、折叠、草稿和导出状态。
5. **完成洞察、事项、归档原型**：单项洞察增加行动回链；事项列表/编辑分离；归档恢复中心明确风险和历史；不改变既有日期算法。
6. **接通编辑器与设置回链**：落实 T-1561～T-1567 与 T-1568～T-1574 的页面关系，项目、来源、文档目标只保留一个真实配置入口。
7. **统一快速表面**：快速弹窗、专注、渲染块、页签和 dock 复用记录结果、错误和空态；按容器能力做降级和打开完整页面入口。
8. **质量与迁移验收**：字段/路由/状态守门 → 双语/键盘/IME/无障碍 → 320px、移动安全区、宽 dock、双主题视觉 → 隔离/真实内核新建、记录、回顾、恢复和重载回归；每页分别记录自动证据和宿主证据。

## 页面级改造排期拆分

T-1575～T-1584 是统一页面壳与主要工作区的主线；以下任务把容易被概括掉的功能面单独列出，避免只改视觉层：

- 今日：NLP 双模式、筛选标签、配额/上限状态、批量危险动作和跨页专注（T-1577～T-1578）。
- 回顾/洞察：范围和路由保留、记录动作抽屉、图表点选回链、比较器搜索、上限/配额口径和成熟度定义（T-1578～T-1579）。
- 事项/归档：agenda、分步表单、转打卡确认、错过/改期/里程碑、恢复预览和永久删除影响（T-1580～T-1581）。
- 问卷/日记、提醒中心、专注、快速弹窗：分别拆为 T-1585～T-1602，和共享页面壳一起验收双结果、目标选择器、状态机、重载和移动操作。

## 跨表面工程化补充

当前 `currentPage`、单一洞察返回页和统一 `render()` 入口使页签、dock、快速弹窗、移动宿主之间容易互相切页；编辑器、事项、设置和洞察返回也常固定回今日。后续需定义显式的 surface context：`page / returnStack / date / filter / workspace / focus / scroll`，每个表面独立保存并在关闭、刷新、重载时按能力恢复或明确降级。旧 DOM 钩子、书签和深链接用兼容映射迁移，不能靠隐式全局变量猜上下文。

加载、空态和错误也需要统一契约。今日已有多种空态，但回顾、事项、归档、洞察和初始化失败仍有纯文本或硬编码失败提示。统一状态至少包括 loading、empty、no-match、unprobed、unsupported、permission/target-missing、failed、retryable、saved、unsaved/draft；每个状态都要有真实来源、`role=status/alert`、下一步动作和双语文案。异步结果过期时丢弃，失败保留输入/草稿/焦点，重试不能重复写入。

宿主壳需要单独做矩阵：移动 WebView 320/360/390/430、窄 dock、页签/弹窗宽度、横屏短高度、软键盘和 safe-area。统一滚动容器、底部操作栏、topbar 层级和 reduced-motion 作用范围，避免菜单被底栏遮挡或不同表面重复渲染导航。多 root 同时打开时要有渲染预算和 teardown；渲染块的 MutationObserver、多个块并存、销毁后回调和局部失败要有安全回退与打开完整页面路径。

## 边界

这次统一原型不新增打卡类型、不改变 Store v3、事件身份、日期/排期公式、来源契约、文档旁路和公开 API。改造先解决入口、层级、状态、回链和可解释性；需要新数据字段、自动合并或跨来源语义的功能另立任务。
