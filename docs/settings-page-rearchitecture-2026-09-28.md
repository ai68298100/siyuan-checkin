# 设置页 UI 原型与重构步骤（2026-09-28，研究稿，先不开发）

## 先定义设置页的作用

设置页承担四件事：

1. **改变插件行为**：今日列表、提醒、快捷键、弹窗和显示偏好。
2. **建立外部关系**：宿主/插件能力、第三方来源、思源文档与笔记本目标。
3. **维护数据**：导入导出、恢复点、诊断、审计和重置。
4. **解释当前状态**：哪些已配置、哪些正在运行、哪些需要用户处理。

它不是今日工作区，也不是所有功能的目录。设置首页应回答“我现在需要处理什么”和“改完会影响什么”；长表单、来源高级参数和恢复工具进入对应详情区。

## 现有结构与问题

当前 `src/render/settings.ts` 有 9 个一级组：外观、今日视图、对话框、快捷键、数据、宿主、文档写入、第三方来源、关于。随着联动、问卷、模板、诊断和迁移能力增加，出现四个结构问题：

- **层级混用**：外观和对话框是个人偏好，第三方来源是有前置条件的配置流程，数据与恢复是高风险操作，却使用同一种设置行。
- **入口分散**：项目绑定、文档目标、来源映射、问卷模板和宿主提供方分别在项目编辑器与设置页，用户无法从首页看到“待处理配置”。
- **状态不可比较**：普通开关、来源配置徽标、运行状态、文档写入结果和诊断数量同时出现，没有一张总览说明哪些是已保存、已启用、已产生结果、已失败。
- **长内容挤在页面内**：外部来源卡片、文档选择、恢复指南和高级边界一起渲染；设置搜索虽可用，但按组文本匹配，不能把用户直接带到某个具体字段或未完成步骤。

## UI 原型：两层结构

```text
设置
├─ 设置首页（总览）
│  ├─ 待处理：目标失效 / 来源未完成 / 文档写入失败 / 待保存草稿
│  ├─ 最近活动：最近成功读取、写入、宿主探测、诊断问题
│  ├─ 快捷入口：新建项目、配置自动记录、绑定思源目标、导入/恢复
│  └─ 全局搜索：字段、来源、项目、文档路径；显示分组和状态，回车直达
├─ 今日与提醒
├─ 外观与操作
│  ├─ 外观（主题、语言、动效、触感、头像、图标）
│  ├─ 今日视图（分组、排序、完成项、周条）
│  ├─ 提醒（安静时段、提醒时刻、提前提醒）
│  ├─ 快捷键
│  └─ 弹窗与页签
├─ 联动与目标
│  ├─ 自动记录来源（宿主/插件、第三方来源）
│  ├─ 思源文档输出（报告、摘要、问卷、锚点）
│  └─ 思源目标管理（文档/笔记本选择器、集中体检、失效修复）
├─ 数据与恢复
│  ├─ 导入/导出
│  ├─ 恢复点与回滚
│  ├─ 诊断与审计
│  └─ 重置（危险操作单独分区）
└─ 关于与兼容性
```

首页不是新的一级功能数据源，只是对各模块的只读投影。待处理卡片必须能跳到具体字段或卡片；无问题时显示“没有待处理项”和最近活动，不制造空的警告区。

### 首页卡片原型

```text
[设置搜索……]                         [清除筛选]

需要处理（2）
┌ 文档目标失效 · 叶归 LifeLog                         重新选择  打开来源 ┐
└ 摘要最近一次写入失败                                 重试      查看审计 ┘

最近活动
┌ 今日 10:24  思阅  写入「阅读」项目  20 分钟       查看记录 ┐
└ 今日 09:10  摘要  写入目标文档成功                 打开文档 ┘

配置入口
[自动记录行为] [写入思源笔记] [数据与恢复] [外观与操作]
```

### 详情页/抽屉规则

- 每个详情区顶部显示用途、影响范围和“已保存/草稿/需要处理”状态。
- 普通偏好采用即时保存；涉及目标、来源启用、批量恢复和重置的操作采用“编辑草稿 → 变更清单 → 确认保存”。
- 来源和文档目标使用前面已登记的统一选择器；高级边界、查询上限、隐私和兼容性放在折叠说明。
- 详情返回首页保留搜索词、滚动位置、展开卡片和焦点；移动端使用底部返回，不再依赖长页面滚动寻找上一级。

## 分区职责

| 新分区 | 放什么 | 不放什么 |
| --- | --- | --- |
| 外观与操作 | 主题、语言、动效、触感、头像、今日显示、提醒、快捷键、弹窗 | 来源凭据、文档目标、恢复操作 |
| 联动与目标 | 项目产生记录的来源、宿主能力、第三方来源、文档输出和统一目标选择器 | 导入导出、纯显示偏好 |
| 数据与恢复 | JSON/CSV、快照、诊断、审计、待处理箱、重置 | 联动启用开关和文档目标配置 |
| 关于与兼容性 | 版本、最低思源版本、公开契约版本、已知兼容边界 | 需要用户频繁操作的配置 |

宿主/插件、第三方来源、思源文档写入仍保留各自语义，但在“联动与目标”下以任务入口呈现。三者内部沿用 T-1551～T-1560 的职责、动作、目标、状态、问题分层。

## 具体改造步骤

1. **建立设置字段注册表**：给每个字段登记分区、详情卡、风险级别、保存方式、搜索关键词、状态来源和跳转目标；先覆盖现有 9 组，避免重构时遗漏事件监听。
2. **实现首页只读投影**：汇总待处理项、最近活动、草稿数量、未配置联动和数据恢复入口；所有数量必须来自已有状态/审计，不新增第二套业务判断。
3. **把搜索升级为字段级导航**：按字段标题、说明、来源、项目名、文档路径和状态匹配；结果显示所在分区与卡片，选择后展开目标详情并聚焦控件；支持中文输入法、无结果和键盘上下移动。
4. **拆分外观与操作**：把现有外观、今日、提醒、快捷键、对话框按职责重组；设置项不改存储键，旧书签和深链接通过别名映射到新分区。
5. **合并联动入口**：在一个分区里按“自动记录 / 写入思源 / 宿主能力”提供入口，复用来源卡、文档目标选择器、项目回链和四轴状态；先迁移 DOM 容器，再调整文案，避免一次改动同时改变事件语义。
6. **隔离数据与恢复危险操作**：导入、恢复、删除快照、清空审计和重置分成卡片；恢复前显示影响范围和备份动作，重置永远不与普通保存按钮相邻。
7. **迁移状态与无障碍行为**：保留展开状态、搜索状态、草稿焦点和移动底栏行为；每个详情区有唯一标题、`aria-current` 导航和可回到首页的按钮。
8. **分阶段验证**：先跑字段/路由/存储接线守门，再做双语、键盘、IME、320px～宽屏视觉走查，最后用真实内核验证文档目标、来源卡、恢复和重载。旧配置必须在新结构下原样恢复，未知宿主状态不能被首页概括成已连接。

## 暂不改变的边界

本原型不新增一级产品功能、不改变 Store v3、不改变公开 API、`externalRef`、墓碑、文档旁路写入或来源采集口径。首页只读聚合现有事实；任何新状态字段、自动修复或批量迁移另立任务评审。
