### 已确认的正确性与契约问题

1. **洞察戒除口径（P0，T-1609）**：`src/model.ts:isComplete` 将每日 `atMost` 二值零事件视为完成、有破戒事件视为未完成；`src/features/insights.ts:buildHabitInsights` 仍用 `progress > 0 && progress >= target`。旧日零破戒会显示 missed，破戒却显示 complete，数值上限也反向。先用固定日期夹具对齐 `isComplete`、洞察日状态/聚合、回顾口径，再做范围和图表改造；跳过与当天未结束状态必须单独定义。
2. **今日单位修订（P0，T-1610）**：`src/render/fragments.ts` 给行动台传 `revision.target` 却传 `item.unit`。先补“昨日单位 A、今日单位 B”的 fixture 和只读投影修正，再重排卡片。
3. **绑定能力不可凭空预检**：现有 `validateBindingTarget` 用 SQL 元数据和笔记本列表检查目标存在、类型、文档根和笔记本打开状态；本轮未证实一个可靠的思源“可写权限预检”契约。T-1558 先只承诺可证实的元数据/范围检查，写入能力以实际操作结果及审计呈现，不用试写用户正文冒充预检。
4. **目标展示信息不新增存储承诺**：当前目标名/路径由会话查询得到，稳定身份是已存 ID。选择器可在会话里缓存展示信息，查询失败退回 ID 和修复动作；若要持久化名称/路径快照，先另立模型与迁移决策，不能与“不改 Store v3”同时承诺。
5. **保存语义先逐字段核对**：设置变更清单只覆盖十个显式保存字段；其他开关多为内存即时变化加异步持久化。设置重构先登记每个字段的成功、失败、重绘和重载行为，再决定保留即时还是转为草稿，不以整页统一保存造成意外行为改变。

## 关键用户路径的原型验收

1. **第一次建立分钟项目**：从模板或空白进入同一表单，看见类型、分钟目标、排期和记录动作；保存后从项目跳到思阅绑定，检查单位，等待一个可观察片段，在回顾找到该事件的日期/来源/计量详情。未收到片段只显示“等待事件”，不显示已同步。
2. **多指标与重复来源**：健康步数/体重、叶归 Marker 项目各自映射正确目标；思阅片段和微信读书日汇总同时启用时提前提示可能重复，但保持各自独立事实和 `externalRef`，不自动合并。
3. **问卷并写笔记**：答题时只展示当前目标摘要；提交先确认事实，文档失败时两条结果并列，重试只补文档且不重复打卡。目标保存失败发生在事实写入前，应显示另一种失败状态。
4. **回看并调整**：从今日、提醒或来源打开回顾事实；分母、比较、洞察异常日期能钻取；返回后日期/项目/筛选/滚动可恢复。周复盘草稿与既有回顾助手提示词分开。
5. **恢复与离开**：归档恢复先预览是否重新进入今日排期；归档生效日和操作日分别说明。删除复用已有恢复点和确认，关联及不可恢复范围可读；取消零写入，失败不丢选择。

每条路径至少有空数据、配置缺失、宿主不可用、写入失败、重复操作和窄屏键盘版本。记录 UI 行为的证据必须能指向事实/审计；设计稿截图只能证明布局，不能证明外部来源已连通。

## 发布与决策边界

- 先保持三种 `CheckinKind`、Store v3、既有事件/日期/来源身份和文档旁路，不通过改统计或静默换绑简化 UI。若确需持久目标快照、归档原因、跨重载问卷草稿或新的可写能力检查，分别给出数据/契约设计后再立实现任务。
- 归档“手动/自动原因”当前没有持久字段；旧历史只能显示未知，不从时间或事件猜测。T-1594 先完成可证实信息的预览。
- Task Horizon 消费端是否接入、思阅/思播共享会话身份、真实 Android/WebView 与第三方账号属于对应外部证据，不阻塞本地设计/实现切片，也不在 UI 冒充成功。
- 每个切片记录任务 ID、状态、源码/截图/测试证据和下一步；本地检查、浏览器、隔离思源内核、真实宿主、真实第三方分栏。没有现场条件时明确 `host-pending`，不能把“未测”算成“通过”。
