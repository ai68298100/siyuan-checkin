## 一、起点与规划原则

起点（2026-09-20）：

- v17.3.0 已发布：回顾工作区重构、智能体回顾助手、双主题全端精修全部合入。
- 习惯体系融合（SKIP、强度、弹性周期、at-most、成熟度、负向习惯、里程碑）已落地；API v5 四能力（范围读/批量写/项目投影/指标门面）已实现并通过契约测试。
- 未完成事项只有三类外部依赖：真实宿主验收（用户）、Task Horizon 联调（对方排期）、T-1166 摘要驻留（隐私决策）；以及中期计划内尚未做的 API v5 成文、恢复与并发演练、UI 维护收尾。

原则（继承既有路线，五版本全程有效）：

1. **本地优先**：打卡、统计、导出、恢复在无模型、无网络、无第三方插件时完整可用。
2. **事件=原始记录，推导=计算层**：任何新指标不改写历史事件，统计口径变化只发生在计算层（D-215）。
3. **计分单一代码路径**：新指标走独立纯函数模块，UI、智能体 API、批量操作共用同一入口。
4. **API 纪律**：有界、纯数据、显式结果、去重前置；只增不删不改签名，弃用走协商周期。
5. **不臆造思源 API**：笔记联动只用已验证内核接口；真实宿主证据不足的能力先做诊断与降级。
6. **回写 opt-in**：一切写用户笔记的行为默认关闭、用户主动开启，保留审计与失败隔离。
7. **UI 不回潮**：任何功能批次都必须过四端 × 双主题显示矩阵；「先功能后显示」的欠账模式不再接受，显示问题与功能问题同级对待。
8. **模板是内容资产**：模板不触数据模型、不触 API 契约；每新增/修改一个模板都按真实四端渲染验收，宁可数量克制也不牺牲新建页的清爽。

## 三、v18：契约收口、数据工作台与 UI/模板一期

目标：清「已实现未成文」「已自动化未现场验证」两类欠账；同时用一轮专项把现存 UI 错乱收掉、把模板体验立起治理框架，让后续每版都有可对照的显示基线。

### 3.1 契约与数据工作台

- **T-1341 API v5 稳定文档包**：`api-v5-design.md` 草案转正式文档——类型定义、最小示例、错误码、输入上限（批量 200/范围 366 天/5000 事件）、兼容矩阵、`capabilitiesSince` 协商说明；契约测试包随文档版本化发布；`storeVersion` 双语义（内部 v3 / 公共 descriptor `storeVersion: 2`）在文档中显式澄清。
- **T-1342 恢复与并发演练**：真实升级（v2→v3 store）、降级（旧版本读新数据）、损坏数据隔离、双窗口并发写入、断网后重试与恢复点回滚各做一轮现场级演练记录；产出用户可读的《数据诊断与恢复指南》（设置页可跳转）。
- **T-1343 回顾导出增强**：目标偏差解释（对比基线自动生成「差在哪」的可读结论，本地确定性生成，数据不足时明说）、导出报告带来源筛选、批量导出入口；全部走既有安全导出通道（含 Android 容器桥）。
- **T-1344 真实宿主验收清零**：T-023/T-033/T-129/T-1256/T-1173 按 `integration-smoke-checklist.md` 逐项关闭；B-007 Dock Tomato 双插件现场联调。验收证据进 PROGRESS，浏览器结果不替代真机。
- **T-1345 设置页状态可观察性收口**：番茄钟、Task Horizon、智能体三类外部依赖的状态/错误原因/重试与恢复提示统一为同一套组件与文案模式。

### 3.2 UI 错乱与多端显示专项一期

- **T-1346 UI 错乱清查与修复**：以「错乱」为目标的全页专项——
  - 扫描面：文本截断/意外换行、元素重叠（浮层、提示条、底栏遮挡）、对齐错位、滚动穿透、容器塌陷、主题切换瞬间的残留/闪烁；
  - 矩阵：弹窗/页签/dock/移动四端 × 浅深双主题 × 关键宽度（320/360/375/640/844×350 横屏/1180/2000）× 长名称/长单位/大数值/英文 i18n（英文普遍比中文长，是历史溢出重灾区）；
  - 输出：修复即补守门断言入既有测试链；无法立即修的长尾项进「多端显示问题台账」（登记于本文附录，随版本滚动清零）。
- **T-1347 真机显示回归通道**：真机反馈的显示问题（截图/录屏）进入独立台账，逐条复现于脚本走查后修复；每条关闭必须同时有脚本证据与用户确认，二者缺一则保持开放。

### 3.3 模板体系一期：打磨现有与显示治理

- **T-1348 现有模板打磨**：逐个盘点现有打卡模板与事项（事件）模板——类型/排期/目标默认值是否合理、图标与命名一致性、i18n 对等、与负向（at-most）/配额等新能力的兼容性（如旧模板没有用到 SKIP、配额语义）；不合理的就地修正，修正不迁移用户已建项目。
- **T-1349 模板显示治理**：新建页模板区不再平铺全部——
  - 分类维度（健康/运动/学习/工作/生活/戒除等）+ 搜索 + 「最近使用/常用」置顶；
  - 沿用 T-029 折叠模式默认收起，展开后分批渲染（参照收件箱每 5 条逐批展开的先例），任何端点开模板区不得撑高新建页或产生横溢；
  - 模板预览：悬停/点击先看类型、目标、单位、排期摘要再套用，防误建；
  - 事项（事件）模板与打卡模板共用同一套分类/折叠/搜索框架，不各搞一套。
- **T-1350 模板显示矩阵门禁**：模板区在 320px 窄端、dock 280px、移动端、桌面弹窗的展开/收起/搜索/分类切换全场景断言入 `test:ui`；新增或修改模板必须过该矩阵后才可合入。

明确不做（v18）：不新增大型数据模型；不动 API 签名；模板只做内容与显示治理，不做模板市场/分享。

进入条件：v17.3.x 真实宿主反馈窗口结束（或 2 周到期）。
发布门槛：现场清单、完整质量链、升级/回滚说明、SHA-256 一致、模板矩阵与错乱台账本轮清零项复核。
风险预案：Task Horizon 未排期时 T-1341~T-1343 照常发布，联调项保持开放不阻塞版本。

## 四、v19：笔记原生深化与 UI/模板二期

目标：把「打卡数据进入笔记」从单点锚点扩展为体系；模板从「治理好存量」进入「有依据地扩充」；UI 从专项修复转入维护态并清掉台账长尾。

### 4.1 笔记原生

- **T-1351 渲染块二期**：可配置数据集（分类/标签/分组聚合视图）、热图与汇总的表达式（如只看完成率≥80% 的项目）、点击日期跳转增强（定位日记块并高亮）；渲染安全边界沿用「只读、不渲染任意 HTML」。
- **T-1352 日记集成**：周期报告（周报/月报）可定时或手动写入指定日记文档（opt-in，默认关）；与 T-1232 打卡即笔记共用锚点与失败隔离通道；撤销策略先记 DECISIONS。
- **T-1353 每日摘要写驻留文档（T-1166 启用）**：前置条件是用户完成隐私决策——方案、数据边界（本地路径、内容字段白名单）、外部工具经内核 API 读取的最小形态形成设计稿，评审通过后才实现。

### 4.2 UI 维护态

- **T-1354 UI 维护收尾与错乱台账清零**：清理重复 token 与历史样式、反馈/空态/错误/保存状态组件复用归一、布局跳动专项；v18 遗留的「多端显示问题台账」长尾在本版本内清零或明确降级为「已知限制」；完成后下修 CSS 预算基线（D-239 的 480KB 告警/520KB 硬线重新评估）。
- **T-1355 性能基线扩展**：渲染块在 1k/10k/100k 事件下的渲染门禁并入 `test:extended`；日记回写在多窗口场景的合并演练记录。

### 4.3 模板体系二期：参考扩充

- **T-1356 同类软件模板调研与扩充**：以 `benchmark-habit-apps-2026-09.md` 为底稿，逐类核对 Habitify/Loop/Streaks/TickTick/everyday 等的官方模板与预置目标，挑选与本插件五类型/六排期/at-most 语义可映射的模板扩充入库；每个新模板标注来源与默认值依据；不可映射的（如需要定位、社交、设备传感的）明确记录不做。
  - 候选方向（数量按验收容量取舍，不追全）：健康（喝水 ml、步数、睡眠时长、体重记录）、学习（阅读时长/页数、背单词个数）、运动（跑步、健身时长、拉伸）、工作（深度工作时长、番茄计次）、生活（冥想、写日记、早睡）、戒除（戒烟、戒糖、限时刷手机——at-most）、情绪（感恩记录、情绪自评 1~5 自定义数值）、财务（记账习惯、储蓄进度）。
- **T-1357 模板浏览体验升级**：分类页签/下拉 + 搜索 + 精选推荐位；模板数量增大后新建页仍只露出精选与最近使用，其余经分类浏览按需加载；暗色主题下模板图标对比度专项核对。
- **T-1358 模板回归守门**：模板全量清单测试（每个模板的类型/排期/默认值/图标/i18n 可实例化），扩充不破坏既有实例；模板矩阵门禁覆盖新分类浏览交互。

明确不做（v19）：不做通用模板引擎/脚本执行（表达式限于白名单函数）；渲染块不开放任意 HTML；不做模板云分发。

进入条件：v18 发布且无 P1 级回归；T-1353 需用户隐私决策完成。
发布门槛：双主题视觉矩阵、渲染块性能门禁、回写 opt-in 边界回归、模板矩阵、`test:quality` 全绿。

## 五、v20：受控智能体成熟

目标：把智能体从「回顾助手 + 优先级建议」扩展到「项目生命周期草案」，同时把「只读 → 建议 → 用户确认执行」三层边界做成可审计、可导出的完整闭环；不提供万能写入口。

- **T-1359 项目草案确认流（AI 规划 C 块）**：智能体可生成新建/调整项目的结构化草案（名称、类型、目标、单位、频率、分组），用户在普通编辑器中检查后保存；模型不直接写 store，全部走既有建议工作流（令牌、冲突检查、审计、撤销）。草案可引用模板体系（「帮我建一个喝水模板的变体」），但产出仍是可检查的结构化草案。
- **T-1360 建议执行范围扩展**：在现有「优先级调整」之外，开放排期/目标字段的建议执行（差异预览、before 基线校验、冲突跳过、可撤销不变）；历史事件与已确认记录永远不在建议范围内。
- **T-1361 机器可读冲突与失败诊断（AI 规划 D 块）**：保存失败、版本冲突、迁移失败、锁超时输出结构化原因码；普通界面给恢复操作，智能体只解释原因与建议顺序；补齐并发写入/锁超时/迁移失败测试。
- **T-1362 智能体审计导出**：建议确认/撤销/应用审计轨迹可导出为版本化 JSON 诊断；设置页展示审计统计摘要。
- **T-1363 习惯内核二期调优**：按真实使用反馈优化周期目标推荐、里程碑节奏、反内疚文案与统计口径表述；所有调整只动计算层（原则 2），并保留旧口径一期并行。
- **T-1373 打卡来源扩展探索（探索项，不承诺实现）**：现状来源为 `manual / tomato / import / api / occasion`（智能体经 api+确认流）。系统盘点候选来源并输出可行性结论：思源任务/日历类插件经公开 API 回写（Task Horizon 模式复用）、思源日记模板触发、日历视图直接打卡、命令面板/快捷键快速打卡、外部自动化经 API（iOS 快捷指令等）、智能体自然语言打卡增强。任何新来源必须走既有边界——externalRef 幂等身份、有界输入、来源字段登记、审计与可撤销；探索产出为《来源扩展评估》决策记录与优先级短名单，是否立项另行决策。

明确不做：不做自动批量修改、不做模型直写、不引入 RPG/积分膨胀（可选轻量积分保持默认关）。

进入条件：v19 发布；真实模型联调窗口（可与 B-007 同场）。
发布门槛：未配置模型时全功能可用回归（AI 不阻塞基线）、写入口审计证据、`dataEgress`/`localWrite` 能力声明核对。

## 六、v21：开放生态准入

目标：从「我们有公开 API」升级为「第三方可以按清单自助接入并自测」，让第二个、第三个真实消费方出现。

- **T-1364 适配器准入清单与契约测试包公开发布**：身份、幂等、卸载清理、权限声明、失败隔离五项准入要求成文；契约测试包（npm 包或独立仓库）让消费方在开发期即可自测，不必装插件联调。
- **T-1365 API 弃用周期与错误码标准化**：能力弃用预告字段、错误码枚举稳定成文、`minApiVersion` 协商语义明确；为未来 v6 预留演进说明（只描述流程，不实现）。
- **T-1366 思源插件消费方落地**：以思源集市插件生态为主要候选面——worklog/时间块、日历、任务类等插件经公开 API 接入（Task Horizon 模式复用：契约文档 + bridge 示例 + 契约测试包三件套先行）；通过 README 生态章节、集市插件说明与合作文档触达插件作者；至少一个真实落地（优先消费 `events.range.read`，同时消掉 docktomato 桥内全量扫描的遗留）。
- **T-1367 迁入源扩展**：在 Loop/Obsidian H21 之外评估 1～2 个主流习惯应用的迁入路径（只读其公开导出格式，不逆向私有格式）。

## 八、贯穿性纪律

- **固定质量链**：每批任务过 `pnpm run check`、`build`、`test:quality`、`check:release`；浅/深双主题、桌面/页签/dock/移动端、30 项容量、长文本、无障碍、真实宿主与自动化证据分开记录。
- **UI 细节与多端显示纪律**（v2 新增）：
  - 每个版本的发布门槛都包含：全页内容审计 + 宽度断点走查 + 四端 × 双主题矩阵 + 错乱专项扫描（T-1346 的扫描面清单作为固定检查项）；
  - 显示问题（错乱/截断/重叠/溢出）与功能缺陷同级，不设「视觉问题下版本再说」的默认豁免；真机显示反馈走 T-1347 台账通道，双证据（脚本 + 用户确认）关闭；
  - 英文 i18n 文案一律按「可能比中文长 40%+」预设做布局验收；真机显示缩放（如 80%/110%）纳入走查变量。
- **模板纪律**（v2 新增）：模板为纯内容资产，不触数据模型与 API；新增/修改模板必须过 T-1350 模板矩阵；新建页任何时刻只露出精选/最近使用/分类入口，不允许回到全量平铺。
- **版本语义**：内部 `CheckinStore` 当前 v3、公开 descriptor `storeVersion: 2`；任一数字变更必须先补决策记录、迁移说明与契约测试。
- **minAppVersion**：维持 3.8.4 实测基线（D-238）；下调必须先完成 3.4.2～3.8.3 真实回归矩阵；上调在发布说明明示自动禁用影响。
- **全版本明确不做**：RPG 化、账号体系与社区排行榜、自建同步服务、系统级后台通知、万能智能体写入口、逆向第三方私有数据格式。
- **任务登记**：本文 T-1341～T-1372 在各版本启动时登记入 TODO.md 并拆批次（每批 3～5 个相关任务），外部依赖项（Task Horizon 联调）保持可并行插入。
