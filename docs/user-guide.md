# 小驴打卡任务指南

这份指南按“我现在要做什么”组织功能，适用于当前已发布版本。它只描述已经存在的入口和结果，不把开发中的路线图当成可用功能。

## 30 秒完成第一次记录

1. 在思源中打开「小驴打卡」，进入「新建」。从模板开始，或者填写名称、类型、目标、单位和计划。
2. 保存后回到「今日」。找到刚创建的项目，点击主动作；次数、时长、数量和自定义项目可以继续用快捷增量，或打开精确输入。
3. 打开「回顾」，先确认日期范围、事件数量和来源，再进入项目或某一天查看原始记录。

第一次只需要完成一条事实。提醒、来源联动、笔记输出和 AI 都可以稍后配置，不会阻塞手动记录。

## 选择合适的记录类型

| 你要记录的事实 | 类型 | 今日的主要动作 | 统计口径 |
| --- | --- | --- | --- |
| 做没做 | 二值 | 完成 / 撤销 | 达到一次即完成 |
| 做了几次 | 次数 | `+1` 或精确值 | 累计达到目标才完成 |
| 花了多久 | 时长 | 快捷分钟数或精确值 | 按项目单位累计 |
| 数量、距离或金额 | 数量 | 快捷增量或精确值 | 按单位累计，单位随记录保留 |
| 评分或自定义数值 | 自定义 | 输入数值 | 按项目目标和步长计算 |
| 不超过某个上限 | 戒除 / at-most | 记录发生的次数，或保持不记录 | 没有超限是完成；记录本身不是完成 |

目标、单位和排期会影响当天是否应该出现项目。修改规则前先看编辑器中的预览；历史事件不会被静默改写。

## 忙乱时如何修正

- **今天漏记**：在项目操作中选择补记，明确选择日期后再保存。补记不会把事件伪装成今天发生。
- **刚才记错**：在结果附近使用撤销，或在回顾的原始记录中找到对应事件。先核对日期和来源，再删除或修正。
- **今天不适合做**：使用跳过。跳过表示用户主动休息，和没有记录、自动来源失败、at-most 破戒分别统计。
- **写入失败**：先保留提示中的原因和重试入口。文档报告等旁路输出失败不会回滚已经保存的打卡事实；存储本身失败时不会显示假成功。

## 一周后怎样复盘

1. 在「回顾」选择日、周、月或自定义范围。
2. 先看事实数量、项目范围、来源和更新时间，再看完成率、趋势、热力图和连续记录。
3. 点击项目或日期进入原始事件，确认数字的分母、来源和是否包含跳过日。
4. 只有在事实确认后，再使用建议或编辑规则。规则调整前先看影响预览。

「洞察」是回顾里的单项目上下文页，不需要把它当作独立的每日入口。

## 配置自动来源和笔记联动

在「设置 → 外部联动」逐张查看来源卡。每张卡都应能回答四个问题：产生什么、写入哪个项目、最近一次结果是什么、失败后下一步是什么。

- 先选择项目和目标文档，再启用来源；没有目标时保持手动记录可用。
- 监听型来源不显示虚假的“立即同步”；只有实际提供拉取动作的来源才显示立即读取或立即拉取。
- 来源失败、等待、无数据和成功是不同状态。先看最近结果和诊断，再决定重试、停用或换绑。
- 日记、摘要、问卷和锚点属于文档输出；它们的文档失败不等于打卡事实丢失。

移动端沿用单列内容、底部导航和安全区；长表单、回顾和设置由页面自己的滚动区域承载。浏览器窄视口检查不能替代真实思源 Android 客户端的键盘、安全区和返回手势验收。

## 导入、导出和离开

升级或迁移前，在设置页导出 JSON，并阅读[导入导出格式总览](export-formats.md)确认备注、图片和来源字段的范围。Loop 和 Obsidian 导入会先预览；重复身份会去重，非法行会给出行号和原因。恢复点独立于 JSON 主档，可在数据设置中导出、导入或清空；任何失败都会保留当前打卡数据、旧恢复点或诊断路径，先按[常见问题](faq.md)排查。

插件不提供云同步或社交排行榜。卸载前请先导出需要保留的主档和附件；数据桶、诊断和清理边界见[数据、隐私与卸载说明](data-privacy-and-uninstall.md)。
