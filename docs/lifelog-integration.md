# LifeLog 联动口径

LifeLog 的一条记录形如 `12:00 工作：写日报`：时间是记录边界，时间后的第一段是项目，冒号后的内容是具体事项。某条记录的时长等于同一日记文档中上一条记录的起始时间到本条记录起始时间的差值，并归属于本条记录；当天第一条没有前置记录，时长未知，不写入打卡。

联动设置支持“项目映射”：每个 LifeLog 项目精确映射到一个小驴打卡项目。结算出的每个区间只写入当前记录项目映射的目标，因此同一天可以形成多个不同打卡项目的时长事件。只要配置了映射，未命中的项目就跳过；完全没有映射时仅自动匹配唯一同名的分钟项目，不再使用旧版单目标兜底。

映射身份使用原有 `yeguif:<blockId>:<localDate>`，按块幂等；事件备注保留“项目：具体事项”，来源仍为 `yeguif`。读取范围仍限定用户选定笔记本内当日新建段落，不读取叶归私有存储。

## T-1614 映射与源段时间（2026-10-04）

设置使用可增删的映射行，目标支持搜索全部分钟项目的名称或 ID，不再只展示前 200 项。来源重名、缺目标、已归档或非分钟目标会阻止保存并说明原因。编辑先作为表面内草稿，点击保存后才影响读取；失败保留草稿，放弃草稿可重新读取已保存映射。另一表面更新了映射时，陈旧草稿不能静默覆盖。

偏好重载与适配器都不再截断至 50 条；有效映射数量可见。尚未入账的源段使用真实开始时刻（保留源秒数），摄取时间不用于 `occurredAt`。分钟结算和块幂等身份保持既有契约。

`normalizeYeguifMappings(value)` 不再限制为 50 条，不接受容量参数；保留输入顺序、去空、项目名与目标 ID 的既有长度限制，以及来源项目按大小写不敏感去重并保留第一条。不同来源项目可以映射到同一个目标；每个来源区间仍保留自己的事件和块身份，不合并为一个来源片段。275 条映射与第 275 个目标的归一化、JSON 往返和试算已有定向验收。设置页候选搜索、偏好重载和宿主摄取由主代理集成；`view-preferences.ts` 的独立 `.slice(0, 50)` 同样需要移除或改用本归一化函数，不能仅据纯模块通过宣称 UI 保存及重载已完整支持。

### 逐源项目预览与最近结果投影

纯模块 `buildYeguifPreviewReadReport` 接收已结算的 `YeguifEntry[]`、完整目标候选、项目映射和现有 `SourceIngestReport`，返回按来源项目分组的 `PreviewReadReport`。每组保留来源名称、目标 ID、目标名称、记录数、分钟数以及 `byStatus` 分区；状态可明确表示可写、未映射、目标缺失、目标已归档、目标单位非分钟、重复、墓碑或最近写入结果。目标候选不在适配器内截断，未配置映射时的唯一同名匹配也搜索完整候选集。

报告的 `totals` 从同一批分组结果派生，记录数和分钟数不会在“可写/跳过”分区之间重新计算。调用方可通过 `results` 按 `yeguif:<blockId>:<localDate>` 注入最近写入状态；预览模式没有逐条结果时保持 `writable`，摄取模式没有逐条结果时标为 `result-unknown`，适配器不会把摄取总数猜成逐条结果。`differences` 对照已有读报告的 scanned/matched/planned/written/duplicate/tombstoned/invalid/blocked 等计数，便于 UI 明确报告不完整，而不是把不一致隐藏在合计里。

接线建议：预览读取完成后将结算结果、目标候选快照、持久映射和最近一次逐条写入结果交给该函数；设置页只渲染 `groups` 与 `totals`，最近结果也使用同一 `groups`，不要再分别维护来源计数。纯函数不访问宿主、不写事实、不迁移旧事件、不改变 `yeguif:<blockId>:<localDate>` 身份或历史时间规则。

`settleYeguifEntries` 的结果新增必填 `startMinutes` 与 `endMinutes`：分别取上一 Marker 和当前 Marker 的起始分钟。`minutes = endMinutes - startMinutes`，`blockId/type/text` 仍取当前 Marker。例如 `09:00 工作`、`09:30 跑步：晨跑`、`09:50 拉伸：肩颈` 产生跑步 30 分钟区间 `[09:00, 09:30)`，拉伸 20 分钟区间 `[09:30, 09:50)`；不能把当前 Marker 的 09:30 当成跑步段开始，也不能使用轮询时刻作为发生时间。

宿主对新事件调用：

```typescript
const moment = buildYeguifActionMoment(entry.localDate, entry.startMinutes);
```

`buildYeguifActionMoment(localDate, startMinutes)` 返回 `ActionMoment | undefined`。它从显式 `YYYY-MM-DD` 和日内整数分钟生成本机本地时区的时间，`occurredAt` 是该时刻的 ISO 字符串，`localDate` 保留来源日历日；不读取系统当前时间，也不使用摄取时间回退。输入无效、日历不存在、分钟不在 0～1439，或本地夏令时跳跃导致该时间不存在时，返回 `undefined`，宿主应按受阻来源记录处理。夏令时回拨中重叠的本地分钟遵循 JavaScript 原生的较早一次；源 Marker 没有偏移量，不能声称已识别它属于哪一次。源时间使用宿主本地时区，跨时区历史重解释不属于此切片。

Marker 的秒字段兼容合法的 00～59，结算仍沿用整数分钟精度；非法秒数现在拒绝。结算与块身份同时拒绝不存在的日历日期；首条无前置、同分钟零段仍不产生事件，输入排序稳定且不改原 Marker 集合。

本切片不迁移任何既有事件，不调整其数值或时间。源段、文本或目标映射修改都不改变同一 `blockId + localDate` 的 `yeguif:` 身份；宿主现有事件与墓碑检查必须先于新写入，不能因新增开始时间重新记录同一块。真实源开始时间只用于以后尚未入账的事件；既有按摄取时刻落盘的事件保留原样。改写旧片段的替换/重结算仍属于独立 T-1544 条件项。

试算台复用生产解析与映射，且显式映射的目标必须存在、未归档、单位为分钟，才能报告匹配成功；先前仅自动匹配检查这些条件，显式映射可误报归档或非分钟目标，此缺陷已修复。试算台仍是来源项目路由检查，不会写事件或展示未经结算的“真实片段”；粘贴输入的 50 行限制继续可见地报告截断数，与映射容量没有关系。按来源日期的规则版本和项目可用性由摄取宿主最终校验。
