## 4. 接入与日期语义

### 日历读取

- 仍需检查 `protocol/version/capabilities` 和方法是否存在；合作正式启用还需对应契约标记及已验收 fixture。基础能力探测只用于判断现有 API 面。
- 捕获 API 后 `await whenReady()`，必须确认返回值严格为 `true`，并重新检查 `window.siyuanCheckin === capturedApi && capturedApi.isReady() === true`。旧引用能读取数据不代表仍是有效会话；当前 `isReady()` 自身只反映所属宿主状态。
- 生命周期通知是拟新增能力。通知仅触发重新探测，不携带用户 store；现有 `api.subscribe()` 数据事件不带 `checkin:`，window 事件名带该前缀。
- `getCalendarProjection` 当前同步返回，不能用 AbortSignal 或 Promise.race 宣称可中断已经开始的投影计算。消费端应限制读取范围并丢弃失效会话的结果。
- 配额项目的日 `complete` 表示“当日已记录”，不是周/月达标；`quotaRate` 是实际投影末日所属周期的累计量，不是 0～1 比例。本批不要求绘制配额百分比。
- 项目顶层 `scheduleType/unit/direction` 取实际投影末日的有效修订，不能用于解释所有历史 point；逐日 `scheduleType` 尚待补齐。未来 `at-most-safe` 不能展示成“已经达成”。
- 超限返回的 `endDateExclusive` 仍保留请求上界。须看 `truncated` 与实际 points，不得用请求端点推断完整覆盖。

### 普通任务写入（拟冻结的 L2 规则，W-03 未全部实现）

- **即使只有一条，也只使用 v5 `recordEventsBatch()`**。能力或契约不足时保留未同步，不降级到 single；旧 v4 bridge 不作为本批生产接线模板。
- 用户明确启用后，按固定 `itemId` 绑定。明确保存 `source: "api"`、`externalRef`、`occurredAt`、`unit`、`value: 1`，同一待处理事实的 payload 固定，重试不能换目标、换日或生成新身份；解除后重新绑定不自动将旧完成重放到新目标。
- 身份格式为 `taskhorizon:<taskBlockId>:<YYYY-MM-DD>`。`externalRef` 的日期是身份的一部分，实际落账日由带时区的 `occurredAt` 按宿主本地时区推导；双方须一致，不得把 externalRef 日期当落账参数。
- 新事实应校验：目标存在且当前未归档；落账日不早于创建日、不在归档区间、不在未来；当日有效修订为 count + daily + atLeast；显式单位匹配；当日未 SKIP。遇到 SKIP 不自动撤销，时区变化造成日期不一致时明确阻塞。
- 拟冻结判序为：**输入格式 → 同身份墓碑 → 已存事实/批内重复 → 新事实业务校验 → 规划写入**。规则后来变化不得覆盖原事实的 duplicate 回执。当前代码重复检查仍先于墓碑，W-03 要按上述顺序补齐并验收。
- 现有通用 `not-scheduled` 实际检查创建日与归档可用区间，不能解读为已校验星期或间隔排期。合作限制按 `externalRef` 的 `taskhorizon:` 前缀识别；公开写入的 `source` 仍为 `"api"`，不填 `"taskhorizon"`。这些限制只作用于 Task Horizon 身份，不破坏其它来源非排期 `logged` 的兼容行为。
- 当前日期时间检查可拒绝 date-only、无时区及不能解析的输入，但 **Date.parse 仍可能归一化非法月日或 24:00**。本次纯规划复现见验证记录；严格日期时间校验和身份日一致性纳入 W-03，不能按当前行为默许滚日。

## 5. 回执、队列与取消边界

正常返回数组与捕获输入 1:1，按原顺序处理：

| 结果 | 消费端动作 |
| --- | --- |
| `recorded` / `duplicate` | 要求有效 `eventId`，将该身份标记为已同步，不再重复增账 |
| `discarded` | 表示同身份删除屏障，停止自动重放；不换身份绕过墓碑 |
| `blocked` | 展示业务原因，保留待处理供用户处理；不自动改 payload |
| `rejected` | 展示该条格式/参数原因，修正或重新明确意图后再处理；不把它视为成功 |
| **宿主级 Promise 拒绝** | 没有取得可靠批量回执，可能已有事实落盘；保留整批身份，按原 payload 重试或对账，不能生成新身份补写 |

逐项 `rejected` 与宿主级 Promise 拒绝是两种情况。成功回执丢失不能证明没有写入；同身份重试由 provider 去重和墓碑保护。

消费端负责持久化待处理队列与重试入口，我方负责最终去重、墓碑及逐项回执。batch 不走 single 自动恢复路径已有源码依据，但重载隔离 fixture 尚待 W-06 收口，不能以源码阅读代替验收。

L2 MVP 建议采用**单向追加完成事实**：取消任务、关闭联动、解除映射或丢弃消费端队列均不等于撤回已写事实，也不能承诺取消正在执行的写入。需要撤回或可取消排队时，另定状态与对账协议。首次启用默认只监听后续完成；历史回补须用户另行确认范围并沿用稳定身份。

读日历与写完成使用两个独立的消费端设置开关；项目级日历隐藏仅控制展示，不控制回写。当前公开 API 没有授权令牌或权限隔离接口，这些开关表示用户启用意图，不能描述为 provider 强制鉴权。

## 6. 共同验收

| 验收组 | 必须覆盖 | 通过条件 |
| --- | --- | --- |
| 远端刷新 | 名称、隐藏、归档/恢复、增删事件；无变化；后续业务失败 | 变化通知一次且可读新投影，无变化零次，卸载后停止 |
| 生命周期 | 两种加载顺序、失败重试、热重载、新实例先于旧实例卸载 | 重新探测有效会话，旧实例不影响新实例 |
| 投影 | 配额 1/10、quota→daily 修订、未来 atMost、隐藏与归档 | 日期级语义准确，不误报周期达成，快照防御性复制 |
| 范围 | 闰年、跨月/年、非法/空/反向、366/200 边界及超限 | 非法拒绝，超限可见提示，实际覆盖范围正确 |
| 新事实 | 非每日次数、历史方向/单位、创建/归档/删除、SKIP | 按有效修订校验并返回已冻结原因，保留通用来源兼容 |
| 日期与身份 | 非法月日、24:00、无时区、跨午夜/时区、未来日 | 不静默滚日或换身份；日期一致；已有事实与墓碑优先 |
| 失败与重放 | 批内/跨批重复、落盘后反馈失败、排队卸载、调用后改输入 | 正常回执 1:1，eventId 可对账，原身份重试无重复 |
| 重载与现场 | batch 失败重载、消费端队列重载、多窗口及双方客户端 | 无 single pending 补写副本，队列不丢，双方实测结果单独记录 |

我方先负责 provider 修复、候选版、固定 tag/commit、契约 fixture 和测试结果；对方可先评审范围并准备图层及消费层。双方对齐 fixture 后，再接消费端、做桌面/独立窗口/移动端现场验收。provider 或 mock 测试不替代双插件现场。
