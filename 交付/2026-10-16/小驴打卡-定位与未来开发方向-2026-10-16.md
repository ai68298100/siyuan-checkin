# 小驴打卡：定位与未来开发方向

更新时间：2026-10-16。当前发布基线：v18.17.6。

本文是当前产品方向的简明入口。具体任务状态以 [TODO 顶部](../TODO.md)、[PROGRESS](../PROGRESS.md) 和 [BLOCKERS](../BLOCKERS.md) 为准；历史路线文件保留研究背景，不作为新的排期依据。

## 1. 定位

面向用户，小驴打卡是**思源里的低压力个人行动记录与复盘工作台**。

面向开发者，它是**思源中的个人行动事实层**：由小驴保存唯一的可追溯事实，统计、回顾、笔记输出和外部插件通过可重算投影与公开契约读取或追加事实。

核心闭环是：

```text
设定可行规则 → 今天完成一小步 → 低摩擦记录事实
→ 回到事件和来源核对 → 看懂变化 → 主动调整下一步
```

这一定义把插件和普通习惯应用、任务管理器区分开来：小驴负责个人行动事实、规则和解释，帮助用户知道发生了什么以及下一步怎么调整；它不负责团队任务分派、项目协作或替代思源的文档编辑器。

## 2. 目标用户与主承诺

核心用户是在思源里记录工作、学习、阅读、运动或生活日志的个人用户。他们希望记录成本低，能够跳过、补记和撤销，不被连续天数、惩罚或社交排名驱动，同时又希望自动来源和笔记联动可核对、可关闭、可恢复。

产品主承诺固定为三点：

1. **今天容易行动**：打开后能看懂当前最值得做的一步，二值、次数、时长和数量记录都能快速完成；复杂规则按需展开。
2. **事实可以核对**：每个主要数字都能回到日期、项目、来源和原始事件；没有记录、主动跳过、明确未达成、来源失败和未来计划必须分开表达。
3. **调整有边界**：修改规则先展示影响，历史事件不被静默改写；笔记写入、外部联动和智能建议都由用户主动开启，并保留失败、重试和撤销路径。

## 3. 三条长期主线

### A. Today：低摩擦行动入口

现有“今天/回顾/事项/记录/更多”入口继续沿用。后续重点是把 Today 的现有能力串成一条短路径：下一步、快速记录、结果确认、撤销/重试、来源状态和返回上下文。事项、提醒、专注、最近漏卡和同日历史作为辅助上下文，不能和主动作争夺首屏。

### B. Review：从图表集合变成证据工作台

回顾先展示事实、日期范围、来源和统计截止时间，再展示趋势、节奏、完成率和建议。每项推断都要说明口径、样本量和证据入口；每条建议都能回到原始事件或规则调整位置。已有 pace、洞察、建议、报告和行动卡应优先统一口径、补回源和失败降级，不因增加一张图而重新建设平行指标。

### C. Open connections：私有事实源，公开可回源

小驴的事件和审计记录是 canonical source。笔记锚点、日记报告、渲染块、API v5 和外部来源只做有边界的投影或追加入口。每个来源必须有能力发现、用户 opt-in、稳定 `source + externalRef`、幂等、失败诊断、停用和重试；来源失效时，手动记录仍然完整可用。

## 4. 明确不做

- 不扩张为第二个通用任务管理器、团队协作工具或全能日历。
- 不建立账号、社交排行榜、RPG 惩罚经济、系统级后台常驻或自建云同步。
- 不读取其他插件的私有数据库、未版本化 DOM 或内部事件来推导事实。
- 不维护第二份可编辑事实账本；笔记正文和外部图层不能取代小驴事件。
- 不提供万能 AI 写入口。AI 只能经历“只读 → 解释 → 结构化草案 → 用户确认 → 普通保存”，关闭模型时手动记录、统计、导出和恢复必须照常工作。
- 不把低压力做成“没有记录也算完成”。降低记录成本、允许跳过和保留恢复，比隐瞒数据缺口更重要。

## 5. 当前判断

v18.17.6 的本地记录、规则、统计、恢复、API v5 和生态框架已形成较完整底座。当前主要风险集中在可信度和证据，而不是功能数量：

| 领域 | 当前判断 | 对路线的影响 |
| --- | --- | --- |
| 核心记录与复盘 | 能力已多，需继续统一口径和失败状态 | 先串起 Today → Review，避免继续堆入口 |
| 数据可靠性 | 主 Store、跨窗口和恢复已有多批修复，仍需长会话、辅助存储和现场矩阵 | 先验证“不丢、不重复、不假成功、不复活” |
| 开放 API | v5 有 20 项能力和契约测试 | 先稳定错误码、生命周期、弃用和消费方证据，不以能力数量作为进展 |
| Task Horizon | 合作是条件性支线；C-01/02/03、W-03、W-06 未收口，两个 integrationContracts 不存在 | 先补 provider 与 fixture，再分 L1/L2 联调；不写成当前已接入 |
| 真实宿主与移动端 | 浏览器和隔离内核不能替代思源桌面、Android、读屏和双插件现场 | 自动化、浏览器、真实宿主、真实第三方四层证据分开记录 |
| 历史路线 | 旧 v18～v22 规划和部分评审文档包含过期版本、已交付任务 | 新任务只从 TODO、PROGRESS、BLOCKERS 和本文件进入 |

## 6. 未来路线：五个结果闸门

版本号不预先绑定功能。每个闸门完成后再决定是否发布小版本或大版本；外部合作不能阻塞本地核心价值。

### M0：可信记录底座

目标是让用户相信每一次记录都能解释、恢复和对账。当前优先收口：

- 主 Store 与辅助桶的失败、恢复、墓碑和诊断；旧窗口、重载和并发不能让事实复活或重复。
- 所有入口（Today、Quick、Dock、渲染块、API、Agent）统一 request-id、逐项回执、幂等和失败重试语义。
- 日期和时区契约：严格校验 `occurredAt` 真实月日/时间，固定 localDate 推导；读投影和写入规划分别验收。
- 每个页面的会话/root 生命周期、异步代际和返回上下文；设置页能看懂来源配置、最近结果、问题和恢复动作。
- 继续补真实思源桌面、页签、dock、Android、键盘和读屏证据。

退出条件：失败不会静默成功；重试不会重复记账；重载不会丢失或复活事实；手动记录在所有外部来源关闭时仍完整可用。

### M1：把现有核心串成日常闭环

目标不是新增更多页面，而是减少从空库到第一条事实、从事实到调整的摩擦。重点包括：

- 空库、首次成功、模板、记录结果和下一步入口的连续路径。
- Today 的主动作、待处理、来源状态、撤销和重试的最小失效域。
- Review 的事实详情、范围/分母/更新时间、事件回源和建议下一步。
- 编辑规则时的未来影响预览；保留历史口径，不把规则变更伪装成历史事实变化。
- 统一错误、离线、空数据、依赖缺失、缓存过期和连接恢复的下一步文案。

退出条件：常用记录保持一到两步完成；用户能从记录结果进入 Review，再回到原事件或规则；任何失败都有可执行的恢复动作。

### M2：深化本地差异化

目标是让小驴回答“为什么最近变了、怎样调整更合适”，而不是只显示热力图。

- 将已有节奏、逾期、配额、at-most、强度和建议统一到同一投影口径，互不混淆。
- 将 Review 组织为“事实 → 依据 → 推断 → 建议”，为每张行动卡提供证据跳转和样本不足说明。
- 情境记录只做可选、低摩擦上下文，不把每次打卡变成问卷；先验证真实需求，再决定是否扩展事件模型。
- 笔记锚点、日记报告和渲染块继续采用 opt-in、追加、审计、失败隔离；不建立第二份事实账本。
- 导入导出继续做预览、语义差异、身份冲突、可重复执行和回滚。

退出条件：同一事实在 Today、Review、洞察、渲染块和 API 中口径一致；每张主要建议能回到原始证据并说明适用范围。

### M3：受控生态连接

外部生态按条件闸门推进，不以“有 API”代替“已接入”。

1. **Task Horizon L1**：我方先完成 C-01/02/03 与日历 fixture，双方冻结生命周期、刷新、投影和降级；对方再接只读日历图层并做真实现场验收。
2. **Task Horizon L2**：我方再完成 W-03/W-06 和重载 fixture；普通任务完成首版限定 `count + daily + atLeast`，单条也必须 v5 batch，由消费端持久化队列，我方负责去重和墓碑。
3. **其它来源**：继续按“登记 → 生命周期 → 结算 → 身份 → 治理”五段框架接入。优先公开契约、用户主动导入或已有稳定来源，拒绝私有数据库和未版本化 DOM。
4. **API 生态**：先稳定 capability、错误码、弃用周期、contract fixture 和兼容矩阵；至少有真实消费方和现场证据后，才扩大写入能力。

退出条件：每个合作都有版本化契约、双方 fixture、失败/重载测试、真实消费方版本和现场证据；缺失合作时 UI 隐藏或降级，手动路径不受影响。

### M4：受控智能与长期决策

- 先做本地确定性解释和建议，再接模型生成复盘问题、项目草案和排期草案。
- 所有写入经过差异预览、影响范围、冲突检查、用户确认、审计和撤销；模型失败不影响手动功能。
- 性能、隐私和同步先做设计评审。没有明确的数据所有权、冲突合并、撤销和删除语义，不实现云同步、CalDAV、账号体系或跨设备服务。

退出条件：关闭智能能力后产品仍完整；模型输出可追溯、可拒绝、可重试，绝不静默改事件、排期或用户文档。

## 8. 新功能准入五问

任何新增功能先回答：

1. 它减少了哪个具体时刻的负担？
2. 它保存或推导的事实身份是什么，能否回放、去重、撤销和导出？
3. 它怎样进入 Today → Review 闭环，能否从结果回到证据？
4. 无数据、离线、来源失效、跨日、跨窗口和移动端失败时，怎样退回手动路径？
5. 它增加了多少压力、维护成本和隐私风险？

答不上来的功能只进入研究或实验区，不进入默认一级入口、不增加公开契约，也不进入版本承诺。

## 9. 每阶段的判断指标

这些指标用于决定继续、调整或停止一条路线，不建立账号或遥测系统：

- **首次成功**：从空库到第一条确认事实的步骤和耗时，取消后草稿是否保留。
- **记录信任**：重复提交、宿主拒绝、重载后的重复率为 0；失败项能否按原身份恢复。
- **回顾价值**：主要行动卡能否跳到证据；样本不足不误导；用户能否从建议回到事件并调整。
- **来源健康**：显示新鲜度、完整窗口、失败原因和重试状态，而不是只显示“已连接”。
- **生态证据**：公开契约、fixture、真实消费方版本和现场验收分开计数。
- **维护成本**：大数据冷启动、写入预算、CSS/JS 体积、无障碍和移动现场证据不恶化。

近期最重要的判断不是“再增加多少功能”，而是“已有能力是否让用户更容易完成、核对和调整”。
